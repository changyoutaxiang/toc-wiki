# AC 5.0.0.32 全量静默升级与三条件打标

> 出自 2026-07-06 Battle-1 Next Steps 战役对齐会「AC 版本与打标进度」一节。AC = 老师上课用的客户端（见 [Cocos](../entities/Cocos.md) （[A](https://alidocs.dingtalk.com/i/nodes/X6GRezwJlAvgOpGkS05dy9BL8dqbropQ) · [Leon](https://alidocs.dingtalk.com/i/nodes/b9Y4gmKWrPNpBnG0seqLNp0LJGXn6lpz)））。

## 背景

- AC 5.0 已开发并短暂部署，因测试子版本 5.0.0.32 回滚到 4.8.9；**4.8.9 有 PDF 兼容 bug**（教材显示扭曲，无法正常授课）。
- 产研称 5.0 无此问题，但**部署版本 ≠ 测试版本**（5.0.0.30 vs 32），稳定性需确认。
- 当前打标数量为零，亟需推进。

## 决策内容

1. **采用 5.0.0.32 稳定版全量 + 静默升级**：尽快完成验证并启动；Leon 要求**明天（7/7）前**确认用 5.0.0.32 并统一推送（Owner：建飞）；建议加警告文案「授课中勿关闭任何组件，否则 AC 可能重启」。
2. **三条件打标规则**（三条件**全满足**才可打标）：①完成 center 培训 ②AC 版本 ≥5.0 ③CPU 设备达标；由**海玄（＝曹海璇，正名见 [人名正名册](/Users/wangdong/Desktop/%E6%9E%81%E7%AE%80%20LLMwiki/wiki/%E4%BA%BA%E5%90%8D%E6%AD%A3%E5%90%8D%E5%86%8C.md)（本地资料，钉钉／GitHub未提供））统一核验**；技术标（H5）与教练培训标须并存；后续设备/版本降级则标签动态降级。
3. **差课率定义**（同日战役二口径）：含教师迟到/缺勤/早退 + 技术问题影响授课。
4. 配套建议（未单独拍板）：袁慧茹建议建**统一 BI 看板**列全体老师姓名 + 三条件完成状态（现存问题：部分老师声称完成培训实则未完成、数据散在三个看板无统一视图）。

## 依据

- 4.8.9 PDF 兼容 bug 使 4.8.9 无法作为长期基线；5.0 当时已开发，但稳定性证据未形成；本页不据开发状态认定已稳定。
- 现存问题：部分老师声称完成培训实则未完成（或只领了 PDF），难核验；数据散在三个看板、无统一 BI 视图。

## 影响范围

- 版本治理线（05-29 设备标准锚定 Cocos 黄金 → 本页 → 07-16 Cocos AC 版本治理）中承上启下的一环。
- 打标 = 认证权 = 资源分配权：海玄（＝曹海璇）的核验权成为关键控制点（源内 AI Insight 保留）。
- 静默升级尚未开启，等 5.0 稳定性确认（截至 2026-07-06）。
