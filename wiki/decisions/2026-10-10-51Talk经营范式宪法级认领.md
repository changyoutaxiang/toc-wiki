# 51Talk 企业经营新范式：宪法级认领与使用约束

## 认领、效力与依据

**本经营范式是 Tutor OS 智能体在经营判断、组织设计、工作流重塑、SOC 与 Agent 设计、交付验收中的宪法级依据。** Leon 于 2026-10-10 直接指定公司最新架构图及 CEO 解读版，并要求“深度理解和吸收后，把它作为宪法级内容，刻到我们的2个记忆库中”。本页记录该认领并结构化原文约束；认领原文的效力不等于 Leon 逐句复核本页所有 Agent 推演。

依据：CEO《51Talk-Q3季度管理会议会前必读》，文内修订日期 2026-10-01；两个记忆库为 TOC LLMwiki 与本机 TOC GBrain（default）。本页承接 2026-09-15 公司治理 Context Pack 的战略铁三角和运行原则，明确两大重塑的最新经营表达；不凭“更新”宣称整包或 Tutor OS 域内设计宪法失效。实际条款冲突须并列回源，不由 Agent 自选胜者。

## 一、经营的完整逻辑

**客户价值确定方向 → 客户任务把价值具体化 → 工作流重塑与组织方式重塑共同完成任务 → AI 驱动系统化交付 → 同时检验客户结果、经营结果与可复制能力 → 真实反馈改进下一轮。**

这条链是依据全文整理的运行解释。原文定位是“重塑公司运行方式”：客户价值是北极星，AI 驱动是核心，系统化交付革命是实现方式。两大重塑共同支撑铁三角。“人掌舵，Agent 执行，系统学习”贯穿全链。

客户任务表达家庭在真实场景中希望完成的进展；公司交付任务表达为实现该进展需要承担的工作。不得把内部活动量直接当作客户任务或价值兑现。客户价值成为经营中心，同时保留健康经营与财务纪律；学习效果、满意度、续费与现金贡献各有证据，不能互相替代。

来源：原文“写在会议之前”、§1、§2、§4.4；内嵌架构图。

## 二、工作流重塑：价值如何稳定到达客户

从客户当前状态、期望结果和完成证据倒推端到端流程。从设计开始组合 Agent、系统与人的能力，明确每一步的必要条件、共享上下文、承诺接续、异常恢复和结果回执。

体验课的客户任务是判断适配、真实体验课程与老师，并在透明信息下作出选择。链条包括理解与定级、课程与教师匹配、学习就绪、课堂体验、反馈与选择、付费后的首月接续。首月任务是顺利启动、持续适合地学习、问题得到解决、看见真实进步。

两条工作流共同持有家庭目标、已验证起点、教师与时间安排、前端承诺和未解决问题。发送之后必须确认接收、下一动作和完成状态。工作按客户状态推进，不能把所有家庭压成同一触达次数。局部改善需要检查是否损害后续体验。

来源：§1.1–1.2、§4 A／B、两条工作流的交接契约。

## 三、组织方式重塑：围绕客户任务组合能力

**以客户任务为中心，而不以岗位为中心。** 先定义结果，再动态组合人、Agent 与专业能力。专业分工提供底座；客户任务决定能力怎样进入现场、协同和退出。

原子小队等行动单元应把结果责任、专业判断、资源调用与反馈放进短闭环。结果负责人管理现场优先级和阶段结果；专业负责人建设人才、标准、平台与复用能力。责任必须配有实际投入、相应资源和授权，跨部门冲突有升级与裁决路径。

High agency 是主动承担结果的能力：主动找事实、提出主张、调动资源、在授权内试验、诚实暴露问题并升级越权冲突。组织同时提供权力和支持。解决方案工程师把专业能力带进真实客户现场，能够共同定义问题、做出运行方案、验证结果，并把有效方法带回专业体系。

只改工作流，部门边界会阻断执行；只改组织，小队可能只产出局部功能。两大重塑共同发生，才让能力形成完整客户结果。

来源：内嵌图、§1.3、§2.4、§4.3。选人演练、投入比例、任务契约字段与具体评价安排仍按原文的研讨建议身份使用。

## 四、人掌舵，Agent 执行，系统学习

默认由 Agent 与系统承载状态识别、知识调用、执行、跟进和协同复杂度；人掌握价值与教育专业判断、复杂取舍、信任沟通、授权和最终责任。

Agent 执行需要共享家庭上下文、目标边界、工具与执行反馈。尚不可靠的能力要有清晰人工兜底和改进计划，经过真实验证再扩大。接管时带着前因后果交接，人工补位必须可见。

标准化明确基准产品、适配规则、权益与调整条件；产品化让能力可使用；系统化连接事实、动作、责任和反馈；AI 在共同标准上处理个性化。有效经验与失败案例进入知识、规则、流程、工具及评测，并以下一轮实际行动检验学习。

来源：§2.2–2.3、§2.4、§4.2–4.4；学习回路的组织表述为 Agent 依据全文作出的整理，不能凭存档、调用或上线宣称效果。

## 五、公司专业能力与区域客户现场必须合流

专业团队交付局部能力、区域靠旧流程和人工拼接，会使能力进步与客户竞争优势脱节。原因同时可能在专业能力本身、工作流、资源与责任安排，不得统一归咎于“区域不会用”。

Q4 已表达的重点是中国和中东，将课程产品重塑、外教质量提升、蜂巢系统奠基三大战役，合流到“体验用户体验课”和“新生30天客户体验”两条关联工作流。它是同一战略的现场合流，不新增第四大战役，也不机械配置四套研发班子。该重点有季度时效；后续改变需新的正式依据。

总部与区域共同承担结果；公司能力必须被现场使用并推动客户变化，区域也需把客户事实、销售、服务和运营力量投入闭环。专业能力与现场验证相互修正。

来源：§3、§4、§4.1–4.3。

## 六、完成标准：三类结果共同判卷

| 检验层 | 要证明什么 | 不能用来替代它的证据 |
|---|---|---|
| 客户结果 | 适配与价值被理解，承诺兑现，学习启动和连续性成立，问题得到解决 | 预约、出席、报告发送、联系或工单关闭次数 |
| 经营结果 | 同口径转化、退费、投诉、单位服务成本与财务质量改善 | 局部客户好评、单个高手或个别案例 |
| 可复制能力 | 普通团队能够持续使用，换人仍能接续，异常能恢复，下一团队能接住有效方法 | 小队挂牌、Agent增加、功能上线或试验启动 |

五个可观察变化：客户任务定义目标；Agent在真实工作流中执行；共同标准稳定交付；同一家庭的状态和承诺贯通；结果责任、投入与授权匹配。验证固定客群和完整窗口，区分注册付费率与出席付费率，首月观察满30天；计入渠道、价格、师资和新增人工成本，保留失败与异常。长期续费与转介绍需要更长窗口。隐性人工、特殊供给与高手依赖必须显露。

来源：§4.4及其“测量口径”说明。

## 七、Tutor OS 的应用约束（Agent 转译）

先问服务哪个家庭、哪个学习阶段和场景、要完成什么，再确定教师供给、匹配、准备、课堂支持、履约恢复与跨课接续怎样进入完整交付。好教师必须能被目标客户理解、在需要时获得、真实教好，并接住后续学习。内部培训、评级与局部质量改善需继续验证是否形成客户可感知的整体结果。

SOC与Agent设计先选能完成客户任务的方法；沿用人类方法时转译，具备更适合能力时重新设计。专业OS在客户现场共同运行，优先验证最小完整闭环，局部成功仍按局部范围报告。

Good Lesson首轮AI分析继续供教研复核；本范式没有自动批准教师评分、激励、权益、固定老师承诺或生产动作。

来源：§3.1、§4.2，结合本项目现行AGENTS的应用转译；本节不得反推为CEO逐字原话。

## 八、读取、纠错与适用边界

涉及经营、组织、工作流、SOC或Agent设计和交付验收时，先读取本页，再回CEO解读相关章节和实际业务依据。现有方案若背离上述逻辑，应明确指出冲突并提出改法，不用旧岗位或局部项目惯性覆盖最新范式。

CEO原文的正式方向、时点诊断、阶段观察、候选制度及研讨建议分别保留。§2.4销售角色转型与第四部分操作设计为研讨建议；首月不做销售、具体人数／资源／任命／预算／价格／KPI门槛未自动成为正式政策。Polly比较是内部管理观察，“显著”不自动表示统计显著性。Q3案例与数字不是2026-10-10实时业务状态。

该宪法级认领是当前岗位判断和设计的约束；不修改公司基本法正式修订程序、不扩大行动授权、不抹掉教师权益和原文未定事项。遇到新正式材料、关键反证或条款冲突，回源说明需修改的具体主张和适用范围，保留历史，不静默覆盖。

本次校准：2026-10-10前一轮图解仅作讨论过程。本页及CEO原文是当前解释；补足了AI Native默认承载复杂度、岗位中心的转移、专业母体与现场协作、High agency制度支持，以及客户／经营／复用三重检验。历史回答不可当新的权威来源。
