## 2026-09-08 候选：技术投诉的组合证据链

本批 5 页演示稿把学生投诉后的技术验证细化为一条组合证据链，不能只看单项指标：

1. **网络**：核对课程时段的 `Delay to Server`、`Delay to Peer`，再看 Classroom Access / IntelliSense 日志、教师当时的网络稳定性与 ISP/Wi-Fi 条件，并回看受影响课程片段。
2. **RAM**：核对课程时段内存占用、设备总内存与可用内存，结合课堂/IntelliSense 日志、AC/浏览器/其他应用状态，并回看录课中的卡顿、延迟或音视频中断。
3. **CPU**：核对课程时段 CPU 占用、处理器型号/规格与后台进程，结合课堂/IntelliSense 日志，再回看录课确认异常是否真实出现在对应片段。

其共同结构是：**学生投诉 → 指标 → 系统日志 → 教师端当时设备/网络状态 → lesson recording → 诊断候选 → 人工复核/处置 → 后续课堂验证**。这只是待审的验证设计：PPT 没有批准阈值、完整案例身份、指标时间窗、日志版本、诊断置信度、误判/证据冲突、处罚或撤销处罚记录，也没有后续课结果；示例截图不证明某名教师确有网络、RAM 或 CPU 责任，更不证明该链已经接入运行。

### 1. 交接必须找到真正采用结果的人

Learning的下一次学习决策责任方不仅输出课前状态，还要接收新课堂证据、前序证据纠错和教学执行结果，留下处理结果。Tutor核实下一位老师实际采用、核实或纠正；课程、工具和共因工程问题交对应改进责任方，不能都塞进教师训练。Service分别记录客户接受、拒绝、未回应；客户恢复完成不关闭教师纠错或申诉。

每次交接补接收方、截止时间、接收/拒绝回执、未采用原因、失败承接人。端到端业务结果Owner对无人接收和悬空负责，各域保留专业判断权；蜂巢协调者负责等待、升级和接管，不裁决学习事实，也不必成为万能Mother Agent。验收链为：**前序证据版本→教师采用/核实/纠正→实际教学与新证据→Learning处理结果→下一课验证**。已发送只到待处理，已接收不等于已采用，没有后续观察机会就记录无法验证。（本次源§一；B组1、C项1。）

### 2. 纠错要传播到派生判断和消费任务

课前Context保留权威引用、版本、适用范围、生成时间、失效规则、缺失/争议信号及实际消费版本；Tutor不另造权威学生学习档案。Learning纠正证据后，要标出受影响的派生判断和后续消费任务；失效事件及接口仍待设计。

| 任务阶段 | 候选处置与需要证明的结果 |
|---|---|
| 尚未执行 | 更新上下文并重新核验，旧证据不再驱动新的错误动作 |
| 正在执行 | 按风险判断暂停相关自动动作、补支持或转人工；不机械中断正常课堂 |
| 已完成 | 保留当时输入、判断、动作和Trace，关联后续纠正与必要补救，不抹掉历史 |

验收重点是错误传播是否停止，而不是页面是否更新。质量复评不自动追改已结算课酬；证据不足或模型超时继续保障正常教学与结算。（本次源§二；C项2。）

### 3. 人工接管必须转移执行权

在已有权限、幂等和提交重验之外，补验**人工接管后撤销或隔离旧Agent执行权；晚到结果先查单对账，不能继续触发下一动作**。审批绑定具体动作、对象和有效版本；关键条件变化重新核验。超时表示未知，不能当作失败后盲目重试。

每项任务须明确重试、费用、最长等待和升级边界，具体数字由责任方在试点前签收。已有故障演练补上接管后迟到回执；同时覆盖资格/时段过期、并发抢占、重复、超时但已成功、重启、客户拒绝和无合格候选。业务结果、动作回执、运行Trace分别验，Trace不替代课堂证据。（本次源§三；B组2、C项3。）

可考虑在现有授权系统上采用窄适配、持久任务记录和明确人工接手；保持单一权威事实源、既有身份权限、对象关联、版本与回执，并能导出、回放和替换。临时方案登记**Owner、实际消费者、成本、平台缺口、迁移验收、复审日期、退役条件**。若权限、执行可靠性或审计不足，只能停在影子/人工确认范围。

### 最小可验链

对一个真实学生和一种明确教学任务，至少连续验证：**课前接住**上一课目标与证据 → **课中验证并推进**而非照抄摘要 → **课后留下证据**、不只写完成状态 → **下一课老师实际使用**这些证据并做纠正。读过交接简报、摘要生成成功或页面存在，都不能单独证明教学连续性成立。

固定老师率与教学连续性应分开观测：较高固定率可降低交接频率，但不能替代连续性证据；较低固定率也不应被直接写成学习断裂。若测试教师能力，应写成“某老师在指定任务、学生状态、材料、提示或教练支持条件下的表现”，不得把系统辅助后的单次结果直接归为老师脱离条件仍稳定具备的能力。

### 尚缺的证据

- 同一学生跨至少两位老师的完整课前—课中—课后—下一课链路，以及后一位老师实际采用、修正或拒绝前序证据的记录；
- 固定率分布、学生选择／排课原因、学习结果与客户体验的同口径数据；
- 老师对错误证据的纠错与申诉入口，以及条件变化后的复检；
- 准备成本、课堂负担、异常恢复和客户权益的真实反馈。

### 同日反馈 v1.1 的验证顺序强化

### 2026-09-08 架构候选：从教学任务入口到网络能力结果

同日另一份 Agent 架构建议把现有 Lesson、条件化能力与方法复用重排成一条验收主线：以“学习任务需要什么真人能力”为入口，以“教师网络能否持续提高交付能力”为结果；供需不只看人数，而看任务所需能力与有效能力能否匹配。它同时要求正常课堂也有正向支持链：理解学生需要 → 获得准备与支持 → 完成教学 → 观察学习证据 → 改善下一次教学；系统发出支持、老师实际采用、后续课堂改善必须分层取证。
