# 经营域共建模板

**每个经营域都回答一个值得长期追问的问题：现在怎样理解它，为什么这样理解，新事实出现后怎样继续往前想。**

沿用 D03、D05 样例的六个模块与顺序。统一的是六个问题，各域可以选择适合自己的文字、表格和关系图，不要求篇幅相同，也不固定假设和好奇的数量。

本模板于 2026-09-17 获 Leon 认可，采用 **V2.0 六模块写法**；经营域页面的本轮内容版本为 V2.1，经营架构仍为 1.1。先行实例为 [D03 新师成材](骨架/TutorOS经营域-D03-新师成材与早期经营.md) （[A](https://alidocs.dingtalk.com/i/nodes/ndMj49yWjXK9ykGpubzXm30bJ3pmz5aA) · [Leon](https://alidocs.dingtalk.com/i/nodes/OG9lyrgJPzkq5xD6fln9E0l3WzN67Mw4)） 和 [D05 授课条件与模式治理](骨架/TutorOS经营域-D05-授课条件与模式治理.md) （[A](https://alidocs.dingtalk.com/i/nodes/NkDwLng8ZLRqrGZjc3LzdNg4VKMEvZBY) · [Leon](https://alidocs.dingtalk.com/i/nodes/3NwLYZXWyna7ByKdiGXYpK3jVkyEqBQm)）。

**本轮确认范围：** Leon 先确认“基本保持着6大模块作为模版”，随后要求其余骨架页“按照03和05的标准以及完全一样的模板，进行改造”，由 subagent 成稿、主 agent 检查工程质量并验收。该认可针对写法与改造分工，不代替各域的业务决定、效果证据或逐条人审。

可填写的空白版本存于本地工艺工具包 `templates/经营域页-模板.md`；下述六模块名称和顺序为现行标准。旧七项内容的客户价值、主要矛盾和重要取舍已分别安放在 NOW 与 MODEL，其他认识、假设、好奇和边界均须按各自证据保留。

| 模块 | 读完应当知道什么 |
|---|---|
| NOW｜现在怎么看 | 核心问题、当前判断和眼下最需要关注的地方 |
| MODEL｜价值怎样产生 | 谁会受益、事情怎样成立、关键条件与取舍 |
| BELIEFS｜哪些判断仍待检验 | 我们暂时相信什么，凭什么，什么会使判断改变 |
| FRONTIER｜接下来想弄清什么 | 尚未想通的问题、已有线索和下一份有用证据 |
| DELTA｜认识怎样走到这里 | 哪些证据、决定或纠错改变了原来的理解 |
| BOUNDARIES｜边界与下钻 | 本域负责解释什么，相关问题去哪里继续查 |

## 1. NOW｜现在怎么看

**目标：让隔一段时间回来的人，约半分钟就能接上思考。**

开头用三小段建立上下文：

- **核心问题：** 本域长期要弄懂什么？尽量落到具体人和实际经历。
- **当前判断：** 给出目前最有依据的理解，同时写出影响结论的关键条件。
- **当前重点：** 眼下最需要看清的矛盾或取舍是什么，为什么值得先关注？有合适的好奇问题时，直接链接到 FRONTIER，不重复展开。

本年度与当季度的重点，有真实依据、能帮助判断时保留在这里，标明时间与两者关系。尚未确认的重点写成建议或待判断；不为每页补齐年度、季度栏目。换期先回看原问题，再决定是否调整。

若本域容易把规则、计划、运行和效果混在一起，加一张简表：**对象｜现在能确定什么｜关键未知或限制**。只放会改变当前判断的事项，详细依据链接原页。明确的未知可以直接说明，不能据此反推事情没有发生。

NOW 负责呈现当前理解。完整推理、历史和证据留给后面的模块与附页。

## 2. MODEL｜价值怎样产生

**目标：读者遇到一个新案例，能用本域的理解解释它，并找到可能出问题的地方。**

先讲一个具体的价值场景：学生或家长的学习、体验、信任会怎样改善；涉及教师时，说明其成长、合理所得与应受保障的权益；再看这种改善怎样持续。

用一条主链、一张关系图或几段解释，说清哪些因素相互影响、靠什么连接、哪里可能中断。不同域可以采用过程、反馈关系、约束或比较框架，不必全部写成同一种流程。

解释中保留三类信息：

- **关键条件与事实：** 每一步要看什么，缺哪项事实会影响判断？区分“具备条件”“实际发生”“产生价值”等不同层次。
- **其他可能解释：** 同一个现象还可能由什么造成？哪些差异来自人群、机会、环境或支持？
- **重要取舍：** 当前倾向怎样做，愿意承担什么代价，有什么可行替代，什么情况出现应当转向？

居家与中心保持平行，按实际差异分别解释；材料没有限定模式时，不替它补范围。权益等价值底线明确写出，不以效果好坏决定是否保留。

只把最值得单独追踪、检验的关键判断送到 BELIEFS；其余随解释保留来源与限制，避免把整张模型拆成庞大的假设清单。

<a id="4-核心假设我们相信什么凭什么相信"></a>
## 3. BELIEFS｜哪些判断仍待检验

**目标：把“我们相信”变成有理由、可修正的工作判断。**

每条保留一个主要命题，建议使用稳定编号，例如 `D03-H01`。用四小段写清：

- **判断与条件：** 相信什么，在什么对象、场景和范围内可能成立？
- **依据与现有分量：** 为什么这样想？目前是设计理由、个别观察、重复样本，还是较可靠的比较证据？有哪些相反事实？
- **改判条件：** 什么新事实会支持、削弱或收窄它？若发现不成立，会改变哪种理解或做法？
- **下一份有用证据：** 最值得补看的材料是什么，怎样区分不同解释？尚不知道如何检验时，直接说明缺口。

正式决定按原批准范围放在 NOW 或其原始决策页，沿用的价值原则放在 MODEL。实施已获批准与实际效果仍待检验，可以同时成立。页面重写不改变旧决定的有效范围，页面人审也不能代替效果证据。

不为凑数补假设，不给整页打一个笼统信心分。现有依据不够时仍可给出有条件的判断，并说清最关键的不确定处。

<a id="7-当下的好奇"></a>
## 4. FRONTIER｜接下来想弄清什么

**目标：保留真正值得继续想的问题，也给新材料带来意外发现的空间。**

通常聚焦两三个问题，数量随内容变化。每个问题建议保留稳定编号，例如 `D03-Q01`，写清：

- **我们好奇什么：** 一个具体问题，可以是反常现象、原因、机会或尚未想好的问法。
- **为什么值得想：** 想明白后可能改变什么；暂时说不清用途，但值得留意的好奇也可保留。
- **目前想到哪了：** 已有线索、不同解释、仍没看清的部分，以及值得继续留意的材料或真实经历。

已有可检验的暂时答案时，链接相应 H 编号，让 BELIEFS 承接命题与证据；这里保留还未回答的部分。尚无答案的问题不必硬变成假设，也不要求立刻对应任务或实验。

新材料到来后，先读清原文，再看它推进哪个问题、是否需要换问法，或提出了地图里没有的新问题。有推进才记录日期与出处。问题可以跨季度保留、合并或退出；退出时留下阶段答案或放下原因。

<a id="5-最新认知现在怎么看最近哪里变了"></a>
## 5. DELTA｜认识怎样走到这里

**目标：让人看懂判断为何变化，也让后来的读者不再重复已经纠正的误读。**

主页面保留仍影响今天判断的少数关键变化，完整历史进入附页。每条包括：

**时间与变化性质 → 当时的理解 → 新证据、决定或纠错 → 现在的理解及影响。**

来源纠错、正式裁决与效果发现标明各自性质。发生日期与记录日期不同且会影响解释时，分别注明；引用此前的具体判断及新依据，用章节或稳定编号定位。

没有可引用的旧判断，就写“首次提出”或“本次补明”，不要编一个错误的过去。仅改排版、补链接或同步的操作留在维护记录中。没有实质变化时保留原日期与判断。

判断变化后，先更新 NOW、MODEL 或相应 H/Q 的正文，再留下这条演化记录，并核对实际受影响的相邻域。只加一条历史记录或新链接，不算当前认识已经更新。

## 6. BOUNDARIES｜边界与下钻

**目标：读者知道本域能解释到哪里，以及下一步准确去哪里找依据。**

用一张短表交代：**想解决的问题｜主要正本或相邻域｜本域保留的解释与边界**。

正式规则链接决策，执行进度链接项目或业务记录，效果判断链接对应证据。跨域共同判断尽量有一个主要维护位置，其他域说明它对自己的影响并引用；各域仍可以保留自己的条件与不同视角。

再写本域真正容易混淆的少数边界，例如统计对象不一致、同源材料重复计证、原件未取得，或判断尚不足以支持某项行动。关键限制紧邻相关主张；通用规则集中说明，避免每个段落都重复。

普通研究问题不自动生成待办，新的理解不自动构成业务授权；已确认事项也不能因为本次没读到原件而重新降为未决。权限与人审继续按项目现行约定。

最后链接本域的证据附页，供进一步阅读。

<a id="依据放在哪里"></a>
### 主页面与附页怎样分工

主页面是唯一认知正文，保留理解所需的关键事实、条件、相反证据与引用。完整证据登记、历史材料、阅读覆盖和全量相关页目录进入 `wiki/queries/Dxx-认知依据与演化.md`。附页服务正文，不另写一套当前结论；已有合适承接页时优先复用。

证据条目至少说明：**入口与定位、时间与对象、来源性质及本次阅读范围、支持什么、不能支持什么**。存在共源、原件缺失或材料冲突时明确指出。主文可用 E 编号直达条目，条目再直达来源。访问情况、决定认可与效果证据分别表述，不能用一个状态替代。

版本快照、全文读取清单、评测结果及发布回执放在维护记录中。HTML 由正文生成，作为阅读视图；不另养一份手工维护的认知正文。

### 这次只微调了什么

1. 六个模块与顺序保留。把原有客户价值、主要矛盾和重要取舍明确安放在 NOW 与 MODEL，避免因更换模板而丢失。
2. H 与 Q 可以互相连接，但好奇仍可开放；不固定三条，不要求所有问题都变成实验。
3. 当前判断只在 NOW 集中呈现；DELTA 解释改变，BOUNDARIES 提供去处，证据附页承担完整追溯，减少重复。

<a id="全文怎么说才方便共同建设"></a>
### 怎样判断写到了点上

用少量真实问题检查：

- 只读 NOW，能否复述当前判断、关键条件和最值得继续想的问题？
- 给一个陌生案例，MODEL 能否提出不同解释，并指出需要哪项事实来区分？
- 给一份新证据，能否准确找到受影响的 H/Q 和正文，说明该改变什么、什么仍然成立？
- 查一项规则或历史纠错，能否找到来源、当前适用范围，并保留证据不足的部分？

结构检查只说明页面可用；实际回答及其证据才用于判断模板是否帮助了理解。以 D03、D05 原有案例为起点，另补新案例与反证更新题；执行后记录结果，不预称通过。

### 全域接续与维护

本页、第二层地图、维护约定和工艺包统一使用同一六模块模板。主页面路径及既有云端节点沿用；完整来源、历史和相关页目录在各域的认知依据附页，主页面用稳定 E 编号直达。

新材料先读清，再判断是否改变 NOW、MODEL 或 H/Q；只有实质改变才记录在 DELTA。作者交付后冻结，交叉复核先从旧页和关键来源形成判断，再比较候选；经理负责跨域边界、关键主张、链接与真实场景的最终验收。

六模块属于写法版本；域划分与核心关系未变时，不连带升级经营架构。域页的人审范围仍按具体内容记录。定稿、页面迁移、行为检验与云端发布分别留证。
