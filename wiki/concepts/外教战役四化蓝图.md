## 二、双轴总图

**纵轴 = 三层**（变化速度不同，**最慢层决定收敛速度**）：

| 层 | 变化速度 | 战役内容 |
|---|---|---|
| 工具层 | 周级 | 标准卡、数据表、cockpit、AI 接管队列 |
| 制度层 | 季度级 | 权力结构、考核激励、预算、旧路径退役 |
| 基本假设层 | 年级 | 四条信念迁移 + 事前可证伪指标 |

**横轴 = 老师生命周期 8 段**（获客招聘 → 初筛设备资质 → CE 评级 → PSO → Launch 入门 → 在岗追踪 → 分发利用 → 薪酬留存淘汰）。

关键提醒：**执行包 v0.1 的全部内容 ≈ 工具层。若只推进工具层而制度层、基本假设层不动，本蓝图自动降级为伪转型**（浅层宣布胜利 + 「管理方式不用变」防火墙）。

## 三、工具层：数据化地基（对齐公司数据治理五层框架，2026-06-06 公司口径）

数据化地基的公司级物理落点 = 五层框架 **L3 官方数据集**。责任口诀：**定义权 L3、验收权 L5、否决权 L4、问责穿透 L2、L1 不碰**。

- **L3 数据资产**：Leon 主责（**定义权**）——哪些算官方数据集、对象怎么切、口径怎么定、字段含义、owner；做不好责任在 Leon 不在数分；
- **L5 业务使用**：Leon 主责（**验收面**）——看板/日报/复盘是否唯一口径；**L5 打架 = L3 没做完**；
- **L4 数据服务**：约束方（守门不干活）——本域一切数据服务只引用 L3，不许从 L2 私拉野口径；
- **L2 数仓**：合作方（问责穿透）——定位到层是 Leon 的事，修是数仓的事；
- **L1 同步**：不是 Leon 的——只确认外教域该接入的源无缺口。

**L3 主责五件事 = 定清单、拍口径、写说明、钉人头、踩刹车。** 数据不用搬（L1/L2）、报表不用做（L4/L5），管的是外教业务的「字典」；每个数据集必须往下钉到具体人。

- **口径差防守**：公司写法 L3 Owner =「全球数分；业务 Owner 共同确认」，若执行成「数分定义、业务签字」即退回失败结构。实操必须做成：**业务 Owner 拍口径（定义权），数分管实现与一致性（工程权）**。
- **标准资产卡（4 张 + 1 个新子标准）**：A. B+/A 老师标准（招聘端预测／在岗端验证两套不混算；06-07 发现 B+/A 口径当前五个版本打架——第一个要拍死的 L3 口径）；B. 设备准入（**3500分，2026-07-01全量上线**；原“06-11上线”为旧计划/编译口径，不作实际日期；源：Leon 2026-09-05确认，问题账TOC-60）；C. CE 三维度（**新增口音／发音子标准**）；D. 分发质量（booking share / lesson share / peak-hour share）。
- **AI 接管队列**：四问全过 = AI 准生证发放。设备预检原拟06-11定线后重评四问；实际设备标准沿7月1日全量上线裁决，有望成为第一个全四问通过的流程（样板价值：让组织亲眼看到「治理完成 = AI 准生证发放」）。

## 四、制度层

**权力来源与治理结构**（现实约束：Leon 不掌人权、财权，每张标准卡的效力来源必须显性化）：外教端标准制定与产品决策主导权（CEO 06-03 纪要，已确立）；虚线汇报（CEO 拟建立，**未落地**，本月催办）；2 名优秀工程师入队（CEO 拟调，**未落地**，与 Big Idea 绑定提案）；数据闭环会 CEO 亲自介入（承诺，待首次召开）；草案自我定义的五个权力点（指标命名/口径裁决/数据责任/异常闭环/系统资产），拟经闭环会形成共识。

**考核与激励**：**「强人不沉淀就不算赢」进入完成定义**——每个战役子项目的「完成」= 业务结果 + 沉淀物（标准卡 / skill / 数据资产）双达标，沉淀不是附加项。Codex 培训作业锚定「产出本部门 skill 入公司资产库」，入库不是终点，还要看复用、入流程、降成本。

**旧路径退役总账**（全局唯一清单）：设备多口径（588 / 3200 / 第三方漂移）→ 3500 唯一线；口音多套标准（国内 Excel / 海外读物）→ CE 卡口音子标准；B+/A 口径五版本并行 → 招聘端 + 在岗端两套官方口径；群里拍板／口头解释口径 → 标准卡 + 裁决记录；各看各的 Excel → 三张主数据表 + cockpit。原则：草案提出新旧并行与退役判据；未生效的新卡不能仅凭版本更新覆盖旧规则，退役仍须有效裁决与公告。

## 五、基本假设层（防伪转型层）

**四条信念迁移**（战役语境）：价值在定义而非执行；AI 是可调度执行能力但不是责任主体；经验必须显性化；结构性产出优于工时但不否定探索期。

**事前可证伪指标**（每月自查 + 周会观察）：① 团队**主动**交出的 skill／标准卡数量（非被要求），及被非作者复用、进入流程、降低重复救火成本的比例；② 是否有人砍掉过自己强撑的环节；③ 汇报中讲结构/资产 vs 讲苦劳的占比变化；④ 压力时刻第一反应：查系统还是找强人（**压力时刻才暴露基本假设，平时只能看到宣称**）。

**伪转型自检**：禁止用标准卡数量／工具覆盖率／资产库条目数当转型进度；禁止考核激励未动就宣称制度层完成；听到「四化是好工具，但开会/考核方式不用变」→ 防火墙话术，当场点破。

**体验设计（信念只被体验改变，不被说服改变）**：刻意制造「查系统比问强人快」的时刻——凡有人问 Leon 口径，回答「在 X 卡 X 字段」而非直接给答案。

## 七、起点篇：How-to-Start（卡生产线与日心说）

> 回答一个问题：**外教战役的四化建设，从哪里开始。** 三个先读懂的词：**卡** = 一个 md 文件 = 一张可计数、可复用的资产卡（口径/标准/判断写成卡才算资产）；**L3** = 数据治理五层框架的「数据资产层」（Leon 主责，五件事 = 定清单、拍口径、写说明、钉人头、踩刹车）；**日心说** = 以 Agent 为中心的组织设计准则，流程、人、资源绕着智能体转。

**总命题：起点是一条生产线，不是一堆任务。** 建卡标准、按 Agent 为中心重排打法、数据治理破局是同一台发动机的三个部件：卡体系 = 资产的度量衡与封装格式（日心说下，**卡的第一读者是 agent，不是人**）；日心说 = 设计准则（回答「卡写给谁看、谁消费卡」）；L3 数据治理 = Leon 亲投的定义权阵地（**L3 五件事就是产卡五步，L3 是战役的第一条卡生产线**）。

> **起点 = 这条最小生产线跑通一圈：产卡（Leon 在 L3 出样板）→ 用卡（agent 只引用卡回答口径问题）→ 计数（卡被复用的次数进周报）。** 跑通一圈后再复制给全员，而不是先全员铺开再求质量。

**卡体系（5 类轻卡）**：

| 类型 | type 值 | 回答什么问题 | 晋升分支 |
|---|---|---|---|
| 数据集卡 | `card/数据集` | 这堆数据是什么、从哪来、能信吗 | 可执行 |
| 指标卡 | `card/指标` | 这个数怎么算、唯一口径是什么 | 可执行 |
| 标准卡 | `card/标准` | 过线不过线、谁说了算 | 可执行 |
| 决策卡 | `card/决策` | 当时为什么这么定 | 洞察 |
| 流程卡 | `card/流程` | 这件事怎么跑 | 可执行 |

三组关系一句话记：**指标卡量世界，标准卡划线，决策卡留 why；数据集卡是前两者的地基，流程卡把前三者串成动作。**「数据卡」= 数据集卡 + 指标卡两个子型（一个描述资产，一个定义计算，schema 与验收问题完全不同）。暂不立类（防爆炸）：人物卡、案例／反例卡——真实需求出现满 3 次再立。

**设计原则（四条）**：分类判据（一类卡值得独立存在，当且仅当它的本体区 schema 和验收问题与其他类不同——防类型爆炸）；头部高度统一（所有类型共用同一份 frontmatter，只有本体区按类型变化）；**卡是字典不是报表**（放定义、口径、规则、理由，不放随时间变化的数值；数值只允许以带日期戳的快照出现，数值变了不改卡，口径变了才改卡）；**第一读者是 agent**（字段经得起「agent 拿这个字段能回答什么业务提问」，回答不了的字段删掉）。

**统一头部必填**：card（枚举：数据集｜指标｜标准｜决策｜流程）、id（`FT-<类型码>-<三位序号>`，台账顺序发号）、title、domain、owner（**必须是具体人名，写「团队」= lint 不过**）、status（候选｜复核｜资产｜退役 四态）、created；标准/指标卡必填 effective 生效日；sources ≥ 1；supersedes 与旧路径退役总账双向同步；used_by 由台账/agent 维护（复用计数的数据源）。

**卡间链接与生产时序**：计算依赖是「指标卡算自数据集卡，数据集卡是地基」；但**生产时序相反（需求拉动）**——业务流程 → 业务问题 → 先定指标 → 倒推数据集 → 数据服务（L4）→ 业务使用（L5）→ 回到业务流程。自底向上铺数据集是数仓项目的经典死法（建一堆没人查的表）。两条硬规则：① 指标卡必须链到数据集卡（计算依赖完整性），但不要求数据集先建成——由指标倒推，先立「骨架数据集卡」（可信度标低）占位；② 每次裁决会出卡成对：N 张指标/标准卡 + 1 张决策卡（why）。

**卡 lint（入库前 10 条，agent 可自动检查）**：frontmatter 字段齐全、枚举合法；owner 是具体人名；一卡一事（正文出现第二个「和」就拆卡）；指标卡「基于数据集卡」非空；标准/指标卡有 effective；数值只出现在快照区且带日期戳；sources ≥ 1 且路径真实存在；supersedes 与退役总账双向同步；不含隐私/薪酬个案/未公开人事；agent 预检通过（非作者出 3 个真实业务问题，agent 仅凭本卡答对）。

**轻重分级与晋升**：以上五类都是**轻卡**（10 分钟写完的候选卡格式）；**重卡 = 系统资产卡（10 格模板，已有）**——标准要进系统锁定、管存量治理与旧路径退役时，由轻卡按 10 格补全升级。流转沿用卡晋升协议四态：**候选卡 → 复核卡（一次非作者复用）→ 团队资产卡（过闸门，计入资产存量）→ 退役卡（降格存档不删）**。复用主体包括人、agent 和系统——卡进 PRS/广告等系统锁定即记一次系统复用。晋升闸门：可执行卡 = 第二个人/agent/系统不找作者就能用出有效结果；洞察卡 = 改变了非作者的一个决策。战役域晋升判决权归 Leon。**前 90 天只表扬不进 KPI**——组织史上标准化的头号死因是「KPI 按月/季锁死 vs 四化产出周期 6-18 个月 → 表演四化」。

**卡库载体（双层）**：团队侧（卡库正本，全员可读写）——COO 倾向钉钉知识库，冒烟测试判据：一张完整卡（含 frontmatter 与卡间链接）写入后，agent 经 dws 读回并解析出全部字段，测不过则降级到共享 repo 方案；Leon 侧（治理台账 + 镜像）——`系统资产卡/_index.md` 升级为全战役卡台账（轻重都登记、发号、记预检与复用）。

**L3 起步：双杀并行、火线先行**。当前有一场正在烧的火与 L3 缺位完全同形：**国内 launch 通过率 MTD 约 19%（目标 23%）**，归因靠人工猜；CEO 已表态「一定有物理变化」，三路快查（中方查评分口径 / 菲方抽失败录像 / 看板下钻）进行中。火线杀：通过率归因官方指标卡（FT-IND-003，借快查现场顺手拍定，「救火必须留沉淀」第一个实证）；日历杀：B+/A 口径五版本归并（收 Sophia/黄荣 one-page → 盘点差异 → 裁决会归并为两张官方指标卡 FT-IND-001 招聘端 / FT-IND-002 在岗端 + 决策卡 FT-DEC-002，旧五版进退役总账）；顺手收割：设备达标卡（FT-STD-001，06-11进PRS/广告并过闸为原排产/编译说法，不能据此验收系统复用；设备标准沿7月1日全量上线裁决）。三卡咬合：通过率失败原因中 seed（疑似设备/形象不合格）占比 25%→32%，与设备线直接相关。

**第一只蜜蜂：口径问答 agent（P2，带前置条件）**——卡库喂给 agent，战役内口径问题先问 agent。三重价值：让「查系统比问强人快」成为日常体验（把「强人」从 Leon 换成系统）、复用计数自动化的起点、最小闭环验证（答不出 = 暴露缺卡，缺卡清单回流生产线）。前置条件（缺一不启动）：团队侧卡库已定且有首批卡；建设者落实（工程师到位或 COO 代建 + 团队访问通道）。可操作验收：10 个真实问题池口径问题，agent 引用正确卡 ≥ 8，且每次失败产出一条缺卡记录。

**开动：第一个数据域只选招聘漏斗**（leads → 资料提交 → 初筛/设备 → NTT/CE demo → PSO → launch）。理由：① 正在烧的通过率火灾就在漏斗末段，火线动作与长线建设是同一条路；② 漏斗是战役 KPI-1（足额供给）和 KPI-2（入职质量）的物理载体；③ 域内打穿才能兑现「agent 完整读取」。**终点线（2026-07-31 收口）**：漏斗每一段都有数据集卡 + 指标卡（口径、owner、数据源、取数路径齐全，域内无野口径）；口径问答 agent 上岗；20 个真实问题池漏斗问题（出题人 = 非作者，判分人 = Leon）答对 ≥ 18，每次答错产出一条缺卡记录，漏斗域「两张报表打架」次数 = 0。**防指标替代**：终点线是手段不是经营成败——经营判据仍是蓝图 §6 的四个数字；agent 可读而 share 不涨，照样是假胜利。Leon 亲投护栏：L3 亲投只做「定义权」五件事，数据不搬、报表不做，每周亲投上限半天到一天，超出即停（在替数分干工程活）。

## 八、风险与防呆

- **最大风险不在工具层**：虚线汇报／工程师／考核激励若落不下来，蓝图收敛速度被制度层锁死（最慢层定律）；
- Leon 强人基因防呆：四外骨骼——数据同事贴身 / one-page / 周闭环会 / 版本化文档；
- 窗口风险：反攻窗口内若供给失速，四化节奏让位于供给救火——但救火动作必须留沉淀（不沉淀不算赢）；
- 文档风险：本手册 30 天未更新即视为失效，纳入 journey 周检。
