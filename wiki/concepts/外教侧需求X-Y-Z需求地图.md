# 外教侧需求 X-Y-Z 需求地图

> [!warning] 待审 · 讨论稿
> 本页合并编译《外教侧需求 X-Y-Z 需求地图》v0.2（2026-08-17）与对齐版 v0.3（2026-08-17~19，**以 v0.3 为准**），源为 discussion-draft（`not_canonical_for`: 当前生产状态、需求优先级、项目立项、人员任命、指标承诺、教师或客户权益动作）。页面级 review 标 **待审**；**截至 2026-08-19** 的深搜结论，任何「已上线、覆盖率、owner、规则生效、客户结果」在行动前都必须回当前业务系统、正式正本或完整旅程读回（证据标签：`[R]` 真实系统读回普遍缺失）。

> **核心结论：82 个原始编号，不是 82 个项目。** 战略层收敛为三个一级战场：**形成好供给、守住每节课、连接好关系**；项目名、产品名、规则、指标和治理 Gate 必须继续独立保留，不能为了表格整齐被硬塞成 X、Y 或 Z。

## 一、三个一级 X（稳定主干）

三个 X 是长期经营对象，不是严格串行的三阶段，也不与系统、部门、项目或常驻小队一一对应：

| 一级战场 | 主要经营对象 | 核心完成定义 |
|---|---|---|
| **X1 形成并持续经营 Customer-ready 供给** | 一名老师／一批老师的供给状态 | 进入、成材，并持续保持 Customer-ready |
| **X2 让每节课稳定、有质量地交付** | 一节已经预约的课 | 正常课按承诺发生；异常课被主动发现、保护、恢复并防复发 |
| **X3 让好老师被可信看见、选中、约到并形成稳定关系** | 一次选约及一段师生关系 | 好老师被可信看见、真正约成，关系持续稳定 |

真实客户旅程常是「供给形成 → 被选约 → 稳定交付 → 客户结果回流」，但经营上三个战场长期并存。**Z4 学习结果判卷接口（A-01／A-02）不是第四个 X**：它是三个战场的延迟判卷（连接学生—老师—课程—师生关系—异常／干预—观察窗口—学习结果），不能短周期归因给单个老师，也不能用教师评分、坏课率、预约率或曝光量替代。

**v0.2 的十个二级战场**（v0.3 继承）：X1.1 候选供给 / X1.2 0—30 天 Customer-ready（载体 TIDE）/ X1.3 全量在岗供给经营与进化；X2.1 出勤稳定 / X2.2 设备网络课堂技术稳定 / X2.3 课中教学与互动质量 / X2.4 异常确认、恢复、双侧保护与防复发（横切前三类）；X3.1 老师价值被准确、有授权地呈现 / X3.2 学生与合格老师高效适配并真实约成 / X3.3 固定老师、复约与长期关系稳定。v0.1 的「5+1+1」细分不删除，降为分析层。

## 三、Y 轴：能力地图与承载前置条件

能力分三层，避免把所有系统名都叫成第四种 Y：

| 层级 | 包含什么 | 是否进入战略主图 |
|---|---|---|
| **3 类横向武器** | 鹰眼（知道）、触达（推动行动）、匹配与推荐（连接） | **是**（当前坐标一律 `Y?`，未拿到端到端 Y2 收据） |
| **纵向能力包** | 招聘生产、资格／训练／Eval、异常处置、Workforce、教师工作台、可信内容、客户结果测量 | 否；由具体 X 组合调用 |
| **7 个共同内核** | 身份、数据、事件、规则、权限、记忆、反馈学习 | 否；是所有能力的地基 |

最高风险不是「少做一个系统」，而是三台引擎各自建设一套老师身份、事件、规则和反馈，最终形成三套互相矛盾的「老师真相」。

**Y2 组织承载前置条件**（v0.3 新增，过去两周暴露的最大 Y 缺口不只是「少一个 App」）：三类能力进入 Y2 前必须有人和组织真实承载——① 谁是业务 owner、生产 owner、第二负责人；② 中国 TOC、菲律宾本地运营、国内／海外市场各负责什么；③ 哪些节点必须由人执行（工单、设备整改、复杂质检、申诉、客户补救）；④ 服务时间、容量、安全缓冲、失败状态与升级阈值；⑤ 数据、产品、教室、推荐、HR、财务、法务等专业 Gate 由谁共签；⑥ 结果如何回写、旧入口和熟人路由如何退出。

**Y 判级原则**：有页面、接口、模型或流程 ≠ Y2（必须普通人可稳定使用、连续运行、异常可见、结果可回读）；写了 AI 或自动执行 ≠ Y3（必须具备感知、判断、授权行动、结果反馈、持续学习和人的责任边界）；局部组件与端到端能力分开判级（AC 可以是 Y2 组件，「异常被主动发现并保护客户」仍可能是 Y1）；身份、权限、审计、规则版本应先成为确定、可重放的 Y2 地基，不必追求花哨 Y3。

## 四、Z 轴：先标目标，不伪造当前坐标

**历史模型的三类 Z 计量对象**：`SP` 学生／家长（最终客户）、`CN` 候选／回流／新老师、`AT` 在岗老师。老师的身份按下方C16后继纠正理解：直接用户、价值共创者和独立权益主体，不与学生／家长的最终客户身份混同。内部运营、销售、审核、产品和技术团队是服务者或能力使用者，不能单独成为 Z 客户；同一需求同时影响学生和老师必须拆成两行，不取平均 Z。统一句式：`客户=SP｜客户任务=…｜当前=Z?【原始现象，生产待核】｜阶段目标=Z2｜长期目标=Z3/Z4｜收据=…`。证据标签：`【原】` 原始提报 / `【推】` 合理推断 / `【核】` 必须回真实系统验证。

**四道分界线**（三条价值路径：承接与解决 Z0/Z1→Z2；主动保护 Z2→Z3；成就与增长 Z3→Z4）：

| 分界 | 必须回答的问题 |
|---|---|
| Z0 → Z1 | 客户发出信号后，是否有明确的人接手并持续负责？ |
| Z1 → Z2 | 客户任务是否真的完成，服务、关系或权益是否恢复？回复、安抚和关单不算 |
| Z2 → Z3 | 是否在客户不必喊之前主动发现、干预并保护成功？只检测到异常不算 |
| Z3 → Z4 | 是否持续改善学习、信任、稳定关系，或老师的可持续收入与专业成就？一次无事故或一次曝光不算 |

**权益动作必须双客户验真**：熔断、降权、资格移除、换固定老师、自动代课、曝光、排序、流量等动作，可能保护学生却误伤老师，必须同时验证：学生是否真的避免或恢复损失；老师事实是否准确；老师是否得到解释、纠错、复核／申诉；是否存在错误限制机会；动作是否可撤回并留痕。「自动动作执行成功」只是过程收据，不是 Z 收据。

### 2026-09-15重读：两张收据与两本关闭账各自回答什么

客户结果收据回答客户是否真正得到结果，能力收据回答换个人能否稳定重复办理；这是Z与Y的区别。Y2可以只稳定服务一个战场，第二个X复用才能另证共享性，不能把跨域复用硬加为所有Y2的必需门槛。（[v0.2原稿](../../sources/raw/外教侧需求_X-Y-Z需求地图_v0.2.md)，L233–239。）

当次补救与根因整改则是一次异常的两个关闭状态。后继对齐版把根因从教师扩展到产品、系统、流程或供给容量，只有涉及教师时才进入相应权益处理；补偿不证明根因消除，系统修好也不掩盖客户尚未恢复。是否需要未来关系重建另交关系经营，不给同一动作重复记成果。（[v0.3原稿](../../sources/raw/外教侧需求_X-Y-Z需求地图_对齐版_v0.3.md)，L115–122、L263。）观察无复发时还要有真实暴露与后续机会，这是当前分析要求，不冒充原稿新增规则。

本次保存v0.3实际16项冲突；其“未增加第16”是旧计数残句，不删除C16老师身份纠正。头部截至8月17而正文含8月19补记，属于带后继补记的版本，不能把全部内容当8月17时已知；82项、21场等只是原作者覆盖记录，不等于本次重读那些底层材料。

## 七、下一轮只读回放：把 `Y?／Z?` 变成事实

正式排优先级或组队前，先做只读小回放（每条只回答：客户任务是什么、当前真实停在 Z0—Z4 哪层、依赖 Y0—Y3 哪种承载、哪步靠英雄哪步已有组织解、两张收据分别是什么）：

1. SIV 候选从进入到 Launch（真实分母、Studio→PRS 回执、质量与流失原因）；
2. 一名新师 0—30 天 TIDE（是否真实上线、任务／真课／支持／毕业如何运行、失败如何接管）；
3. 一节课中缺席坏课（谁先发现、替补尝试几次、两本账何时关闭）；
4. 一次「可见但不可约」选师（资格、地区、合同、标签、档期在哪里分叉）；
5. 一次固定关系排课 BUG（当次 17 节权益如何恢复、未来固定关系是否真正修好）；
6. 一条教师转介绍漏斗（是否把 Referral 从假设升级为小队任务）。

**验收铁律**：没有第二个人可重复运行、失败不可见或结果不回写，就不能判 Y2；没有客户任务真实完成，就不能判 Z2。两条收据（客户结果收据 + 组织能力收据）缺一不可。

## 八、Gate 要点（能力越强，边界必须越清楚）

任务／积分→毕业、曝光、约课推送：规则版本、分母、解释、人工复核、申诉、灰度、撤回，**不得把模型分数直接变成生计动作**；熔断、锁页、减流、停课、移除：双客户结果、人审或共签、错误纠正、恢复路径、审计，区域实操口径不能自动变全球规则；自动代课／匹配／关系变更：资格、档期、客户同意、替补容量、安全缓冲、失败重试、长期关系交接；教师故事、SIV、品牌素材传播：事实卡、教师授权、肖像／素材权、合同市场范围、渠道、有效期、撤回与纠错；跨境数据与 Agent 分析：用途、敏感性、地域、粒度、时效、权限、不落地边界，探查权不携带决策权；产品／模型上线：测试、灰度、观测、事故回退、真实成功回执，demo、页面可开、单一组件上线都不能替代生产验收。
