## 一句话

把项目协调从「人转述给人、会议对齐再散场」改为：**人只定义目标、拍关键取舍；各战线 Agent 在可追溯的议题中直接交换证据、合同和验收结果。**

Multica 只做跨机器的 Agent 通信与任务载体，不做新的项目知识库或替代业务决策。

## 为什么此刻值得试（起草时点）

7/17–7/18 实际施工暴露高频「人肉中继」损耗：评分口径、数据字段、任务模板、教师端回传合同分散在 Alaric / Wilson / Echo / Tina 等人手上；首 show 的每一段都有雏形，但「真实数据 → 标准信号 → 教师端 → 状态回传」仍无人对全链负责。这不是再开一次同步会能解决的——需要让持有上下游事实的工程 Agent 直接对账，并把结论留为可审计证据。

## 新增探索：做的人直接用，用的人直接做

> 记录状态（2026-07-24）：AI-native 工作范式候选；等待杨世文共享代码库后，再依据真实代码架构讨论操作方式。当前不创建开发环境、不申请权限、不修改代码。

Leon 提出的进一步探索：业务负责人不再只是系统的需求提出者和验收者，也成为**受治理的代码贡献者**——在实际使用运营后台时发现页面顺序、文案、默认筛选等可逆小问题，可直接在隔离开发环境中修改、自测并获得即时反馈，再提交杨世文 review、合并和上线。

- 要验证的不是「业务负责人能否比专业工程师写得更好」，而是：**将一部分功能的使用者与生产者合体，能否显著缩短体验—修改—验证的距离，并减少低价值的人际转述成本**。专业工程质量仍由统一的代码审查、自动检查、合并与发布边界保证。
- 需要的不是单一 API，而是一个最小**贡献接口**：代码访问、脱敏测试数据、可复现的本地/Sandbox 运行方式、独立分支、修改预览、自动检查、提交 review 和受保护的核心区域。
- 第一轮只考虑可逆、低爆炸半径的改动；业务规则、计分、任务触发、数据结构、权限、生产发布及真实教师动作不随本原则自动开放。
- **下一触发点**：杨世文共享代码库——届时先读真实仓库结构与现有开发/发布方式，再讨论哪些区域可由 Leon 直接贡献及完整闭环；不在代码到手前预设技术方案。

## 试点范围：只打一条闭环

**试点议题：7/24 前跑通一条可重放的 Sandbox 闭环**：

```text
真实/脱敏样本数据
  → 标准信号
  → 合法任务动作
  → 教师端 Sandbox 接收
  → ACK / 提交 / 完成状态回传
  → 证据留存与人工升级
```

不把「建通用培训平台」「全量生产部署」「修改毕业/激励口径」塞入试点。

## 角色与权限

| 角色 | 在 Agent 协作中负责 | 不允许做什么 |
|---|---|---|
| Leon | 定目标、拍产品/数据/业务取舍、处理升级项 | 被日常同步与细节追问淹没 |
| Alaric Agent | 信号引擎、动作目录、接口/审计证据 | 自行发明业务任务或生产规则 |
| Wilson/数据 Agent | 字段来源、样本、延迟和质量标记 | 把宽表误作 lesson 级事实 |
| Echo Agent | 教师端接收、状态机、回传与错误场景 | 把接口存在当作联调完成 |
| Tina/Sophia Agent | 模板、内容、完成/验证标准 | 将未拍业务规则写死为产品事实 |

人仍然是关键责任人；Agent 只在各自 owner 已授权的工作边界内交换材料和提出判断。

## 每个协作议题的固定合同

每个 Multica issue 必须一次写清：① 目标与边界；② 事实源（字段/文档/代码或 Sandbox 的可访问指针）；③ 输入输出合同（样本、schema、状态枚举、错误/幂等规则）；④ DoD（可重放的验收步骤与证据链接）；⑤ Owner / 时点 / 升级条件；⑥ 真实/Mock 标识（不得把模拟结果伪装成生产能力）。@mention 不是「催一下」，而是让某个 Agent 对这份合同补充、反驳或验收；关键结论回写 issue，避免二次口述。

## 推荐的最小运行方式

1. 建隔离 workspace「新师训练营 · Agent 协作试点」，只放项目相关人和其 Agent。
2. 先接 4 个工程 Agent（Alaric、Wilson、Echo、Tina）；不一开始建 squad、不启用自动化。
3. 只创建 1 个主 issue；由真实 owner 在需要时基于 issue 证据处理阻塞与升级。
4. 连续跑 5 个工作日后复盘：是否减少跨人转述、是否更快暴露合同冲突、是否真跑出一条闭环；不达标就停，不扩大。

## 试点成功标准（草案）

- 7/24 前有任何人可重放的 Sandbox 闭环证据。
- 每个跨战线阻塞都能定位到 owner、合同缺口和下一步，而不是「等对齐」。
- Leon 不需参加日常字段/接口同步，只处理明确升级项。
- 没有真实老师/学生数据、凭证或未经批准的业务口径通过协作空间外流。

## 启动前提（已物理核验）

- Multica 桌面端与 CLI 已安装，本机 CLI 为 `0.3.21`；支持 workspace、agent、issue、@mention 协作和受限 instructions/MCP，创建 Agent 时支持 Codex runtime。
- **尚未配置 Multica server / workspace，未运行本地 daemon，当前没有任何可呼叫的工程 Agent 网络**——这不是「今天直接开始群聊」的开关，而是一项有明确数据出口和权限边界的小型协作试验。

## 不可越的护栏

- 不把 Multica 当事实源：业务文档、代码、数据仍归原有系统；issue 只存协作上下文与证据指针。
- 不发送真实个人数据、凭证、生产密钥、敏感人事信息；先用脱敏 schema / Synthetic Sandbox。
- Agent 无权做业务承诺、改 KPI/毕业口径、发生产动作或替人做绩效判断。
- 自动化之前先人工跑通；任何持续监听、自动 @人 或跨组织扩展，另经 Leon 明确批准。
