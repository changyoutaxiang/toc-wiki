# 老师端成长工具与后台四 Agent 架构（新师训战营 MVP 施工）

> 2026-07-15 15:03 专项设计会（时长 ≈65 分钟），新师训战营 AI/产品化施工启动会。参与：王东(wangdong) 主讲；李雨熹 Echo、杨世文 Alaric、袁慧茹 Katherine、傅肖忆 Eva、贡嘉荷、Tina、李冠辰 Leo。
> 本会 = [[2026-07-13-老师试用期换尺与毕业标准四维]] 之后、8/1 死线前的施工定调——把战线从「定标准」推进到「用 agent＋自建轻工具把训练营跑起来」。

## 背景

规模约束是硬理由：每月约 **2000 名**新老师、8/1 上 30 天试用期，人工盯不过来——「必须 AI」的现实理由，不是技术偏好。

## 决策内容

### 一、老师端 = 极简轻量 H5/小程序，自建、不依赖大 App 团队

现有老师 App 迭代排期满（Echo 提），先自己做轻的。**定位被王东反复钉死：成长工具、不是考核工具**——分数不为淘汰、是告诉哪里能更好；排名不为羞辱、是激励往前；文案、交互全部往「帮你成长」做。

### 二、My Page 四块（对应 CEO 总纲 §二.5 老师端要求）

1. 我现在什么水平（分数＋排名）
2. 我哪里好哪里差（维度拆解）
3. 下一步做什么（训练任务）
4. 完成后得到什么（激励：课时费、推荐位、更多学生）

- 激励要挂真实利益：进步 → 下月接更多课；需与排课/薪酬系统打通（方向对、第一版可先展示「能拿到什么」，兑现后接）。

### 三、后台四 agent 架构与优先级

- 四 agent：**监控**（读每节课 behavior/CPU/network/camera，自动发现迟到、旷课、设备不达标、教学行为问题）／**培训**（按短板推针对性任务）／**沟通**（日常触达提醒、反馈、激励）／**评价**（综合 30 天出毕业判定：通过／重点培养／延长观察／退出）。
- **第一版只跑「监控＋反馈」两个**闭环（监控发现问题 → 反馈变成训练任务），中间用简单规则连，跑通再抽象中枢；培训与评价先简化、人工兜底。
- **人工兜底重决策**：退出/淘汰判定 agent 只出**建议不直接执行**、必须人 review 才执行（误杀一个好老师代价太大）；跑一段验证准确率再逐步放权。
- **触达最后一公里**：主阵地 App 内消息，WhatsApp 辅助；短期可能先用 WhatsApp/其他渠道兜底（Tina 出菲律宾老师触达习惯方案）。

### 四、三大硬前置（缺一即空转）

1. 数据 readiness——蔡琳(Danny) **7/24** 前给接口＋数据（课堂级颗粒度；拿不到则降级到天级别、但不能没有）。
2. 全量 AI QA 监控——「without full monitor we don't have score」。
3. 即时反馈系统 grow log／teacher meter——Leo＋王东团队**自建**、**7/30** ready，不等 App 团队。

### 五、MVP 验收 = 闭环，不是完美

8/1 让 2000 新老师进来、每人在 H5 看到自己分数与任务、后台监控 agent 自动发现异常并生成反馈——这就算跑通。「a bad version 也比没有强」。

### 六、边界澄清（防混淆）

- **训练营 ≠ Cocos 培训**（Eva 追问）：Cocos 面向全量存量老师技能升级，本训练营是新老师 30 天试用；两件事、别混（新老师进来要做 Cocos，但训练营是更大框架）。
- **本 MVP = 蜂巢系统在「新师培训」场景的第一个落地**（Eva 追问）：不一上来建大平台，先在一个具体场景把闭环跑通、产生真实价值再复制扩展。
- 沟通 agent **不取代 mentor**：把人从重复劳动里解放（1 个 mentor 盯 20 → 盯 200 的杠杆）；叙事做成「**教练不是监工**」的 win-win；情感/复杂环节仍由人做（Tina：菲律宾老师重人际连接、对「被 AI 监控」敏感，可能上 Facebook 吐槽）。

## 依据

- CEO 07-13 总纲硬任务之首（30 天试用与训练系统）与 §二.5（My Page）的施工层。
- 埋点从第一天想好：要能追踪「发现问题 → 干预 → 行为改变」链条——这是证明系统有效、向 CEO 汇报的核心（对齐 CEO 六类验收里的「系统结果/验证结果」）。

## 影响范围

- 新师训战营 AI/产品化施工架构定调；8/1 camp go-live 前的时间锚：7/16 AI coding 小队＋PM 出 v1、7/24 数据、7/30 grow log、8/1 MVP。
- 与 [[老师APP重启]]（05 月「体制内主阵地、外包审计四件套」形态）的承接关系：本页定「自建轻 H5、不依赖大 App 团队」——产品形态边界已由[[问题账]] TOC-34明确：老师端沟通阵地由 AC（AirClass）和老师 APP 构成，轻 H5 是训练营成长工具；本页不再另列历史对账开口。
