# Cocos AC 版本治理（195 强升试点·放弃 <3500·GPU 转 CPU 阈值·T-1 标签）

> 2026-07-16 专项决策会。参与：曹海璇（Shayne）主导；王东(wangdong)、袁慧茹 Katherine、王韬 Tao、蔡林、Haibao、韩长林、Lucy。
> 接续线：07-06 群日摘确认磨课教室临时方案（浏览器直开 Cocos 链接）之后，进入版本强升与设备标准的实施决策阶段；05-29「设备标准锚定 Cocos 黄金」（[[2026-05-29-设备标准锚定Cocos黄金]]）的存量执行路径。

## 背景（教师版本与标签现状）

- 已完成培训纳入名单：**6830 人**（国内 2598 + 海外 3072 = 5670 人已打标签）
- 版本达标（4.8.9 及以上）：**5037 人**；不达标（主力为 4.5 以下）：约 **1700–1800 人**，其中使用 2.x 极老版本 **380 人**
- 约 10–11% 教师（≈1800 人）无 CPU 分数上报（版本过低或硬件性能不足）
- 静默升级失效场景：依赖用户授权弹窗，**4.2 以下版本无静默升级能力**，需人工或强制手段介入

## 决策内容

1. **启动 195 人强升试点**：从 6830 名已培训教师中，优先对 195 名使用 2.x 极老版本且设备评分 ≥3500 的教师实施强制升级，本周内通过蜂巢监控缺勤率变化，验证强升冲击。
2. **放弃设备评分 <3500 教师群体**：约 12% 教师（≈1800 人）设备不达标，**判为自然淘汰**，不投入任何升级或运营资源——设备评分 3500 是当前资源投入截止线（硬性淘汰而非人工评估）。
3. **GPU 暂不作硬性准入门槛**：理解成本与招聘执行成本过高（Shayne 原话「看八字，废了」）；当时曾建议将CPU阈值提至3800分间接覆盖GPU需求，**该建议不作现行标准；统一3500分，2026-07-01全量上线**（源：Leon 2026-09-05确认，TOC-33/49/60）。历史行动：下一版本补GPU状态埋点、TS联系600+名疑似关闭GPU教师排查；这些功能验收不由标准上线确认代替。
4. **T-1 动态标签机制上线**：合规状态每日按 T-1 数据更新，教师回退即失效标签，形成「强升→监测→回退→再拉回」持续拉锯式运营闭环（「进三退二」模式）。
5. **版本关停长期路径**：新增教师从本周起**全部锁定 4.8.9+**（新增侧已闭环）；存量 2.x 教师分批强升（初期每日或每两天推进约 7%，匹配培训进度、控制出勤率波动），数量足够少后直接关停该版本入口。
6. **执行手段**：登录页强制弹窗「版本过低无法使用，请前往官网下载最新版本」（可按名单定向推送或按版本号批量关停）；课表页或教室入口加升级按钮。

## 依据

- 强升节奏受出勤率约束，不是技术上限：分批 7% 是为保住业务稳定性——若试点缺勤率无异常，可加速。
- GPU 准入问题本质是「可执行性」问题而非「技术正确性」问题：GPU 对画质有实质影响，但因检测路径与教师理解成本过高，现阶段只能通过 CPU 评分代理覆盖。
- 回退风险：教师可手动安装旧版 APP，导致已约课程异常（如变 PDF）；T-1 动态标签将实时捕获回退并失效。

## 影响范围

- 设备/版本治理线执行段：05-29 黄金锚 → 07-06 5.0.0.32 静默升级+三条件打标（被本页执行机制取代，见 supersedes）→ 本页 195 强升/T-1 标签。
- 与07-13「3500唯一基准」（[[2026-07-13-战役一二重构与3500唯一基准]]）衔接：**当前标准只有3500分，上线日2026-07-01**；3800提案已退出当前标准议程。历史≈1800人处置讨论及GPU方案保留，不把标准确认扩成存量处置或功能已完成。（源：Leon 2026-09-05确认，TOC-33/49/60）
- 体验课教师打标签覆盖率约 90%（多数可排付费课但可排量少）——存量标签现状。
