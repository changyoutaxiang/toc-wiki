# 会议摘要

本次会议把 Cocos / AC / Teacher APP 三条线的技术约束压成一个更清晰的战役判断：

- Cocos 新教材不是“只靠招聘侧抬硬件门槛”解决，而要先由产品技术侧把 400MB 教材压到 50MB 以内，并按设备/网络动态分档下发。
- AC 运行策略要从“所有功能都可开”切到“基础教学优先”：低配设备自动隐藏或降级虚拟背景、美颜、降噪等高耗能功能，把 CPU 和带宽优先留给上课主链路。
- Teacher APP 可以考虑外包加速，但它触及教师敏感数据和接口权限，必须走公司安全、代码 review、审计流程，不能因为快而绕流程。
- Level 内容结构仍未定：每个 level 约 96 节课，其中只有 20 节新版 Cocos 内容，剩余 76 节如何用 Free Talk / CG5 / CZ 5.0 对标内容承接，需尽快拍板，否则会卡开发推进。

# 已确认共识

1. 教材体积目标：新版教材从约 400MB 压到 50MB 以内，不再统一推高画质大包。
2. 动态适配：根据教师设备评分与网络状况，下发 10MB / 50MB / 100MB / 200MB 等不同版本。
3. 功能降级：低配设备上自动隐藏或降级虚拟背景、美颜、降噪等非基础教学功能。
4. 性能优先级：CPU / 带宽要优先服务 Cocos/AC 主课堂链路；动画 FPS 可设 30 / 25 / 12 三档。
5. APP 外包：方向可行，但必须遵守安全权限、代码 review、上线审计流程。

# 关键数据

| 主题 | 数据 / 口径 | 管理含义 |
|---|---:|---|
| CPU 占用：ERP + ManyTime + 虚拟背景 | 约 80% | 全功能并开不可作为低配默认场景 |
| CPU 占用：ERP + ManyTime，无虚拟背景 | 约 60% | 虚拟背景是高耗能变量之一 |
| CPU 占用：仅上课 | 约 40% | 基础课堂链路仍有可运行空间 |
| 虚拟背景日均使用 | 约 2 万节 / 全平台 10-11 万节 | 使用率约 20%，不应优先牺牲主课堂体验 |
| 美颜日均使用 | 约 1000+ 节 | 低频功能，优先级低于课堂稳定性 |
| 新教材体积 | 400MB vs 旧版 40MB | 教材侧必须先轻量化 |
| 教材体积目标 | 50MB 以内 | 老师网络可承载的关键线 |
| 设备评分 | i5 8代约 12000；i3 约 6000 | i5 8代应作为当前可保证基准；i3 需统计占比后再决策 |
| 外包成本 | 约 8000 元/月/人 | 可作为短期开发补位，但不能替代长期 owner 与安全流程 |

# 待决策 / 卡点

1. **I3 设备策略**：先统计全国/中心当前 I3 占比；如果 I3 占比极高（会议举例 80%），应考虑硬件升级，而不是无限降配适配。
2. **Level 课程衔接**：96 节 level 中只有 20 节 Cocos 新内容，剩余课节如何承接仍未拍板。
3. **Teacher APP owner 与维护机制**：AI 工程师或外包可短期承接，但后续维护、代码规范、权限边界必须有稳定 owner。
4. **API 数据安全**：教师敏感数据接口不能开放成“号内全量老师可被拉取”的风险，需要权限隔离和审批机制。
5. **预加载体验**：AC 采用预加载，但首屏延迟、后续翻页体验、资料泄露防护之间仍需测试验证。

# 对外教战役的影响

## 1. 硬件门槛判断被修正

此前风险更像“Cocos 上线会迫使招聘侧大幅抬硬件门槛”。本次会议后判断应修正为：

> 技术侧先通过教材压缩、动态画质、FPS 降档、功能降级和预加载机制，把 Cocos 最低可运行线尽量压回当前招聘标准附近；招聘侧仍要把设备作为质量变量，但不宜立即把硬件门槛一刀切抬到舒适配置。

## 2. Center / 电脑租赁仍是长期杠杆

即使最低配置可被压低，Center 和平台控制设备仍有战略价值：它不是为了解决“能不能上课”的最低线，而是为了保证 Cocos、新教材、自动化、教师环境和质量管理在可控设备上稳定运行。

## 3. Teacher APP 重启进入安全/流程约束阶段

Teacher APP 不只是触达阵地，也会触及敏感教师数据。若走外包或 AI 工程师快速开发，必须把权限、代码 review、上线审计和维护 owner 作为先决条件，否则会形成安全和技术债。
