## 一、最扎心的发现：设备分"3200 vs 5588"是两套语言的信息差

- **对外/对老师沟通口径 = 588（5588，对齐 Cocos 硬件）；系统实际判定准入用的却是 3200 分**——而 3200 本质是 **I3 设备的分**。
- 公司层面以为"我们已经按 S 级/高标准卡了"，**这只是纸面标准；实际执行还在用 3200 这把旧尺子**。
- **3200 的由来**：24 年系统设备检测上线时要求 I3-8 代 / I5-8 代 / AMD，研发拿设备跑分 = 3200。后来迭代**把 I3-8 代从招聘标准里去掉（提高标准）**，但**设备分判定值仍是 3200 没改** —— 这就是 gap。
- **更糟的是分数会漂移**：第三方跑分网站（"A 网站"，专业、持续更新）的版本天天调（V8/V9/V10…），**同一台设备 5/1 测 3200、5/10 可能变 1800**。
- **推论**：过去 X 个月里，我们用一把"虚高且会变"的尺子，放进来一批实际只有 1800–2900 分的低配老师。这正是当前大量老师设备分偏低、上课卡顿的现状根源。

### 数据（菲律宾"水晶球"5/21 拉取，国内全量样本）
- 总样本约 7595（国内实际更多，部分 CPU 型号第三方网站查不到、无分数）。
- 大于 3200 ≈ 6616；**小于等于 3200 ≈ 975**。
- 口径不一致：王韬用PH本地标准 → 低于 3200 占比 ~14.7%；李洋另一口径 ~7%。**同一问题不同版本算出两个答案**，正是要解决的混乱。

## 二、三套打分体系 + 王东的"货币锚定黄金"方法论

- **A 网站**：专业、持续更新，但分数会变（版本迭代）。
- **B 网站**：（友商使用）便民查询，分不变（与 V10 历史值最接近）。
- **自研 C（实测占用）**：测的是真实负载，但受电脑当时开了什么软件影响。
- **方法论（王东）**：把三套打分当三种货币（印尼盾/人民币/卢布），**以 Cocos 最低硬件标准为"黄金"（客观事实）**。拿一台刚好能跑 Cocos 及格的机器，分别在 A/B/C 跑分（如 A=3200、B=1900、C=2800），三者**等效映射同一块黄金** → 三套货币就被锚定到同一硬件真值。
- **决议**：标准由**老蔡拍一个**（别再各算各的数互相误导），且必须满足两条：①该分**能跑 Cocos**；②**不能比 Polly 的硬件要求高（标准不能比竞品苛刻）。

## 三、核心架构判断：静态准入分 → 动态实时分（AC 自适应）

- **现状问题**：只在准入时测一次**静态裸机分**，通过后**所有功能全开**（Crispr 特效 / 虚拟背景 / AI 降噪 / 美颜 / many cam / Chrome…）；但实际上课可能换了烂设备或设备老化降分，功能全开直接把 CPU 打到 100%。
- **终局方案（蔡林，7/1 前上线）= AC 自适应/动态分**：上课时 AC 实时检测 CPU，**低于阈值就只允许分级开启部分功能**（A/B/C/D/E 动态开关），把压力从"逼老师换设备"转回"AC 软件适配降级"。
  - 数据支撑：周末与李洋分析，一台 3200 分设备不开 m-cam 时 CPU 占用 28%，开了 m-cam 直接干到 100%——证明**静态分不够，必须动态判断**。
- **招聘准入两条分支**：
  1. 继续读硬件信号、算法判过/不过（现状）；
  2. **现场面试让老师打开必要功能实测**（尤其 **AI 降噪是必须项**），看 CPU"水位线"——一个都开不了直接淘汰，能开两三个到 80% = 勉强及格，全开 = A 类直接上岗。
- **倾向落点**：准入给老师**一个能听懂的硬标准**（继续用"588"这种语言沟通），进来后靠 **试用期 + AC 动态分**兜底（学 Polly 搞试用期，"借电脑混进来、试用期不行就淘汰"）。
- **存量老师同样要"洗一遍"**：用新标准筛现存老师，判断哪些设备有问题。

## 四、合肥卡顿归因

- **合肥卡顿 = 多因素叠加**，不是单一 ABCDEF 功能导致：
  1. **填课教材卡顿**：已优化，CPU 从 60% → 20%（降 3 倍），今天推测试环境。
  2. **新体验课教材比老教材 CPU 高约 15%**（老教材也卡，新的更高；老教材也在优化）。
  3. **Crispr（特效）+ many cam + I3 设备老师**上体验课/付费课叠加 → 老师 CPU 普遍 100%。
- **关键变量**：5/6 Crispr 上线体验课全量推 + 5 月放了一批 I3 老师上付费课（CC 自约的 229 名老师里 130 名是 I3）。
- **付费课卡顿是否"真爆发"存疑**：可能一直如此、只是现在才听到声音 → **把合肥所有"提出退费"的课逐个排查，用数据说话**，别乱下"设备/亏损造成"的结论。
- 虚拟背景 CPU 占用高，曲建菲一度想先关 → 被纠正（很有用）→ 改为让产研优化。

## 六、判断要点（给 Leon）

1. **这是典型的"单一事实源"治理债**：对外用 588（Cocos 口径）、实际判定用 3200（I3 旧尺），叠加第三方分数漂移 → 标准没有单一可信源，导致低配老师混入。修标准前，先把"哪把尺子说了算"钉死。
2. *"锚定黄金"是值得文档化的好方法论**：用 Cocos 最低硬件作客观锚点，把三套打分货币统一映射到同一真值——把"信哪个网站"的口水仗变成可计算的换算问题。
3. **终局是 AC 动态自适应**：把硬件压力从"逼老师换设备"转回"软件分级降级"，与 5/14 Cocos 技术会"最低配置下给插件开启指引 + CPU 优先级"的结论一脉相承；短期靠老蔡独裁分 + 试用期兜底。
4. **工程纪律亮点（全程曲建菲坚持）**：别拿合肥个案套全局归因，先逐课数据排查再下结论；卡顿是多变量叠加，不能把锅扣在单一功能或"亏损"上。这条纪律本身值得在战役里复用。
5. **与设备这条线强相关的下游**：F5 排雷里的"设备分屏蔽"、618 选老师时"一次性选设备满足 Cocos 的老师"、电脑租赁模式——都依赖这把尺子先校准，否则下游全是错的输入。
