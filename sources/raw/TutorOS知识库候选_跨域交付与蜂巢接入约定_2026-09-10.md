# Tutor OS跨域交付与蜂巢接入约定

## 核心判断与适用边界

**Tutor OS不只要让每个领域完成自己的步骤，还要让一节课产生的证据真正改变下一次教学，并让这条接力在失败、纠错和人工接管后仍能继续。** 因此，领域职责之外，还须明确结果接收、证据失效、执行权转移和方法变更四类约定。

本文吸收2026-09-10与51Talk OS首席架构师的首轮对齐及蜂巢系统首席架构师的补充，作为Tutor OS后续方案与评审的设计知识候选。首要依据仍是《Tutor OS整体方案V1.0修订版》设计宪法：Every Lesson Counts、逐课交付与长期供给共同经营、普通教师在支持中成长、好教师获得可持续收益、当课处理与系统改进双循环。[A §1–4、8、11、16]

下述内容分为三种身份：宪法已有原则、此次吸收的具体设计补充、仍需验证的试点假设。双方或三方方向一致不等于公司制度、具体人员任命、生产能力验收或权益动作授权。本文不改写宪法，不把其总体认领降格为待审；待定的是新增机制的实现、参数与试点条件。

## 一、跨域交付必须有实际消费方和全过程责任

示例：学生换老师后，下一位老师拿到摘要，但仍从头测试；课后新证据上传成功，却无人据此修订下一课。各系统都显示成功，学生仍没有连续学习。这是设计示例，不是本次实测案例。

| 责任层 | 应承担的结果 | 不应越过的边界 |
|---|---|---|
| Learning | 定义目标、权威学习状态和掌握判断；接收新证据与纠错，处理后形成下一次学习决策 | Tutor观察或模型推断不能直接成为正式掌握事实 |
| Tutor | 提供合格适配教师及支持；验证老师实际采用、核实或纠正前序证据，回流教学执行结果 | 不另建竞争的学生画像；课程或工具缺陷不能全变成教师训练 |
| Service | 确认客户选择、恢复接受和结案 | 客户未回应不能当作接受；恢复完成不能代替教师事实纠错或申诉完成 |
| Growth | 在可兑现供给内表达承诺，接收真实交付与客户结果 | 不承诺尚未形成的能力 |
| 跨域业务结果负责人 | 盯住整条客户任务是否实现，承接无人接收和长期悬空问题 | 不替代各领域的专业判断权 |
| 蜂巢任务协调者 | 等待、催办、超时升级与接管路由 | 不裁决学习事实，不必先实现为包办所有决策的Mother Agent |

每次交接至少明确接收方、截止条件、接收／拒绝回执、未采用原因和失败后的责任方。发送成功只能记为待处理；收到不等于采用；无后续观察机会应记为无法验证。

跨师接力应保留：**前序证据版本 → 老师采用／核实／纠正 → 实际教学与新证据 → Learning处理结果 → 后续课验证**。课程、工具和共因技术问题须交对应教研／产品／工程改进责任方。以上是逻辑契约，字段和服务须映射现有权威接口。[A §2–4、14、17；B 第1组；C 第1项]

## 二、证据纠正必须改变后续使用，不能只改一份摘要

课前上下文应携带权威来源引用、证据版本、适用范围、生成时间、有效期规则，以及缺失／争议信号；记录老师实际使用的版本。模型观察、待审建议、权威学习事实保持区分，运行记录不自动晋升长期共享知识。

当权威责任方修正证据，相关派生判断和消费任务应收到失效或重核信号。具体事件名称及传播接口待设计，不能假定平台已支持。

| 任务所处阶段 | 纠错后的处理 |
|---|---|
| 尚未执行 | 重新读取有效上下文，重核受影响的建议与动作 |
| 正在执行 | 按影响判断暂停自动动作、调整支持或交人处理；不因摘要变动机械中断正常授课 |
| 已经完成 | 保留当时输入、判断与Trace，追加纠正关系和必要后续动作，不重写历史 |

验收要证明旧结论不再驱动新的错误动作，能定位受影响的任务与方法应用。证据不足或模型超时应保留正常授课及结算主路径；质量评价修订也不自动回改已结算金额。[A §4、11.4、14–16；C 第2项]

## 三、人工接管需要切换执行权，不能只有“转人工”标签

Agent提出动作意图，正式排课、资格、权益和结算由权威服务在提交时重验权限、规则、资格、时段和对象版本。审批绑定具体动作、对象及有效版本，关键条件变化后重验。

人工接管后，旧Agent的相关执行权须撤销或隔离；晚到工具结果先查单、对账，不能继续触发后续动作。超时意味着结果未知，不意味着执行失败。重复事件、超时后实际成功、人工与Agent并发及迟到回执进入同一条可追溯记录。

逐任务明确最长等待、重试次数、费用及升级边界；数值由试点业务和技术责任方事先签收，不从讨论中编造。至少验证：并发占用、资格／时段失效、重复提交、提交超时但成功、任务重启、接管后迟到结果、客户拒绝和无合格候选。

业务结果、行动状态和运行Trace相互关联但分别收口。Trace回答哪次任务调用了什么，课堂证据回答教学发生了什么；任何一方都不能冒名替代另一方。[A §12–14、20；B 第2组；C 第3项]

## 四、平台暂缺时允许窄适配，但必须能迁移和退出

共享蜂巢承担通用运行底座是目标分工，不能据此推定持久任务、Context、Trace/Eval及发布回滚已经可用。历史演示、会议上线记载和共享文档不是当前接口验收。

必要时，可在现有授权系统上使用窄适配层、持久任务记录和显式人工接手，交付同一个完整任务。条件是保持单一权威事实源、继承既有身份权限、记录对象版本和回执，并可导出、回放、替换。登记维护责任、实际消费者、完整成本、平台缺口、迁移验收、复审日期和退役条件。

若权限、执行可靠性或审计无法满足，则留在影子／人工确认模式。不得由临时实现发展出第二套身份、权威事实库或通用调度平台。安全必需的共享保障可适度先建；第二真实场景用于证明场景能力可复用，不应成为延迟安全保障的理由。[A §12、18–19；B 第2–3组]

## 五、系统改进必须形成可验收的变更记录

当课帮助与长期方法建设是两条相连但独立的回路。一次支持已经完成，不代表系统已经学会。

从经验到能力至少保留：**问题／成功证据 → 候选方法及适用条件 → 修改的Spec／规则／Skill／工具 → 反例与独立评测 → 审核、灰度和回滚 → 后续应用及效果 → 保留、修订或退役**。

方法资产与一次应用结果分别记录。方法有版本、维护责任和失败条件；应用有真实采用、关联课堂、结果与完整成本。发现样本不兼任唯一验证样本，两个模型同意不代替独立证据。教学内容由Learning专业治理，教师培养及运营方法由Tutor维护语义，跨域消费方签实际使用结果。

签收覆盖业务结果、产品使用路径、技术可靠性、数据语义和事实源、独立评价以及资产维护／退役。这些是责任维度，不默认要求新增同等数量的人员。首期可以轻量版本记录加人工审核，不必等完整Registry或自动学习平台；工蜂负责建设机制，线上Agent不自行发布正式规则。[A §16、18、20；B 第3组；C 第4项]

## 六、试点同时检验客户效果和领域团队能否实际交付

**跨师连续教学是有条件的候选切口，不是已批准试点。** 先比较受益机会、证据可用性、支持可执行性、后续观察机会和完整成本。若跨师样本或事实不足，而同师反馈已有可靠校准及后续课，则转向同师窄教学任务反馈复检；不同时启动两套项目。

标准核验、影子验证、真实应用应压在所选窄任务内，不以前置完整评分体系延迟帮助老师，也不混用公司领域优先级的P0／P1编号。持续支持下的交付改善本身有价值；教师跨情境迁移另验，不为证明能力强行撤掉有效支持。教师收益与负担基线从首期建立，新奖励单独验证增量。

| 验收角度 | 必须看到什么 |
|---|---|
| 客户与教学 | 老师真实承接并推进学习；Learning处理结果；客户恢复与后续观察证据 |
| 教师与运营 | 准备及等待负担、支持可执行性、纠错和接管结果；保留低课量、退出、未改善与无法评价样本 |
| 经营 | 教师收益、人工复核、服务恢复、模型及维护的完整成本；窗口不足的续费或现金贡献仍记未知 |
| 系统学习 | 纠错改变后续行为；方法变更可回放、撤回，并关联应用结果 |
| 交付可复制性 | 领域团队能在明确且有限的平台支持下完成接入、发布、故障接管与回放；平台手工支持量及成本也要记录 |

不把“完全不需要平台帮助”当不合理门槛，也不把核心团队全程手工护航包装成可复制能力。第二场景验证前，只称领域资产或共享候选。

试点还应指认一条可退役的重复旧路径，例如手工反复转发课前信息；证明覆盖和回滚后再停止双轨。旧证据无法失效、接管后仍自动写入、权威事实对不上或成本越过签收边界时，暂停受影响的自动执行及扩围，回到授权人工路径。[A §18–20；B 第4组；C 第5项]
