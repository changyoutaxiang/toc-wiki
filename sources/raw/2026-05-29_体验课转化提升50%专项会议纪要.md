## 议题一：618 前「CC 可选/固定体验课老师」方案（车 B 横切）

### 1. 核心约束：体验课时段与付费课时段"绝对隔离"
- 理想产品形态：CC 可见**所有符合体验身份的老师**（含占课时段 + 可约时段），可选可固定。
- **但打通体验课/付费课时段是巨大底层工程，7 月前都上不了**（改动所有底层）。
- 妥协：6/10 / 618 前**只能做临时版本** —— 体验课**只能约到付费课时段**，约不到已被占课的体验课时段。业务侧须为此临时版本"**签字画押**"。

### 2. 分配流程改动
- 体验课课前 2 分钟集中分配前，**增加一个判断**：销售是否已"直约老师"。
  - 有直约 → 不再集中分配。
  - 没有直约 → 仍按原集中分配规则。
- 入口：SCRM 单独入口「AI 推荐外教」；代约场景（原会员中心代约）也加「AI 推荐外教」入口 → 进入新版约课页，新增课程类型「体验课」，约课功能同付费课临时课。

### 3. 推荐与池子
- **推荐逻辑沿用付费课那套**（来不及给体验课单独做一套）。
- 圈一个"**可上体验课老师**"池子，唯一条件 = 可上体验课。
- "我的收藏夹"可读 CC/SS 收藏的老师；可按姓名/ID 搜索；但收藏夹与搜索**都只能命中可上体验课的老师**。

### 4. 标签 vs 认证（澄清 + 决议）
- 曲建菲澄清：**标签 = 人工硬打**；**证书 = 通过学习数据/考证得出**，两回事。
- 王韬指出体验课培训是**直播培训**（要看老师真实表现），AI 自学式培训看不到真实表现。
- **决议（6/10 版）**：先用**人工打标签**（业务运营/师资运营认证），不卡线上考证。

### 5. 两个水龙头：CC 保送 vs 系统筛选
- **第一阶段（6/12 上线）= CC 保送**：王韬拉 **1–5 月被 CC 多次选过的老师**，按**转化率排序**、剔除低转化（多为只上过一两节的，转化率低的不要）放进第一批池子。
- **未来 = 系统化筛选**（认证 + 打标签 + 数据）。
- **共识护栏**：保送必须**限额**、**不能天天保送**、**不能全量保送**，否则会给后续系统化造成困扰；最终一定走系统化，但要预期到 CC 会抵触"为什么我收藏的老师少了"。
- **人质 vs 系统**（曲建菲反复强调）：当前只能靠"人质"（人工保证），但**人质一定会出问题**（如 A 级老师摄像头/停电/CE Demo 够演却不稳）；这是临时态，不是终态。

### 6. 教材 / Cocos
- 约课成功默认匹配体验课教材；**此入口不支持改教材**（改教材仍走原会员中心后台入口，保留销售操作惯性）。
- Cocos 国内 7 月初才上（中东 6 月），**本次先不考虑 Cocos**；但建议选老师时**尽量一次性把设备满足 Cocos 的老师选出来**，避免反复改造（合肥最大痛点正是老师设备/网络带不动）。

### 7. 最拧巴的点：学员自约后如何改选老师
- 转介绍保留学员自约。若学员已自约且**无剩余次数** → 销售需**先取消学员自约的课**释放次数 → 再走「AI 推荐外教」重新选时段、选老师。
- 海轩/海星方案（担心时间紧 + 想统一收口）：老入口不能改老师，必须取消重约。
- 曲建菲倾向最简：销售"指定给这节课一个老师"，但 6/10 上不了。
- **折中落点**：在老页面（SCRM / 学员 PC 详情）把已约时段**带过来、默认选中、推出老师**；点预约时处理 —— **系统不做自动取消课**（避免"课被吞"投诉），给销售两条路：(a) 直接给无老师的体验课指定老师；(b) 取消重约。
- **边界收窄**：**只有"代约 + 转介绍"的课才能选老师**（学员自己的多节体验课不动），并配套**销售培训**。

### 8. 风险与"买保险"
- 把"新武器"放进 618 决战战场风险高。**真正的坑大概率在学员/家长/销售的体验交互流程**，而非 20 个老师的供应（后者只是逻辑+产能+算术）。
- **保险方案**：保留一键回滚到最老版本（把入口下掉，约课沟通流程与原来一致、走自动分配），万一上线翻车可快速止血。

### 9. 资源
- 国内产研：**2 个服务端 + 1 个前端**；前端投入后基本就没别的前端了，服务端至少占 1 人。
- 牵连：主令 / 人民 / 腾飞 / 周周直播 / 市场端（需 Leon 侧协调，其余曲建菲内部消化）。
- **一键分享老师 H5 详情页**功能当前排期到 **6/19**，若要随系统同步上线需提前（H5 可播自我介绍/教学视频）。

### 10. 曲建菲三句话总结（议题一结论）
1. CC 对"**转介绍渠道 + 待约**"的例子，可以选老师。
2. 选出老师后，若次数不够需**先取消（学员自约的）课**再代约。
3. （可选）老师 H5 详情页可**一键分享给家长**。

## 议题二：F5 前五节课专项（车 A 纵切）

### 1. 体验课可固定 ≠ 解决 F5
- "体验课可被固定"只解决**真被固定的那部分 F5 学员**；**大量 F5 课并非从体验课池出**，那部分量更大、未被覆盖。

### 2. "这节课有没有老师"才是最底线
- 王韬：体验课能做到**零 miss**，是因为有**教务团队逐节监课**；付费课的菲律宾团队**没有这个组织架构、功能上也没有**。
- 王韬诉求：给 F5 课加**监课页面**，发现老师没进教室就**手动代课**，不等系统 4 分钟触发。
- 曲建菲反驳：销售明确说"**不要代课**"（不想要乱七八糟的老师），所以**代课不是解药**；销售真正要的是"国内**师资运营**怎么解决"。

### 3. 代课逻辑改造（曲建菲核心主张，本场较大改动）
- 现状：**课中 4 分钟代课**（当年为保护老师体验而设计）。
- 改为：**课前 2 分钟**识别老师 AC 是否打开 → 没开则**课前紧急代课但先不分配** → 上课时老师仍 off 则**分配新老师** → 保证**学生进教室时老师已就位，用户感知不到被代课**。
- 配套：代课老师专业 SOP + 服务端解释 SOP；并加"老师必须课前进教室"规则（不进 = 缺席 = 代课）。

### 4. 连续缺课案例 & 不可抗力
- 某学员**连续三节缺课**（连续三节缺席概率约百万分之 6.8，难理解为何命中同一学员）→ 查证为**老师停电请假**（菲律宾近期大面积停电）。
- **不可抗力问题确认"确实不好解"，销售也没要求解 → 翻篇**。
- 但"**为什么把这种连续缺课老师推出来**"是推荐策略问题 → 要做**反屏蔽**。

### 5. 退费归因争议（再次出现）
- 小龙 AI 分析：**60% 退费是外教原因**。曲建菲强烈质疑：**AI 质检从来不准**（口音质检最不准，小红书都写 AI 测不出口音），质检系统从前年至今换了几轮人都没解决准确性。
- 老邵"相信愿意相信的数据"，但确无更科学数据可替代。
- 量级拆解（沿用 5/28 口径）：外教侧 ~**0.4%**；开课前退费（与外教无关）~**0.25%**；其余在定级、定金等。

### 6. F5 三种模式（王韬的表/PPT）
- **第一种**：FTX 体验课可固定 → 直接变 FT 的 TTP 老师顺下去（**= 车 B 路径，最优，能打 Polly**）。
- **第二种**：体验课可被固定 → 收敛到第一种。
- **第三种**：F5 专属池 / "**驿站**"（建池筛人）→ 曲建菲判断**打不过 Polly**，且会陷入"月月建新池"的死循环。
- **共识**：最终走第一种（FT 老师可固定）；**F5 驿站只作为"筛一波、提升池子水位、解决紧急"的配角**。

### 7. 曲建菲对"池子/水位"的关键判断
- 真问题**不是水位，是"好老师不愿上体验课"**（这正是 FTX 难搞的根因）。
- 解法：让好老师**在这接课、接完长线走**，老师才愿意来；并让用户**提前感受老师**——"老师没有绝对好坏，是对不对口、感不感兴趣"。
- 比喻：**看菜单点招牌菜 vs 开盲盒配菜**，口味自己最清楚 → 这就是"可选 + 可固定"的价值。
- 对"打 F5 标签"：曲建菲认为**没用**（好老师早被约走，打了标签也约不上），更倾向老邵的"**预占放进代课池**"。

### 8. F5 在产研侧的落地浓缩（最终收敛）
**一句话：先排雷，把最差的解决掉。**
1. **零课中缺席屏蔽**：新生前五节课**所有入口都不推有课中缺席的老师**（只加一条屏蔽规则，最快）。
2. **定向搜索强提醒/硬屏蔽**：销售按 ID 定向搜某老师时，强制提示"该老师近期有缺席、不建议给新生约，非约自担风险"。
3. **零学习 + 设备分屏蔽**：屏蔽零课程学习 + 设备分不达标（**设备分合理值待定**：去年卡 3200 分，今年突然给 5500 分，需老蔡确认；因近期大量买设备实测才暴露此争议）。
4. **lesson support / 监课**：运营侧先做，产研给一个监课页面即可。
5. **代课逻辑改造**：见上 §3（改动较大）。
6. **F5 完课强提醒激励**：F5 课可给老师更多钱（相比退费成本，加倍工资都划算）。
- **合肥操作还原**：曲建菲**今天下午约合肥/河北 CC 现场演示**如何约课，还原"为什么推出问题老师"——怀疑是新系统操作问题，需亲眼看而非只听运营还原。

## 三、优先级与战略判断（给 Leon）

1. **两车不合并，分先后**：议题一（618 CC 选老师 / 车 B 横切）**有 618 时效性 → 最紧急、先做**；议题二（F5 / 车 A 纵切）**重要但无硬 deadline → 退为"排雷 + 驿站"配角**。这与 5/28"两车都先拿手里、明天评估"的悬念，今天给出了明确收口。
2. **车 B 是"会折磨一段时间"的长线工程，不是一次性产业**：当前体验课/付费课仍是两个隔离池子，时段打通要重做，**临时方案技术上极可能被推翻重构**。需做**期望值管理**——真要做到 Polly 那种体验"至少一个季度"，10 天突击只能给销售一个"临时支持的口"，用来**防业务侧拿体验差攻击我们**。
3. **"一年怕蛇咬"的政治风险**（曲建菲对老邵的提醒，单独点名）：上次 Beta 版本全开放体验差留下教训 —— **新武器进 618 决战场是高风险动作**，务必留回滚保险，且别让团队拿"临时版本体验不好"反复说事，因为这是**时间逼出来的权衡，不是产品设计取向**。
4. **F5 的本质杠杆仍在外部**：外教侧能撬动的退费盘子很小（~0.4%），AI 退费归因（小龙 60%）**站不住**（质检不准是历史顽疾）。曲建菲收尾点题：**"绝大部分 F 被上面（FTX 可固定）的老师都会上 → 基本就解决 F5，现在是没做透"** —— 即车 B 做透了，F5 自然消解大半，不必另起炉灶建池。
5. **人质 vs 系统**是贯穿两个议题的元矛盾：6 月只能靠人工（保送/打标签/监课/手动代课），但人质必然出问题；长期出路是把这些动作（培训数据 + 出席数据 + 设备分）**喂进算法自动筛**，与 5/26 师生匹配会的"火山引擎 + 数据投喂"一脉相承。
