# FSD 教学质量 Skill Phase 0：面谈冷读材料

> 用途：为 8 月 4 日的面谈准备。本文把提案、当前战役背景、已形成的理解和待讨论的决定放在一起，便于从同一事实底座开始讨论。
>
> 边界：这是会议准备稿，不构成对完整 FSD 系统、生产开发、课堂数据使用权限，或任何教师权益动作的批准。

## 先说结论

Sophia 提议的第一步，值得支持；但应该把它准确地定义为：**用 100 个历史体验课样本，验证 AI 能否低成本、可信地识别一个可训练的教学问题，并把它映射为可复测的训练动作。**

它不是要立即建设一套完整的“FSD 培训质检系统”，也不是要用 AI 给老师打分、改变排课或证明老师已经成长。

这项验证如果跑通，会补上新师营最重要的一块能力：新师营不只筛选出谁能留下，还能在真实课堂中帮助新手老师变得更好。

---

## 1. Sophia 提案到底要做什么

### 1.1 第一阶段的对象

提案聚焦一个很窄、很具体的问题：在新课程体验课中，老师是否完成了“目标语言有效操练”的基本闭环：

`示范或带练 → 学生独立输出 → 必要时纠错 → 再次输出`

首轮只看这一类问题，不试图一次覆盖“好老师”的所有维度。

### 1.2 第一阶段的做法

- 从 7 月下半月灰测期内的新课程体验课中，按预先固定的规则抽取 100 个有效课堂样本；不按投诉、转化、既有质检结果或课堂好坏挑选。
- 样本分为：30 个探索、40 个开发、30 个固定评测；固定评测阶段不再调整规则或 Prompt。
- Sophia 先进行独立盲标，再让 AI 对同一教学事件给出证据、候选问题、置信度和无法判断条件。
- 从固定评测集中抽取 20 个样本，交由第二位具备体验课质检经验的人独立盲评，用来检验标准是否只存在于一个人脑中。
- 每个识别出的具体问题，尝试映射为少量训练卡和后续复测规则。

### 1.3 这一步要回答的问题

1. 这个教学问题能不能被定义得稳定、可复核？
2. AI 能不能基于课堂证据发现它，并把“看到的事实”“作出的判断”“给出的建议”分开？
3. 人工复核是否能被证据包显著减负，而不是仍需逐节完整看课？
4. 识别出的问题是否真的能变成一个具体训练动作，并设计复测？
5. 在这个问题上，AI 可以处理到什么程度，哪些情况必须交给人？

### 1.4 第一阶段明确不做什么

| 不做什么 | 原因 |
| --- | --- |
| 不接入生产系统，不开发页面、接口或自动任务 | 先验证能力，再决定是否投资产品化 |
| 不实时监控，不自动向老师推送反馈 | 先验证识别与训练动作是否成立 |
| 不用于排课、评级、薪资、认证、淘汰或处罚 | Shadow Mode，不触发教师权益 |
| 不证明老师已经改善 | Phase 0 没有正式触达和后续课堂复检 |
| 不证明可覆盖所有教学质量问题 | 只验证第一个单点 Skill |

## 2. 为什么它和新师营是一件事

新师营当前的根本转向是：从“用一次 Demo 筛掉不合格的人”，变成“让新老师在真实授课的 30 天里被训练、被验证，最后由客户体验决定谁毕业”。

所以，新师营不应该只是一个更精细的筛选器，而应该逐步长出“育师”的能力。

可以把它理解成一条成长回路：

```text
真实课堂
  → 发现一个具体、可解释的教学弱点
  → 给出证据与针对性训练动作
  → 老师完成训练并再次授课
  → 用同类课堂复测是否改善
```

Sophia 的 Phase 0 只验证前半段：`发现问题 → 证据 → 训练动作/复测设计`。

“训练后是否真的提升”是下一阶段才需要用真实教师交互和复测来验证的事，不能提前宣称已经跑通。

### 对新师营的补充价值

- 新师营已有客户反馈、可靠性、硬件质量、供给和成长任务等运营维度；这个提案补的是**可训练的教学行为**这一维。
- 它不是要把所有教学能力重新压到人工培训上，而是先证明：在课程产品已提供方法的前提下，能否用真实课堂看见老师在哪个具体动作上没有做到，并针对性补齐。
- 如果识别、训练、复测逐步跑通，新师营就会从“持续评估人”升级为“持续造人”。

## 3. 已形成的共同理解

### 3.1 支持的方向

当前方向判断是：**支持把这件事作为新师营的补充能力来验证。**

长期价值不在于多一套质检报表，而在于形成一条能反复复制的能力：AI 从真实课堂里找到可训练的问题，人把标准、训练内容和争议裁决做好，之后再用课堂结果验证训练有没有用。

### 3.2 两个必须守住的前提

1. **识别必须以 AI 为主。**
   Phase 0 可以由 Sophia 逐例盲标，用来建立标准和校准 AI；但成功不能等同于“人工看完 100 节课”。需要验证的是 AI 能否稳定给出候选判断和可复核证据，让后续人工逐步转为标准建设、抽检、低置信度和争议处理；否则这条能力无法放大到更多老师和更多课堂。

2. **识别出来的问题必须可训练、可复测。**
   如果问题只能被指出、却不能转成明确训练动作，或者训练后无法观察同类课堂是否改善，它只能是一张诊断报告，不能成为成长能力。

### 3.3 护城河可能在哪里

护城河不在“AI 会看课”这件事本身，而在三件事同时成立：

1. 能稳定、低误伤地识别一个具体问题；
2. 能把问题变成真正改变课堂行为的训练；
3. 每一次训练与复测都会沉淀为更好的 Rubric、证据库、训练卡和边界案例。

当这三件事不断积累，培养一位合格新老师的成本会下降、速度会提升，能力也可以从新师营逐步扩展到更多老师。

## 4. 需要特别保护的边界

### 4.1 数据与权限边界

体验课回放可能含有学生和老师的敏感信息。样本使用前，需要明确：哪些回放和片段可用于内部质量研究、可使用哪些 AI 工具、是否需要脱敏、谁能访问、保存多久、如何撤回。

新师营当前的数据合同、持续更新和访问控制本身仍在补齐中。因此，“已有历史回放”不等于“本项目的数据已获授权”。这次 Phase 0 应单独确认其最小必要的数据边界。

### 4.2 教师权益边界

Phase 0 的标签只能描述一个课堂事件，不能外推为老师的长期能力画像，更不能自动影响排课、流量、评级、薪资、认证或淘汰。

一旦未来要将结果用于真实老师触达或权益相关动作，必须另行讨论规则、人审、申诉和审计链。

### 4.3 战役边界

这项试验应接入新师营的长期闭环，而不是另起一套老师主数据、评分体系或运营事实源。它可以贡献一个经过验证的“教学质量问题 Skill”，但不能在本阶段替代新师营已有的毕业、任务和数据治理机制。

## 5. 明天建议讨论并形成结论的要点

| 要讨论什么 | 建议在会上确认的结论 |
| --- | --- |
| 1. 这次到底批什么 | 以“教学质量 Skill 验证 Phase 0”立项；不是完整 FSD 系统建设立项 |
| 2. 首个问题是否选对 | “目标语言有效操练”是否足够具体、与新课程/新师营训练内容是否相关、是否确实可训练 |
| 3. 100 样本如何开始 | 先跑 5–10 个流程试跑；只有回放、目标教学事件、字段和工时记录连续可用后，再锁定 100 样本 |
| 4. 什么是 AI 的工作，什么是人的工作 | Phase 0 允许人工逐例盲标校准；AI 负责候选识别、证据整理和置信度。会后要明确进入下一阶段时，人工如何转为 Rubric、抽检、低置信度与争议裁决，而不是继续逐节完整代跑 |
| 5. 训练动作是什么 | 每种问题至少对应一个可执行训练卡和一个复测设想；先确认它是否可以接入已有培训内容/任务体系，而不在本轮建设平台 |
| 6. 怎样判断 Go / Adjust / Stop | 在固定评测前冻结 Rubric、Prompt、模型版本、抽样规则、独立复核与结果口径；会后形成可判断的阈值或至少明确决策原则 |
| 7. 数据如何合规取得 | 候选池、回放定位、AI 工具、脱敏、访问、保留期限与对照质检数据隔离，由谁确认、何时提供 |
| 8. 资源与交付 | Sophia 预计投入、产研一次性支持、第二复核人、教研边界裁决人，以及 6–8 周后应交付的复盘包 |

### 建议先把以下四项写成会议后的最小合同

1. **试验假设**：我们相信 AI 能在某一具体教学问题上，提供可复核且低成本的辅助判断。
2. **样本与数据合同**：样本从哪来、怎么锁定、哪些数据允许使用、哪些绝不使用。
3. **判定与训练合同**：Rubric、证据、转人工条件、训练卡、复测设想分别是什么。
4. **成功与停止合同**：什么结果值得进入付费课小范围迁移，什么结果只需调整，什么结果应暂停。

## 6. 本次会议不需要解决的问题

为避免把 Phase 0 讨论成一个大系统项目，以下事项不在明天一次拍完：

- 付费课迁移的具体范围和时间；
- 面向老师的正式反馈方式与体验设计；
- 生产系统、实时分析、专属模型、页面和自动任务；
- 教师长期能力标签、评级、排课、流量、薪资或认证规则；
- 其他教学质量问题的 Skill 排期。

这些都应以 Phase 0 的证据为前提，分阶段再决策。

## 7. 会议结束时最小应有产出

如果明天讨论有效，建议带走以下 5 个明确结果：

1. 一个被确认的 Phase 0 名称、目标和不做事项；
2. 首个 5–10 样本流程试跑的输入、owner 和开始条件；
3. 数据权限与回放使用的确认路径；
4. Rubric / 训练卡 / 第二复核的责任分工；
5. 100 样本完成后用于 Go / Adjust / Stop 的复盘框架。
