## 核心结论（认知突破）

1. **【认知突破】30 天训练营培什么，需要 completely 重新定义——训练对象不是"教学能力"，而是"用户初次感知"。** Leon 直觉拍板："它需要 completely 重新定义……大部分的教学能力会包给课程产品、包给 Cocos。" 定义的逻辑基础是**从客户角度往回导**（"我们不要从我们的角度讲，我们还是从客户的角度讲"），而非从运营/内部成功视角出发。这是 07-13 Sophia 点破"100% 运营思维盲区"之后，Leon 亲手把尺子掉转过来的一步。

2. **三层框架「好看 / 好吃 / 有营养」**（本会现场新造，按"用户可感知度"排培训优先级）：
   - **好看（looks good）** = 形象、背景、灯光、摄像头、体面的自我介绍视频、第一印象。用户与新老师首次相遇，"最先被感知到的是，是不是 looks good，包括 appearance，包括 background"。
   - **好吃（tasty / engaging）** = 设备网络自救（basic troubleshooting）、会驾驶 Cocos（"把这些乱七八糟模板从头点到尾"）、教学三板斧（极其热情的 hello / my name is / what's your name）、兜住孩子情绪。这是"最容易产生开始的恶劣体验的地方"。
   - **有营养（nutritious）** = 真实教学深度 / 效果。**largely 外包给课程产品**，感知慢、非训练营 focus（"学生如果不被你[吸引]还能跟你学，他自然有营养 / 跟 NTT 影响不大"）。
   - **目标态 = Customer ready**："你的老师一定要 Customer ready"，"我所有的老师在客户面前都是 60 分上的 / 给家长一个 70 分的体验"。

3. **【反直觉】排在专家 top-list 之外、却是用户第一痛点的：设备 / 网络自救。** Leon 拿真数据压场（"我拿个真数字给你们说，不要瞎编"）：953 节问题课里 **网络卡顿 40% + 设备问题 21% ≈ 70% 的课堂问题与网络 / 设备有关**（频繁进出、看不见听不见、课件打不开都是其果）。"老师要自己会重启一下电脑 / 每两节课重启一次"——从运营视角"太 low、一定不在你的 top list 上"，但**从学生视角是第一位**。新老师普遍不会处理（耳机突然没声等），应有文档 + 训练（basic troubleshooting skill）。

4. **训练营 = 筛选 + 培训 + 包装，本质是"包装"。** 类比选秀天团（100 少男少女一季度）：①筛选（五音不全 / 不敢跳的淘汰）②培训（基本舞步、唱歌、麦别掉地上）③包装。训练营对**已筛选出、有基本教学水平**的老师"做个包装而已——你训的就是他的包装、呈现"。30 天内能改变的有限（"咱没法把它变成凤凰"），所以**必须选择改变什么，且真在两周单位上改变**，锁定用户诉求里"比较高频的那么一两个"。

5. **这会改变招聘逻辑：从"马车夫"到"司机"。** 若"硬件过关 + 网络不抖 + 看起来好看 + 会驾驶 Cocos"就算"好老师"，尺子就变了——不再靠 CE demo 当裁判（CE demo 降为入门尺）。"我们从马车夫变到司机了，我们标准变了。"（延续 07-13"从造老师到客户投票选老师"的换尺，本会把它落到**招聘 / 评价中心的转移**。）

6. **Sophia 的边界追问（用户体验反派角色具体化）。** 她（+ 安娜）承担的"培训内容"边界到底是什么？——**只承接教学相关培训，还是新师试用期全过程凡有物料都算培训**？"不知道我培训的边界是什么，那我才知道我做什么。"她需要两个输入才能定义：① 找 **TS 团队（Sarina / Renao，mentor）** 要"新老师常见疑惑 FAQ"；② **用户访谈 / 新用户反馈**（课堂满意 / 不满意的点）。她另外抛出两点：老师**未分层**（同一天教不同级别，切换难）、MVP 应**先针对新老师、推向最大流量池**（"Poly 就是个大幼儿园，最多的是 K 和 Level 1，跟我们类似"）。

7. **【方法论·Leon 对 Sophia】边界靠"点火把"照出来，不靠事先定义。** Sophia 外企背景习惯"先说清边界再干活"；Leon 明确否掉这套用在当前环境："咱们这个环境不是，是一片混沌……今天和昨天聊的东西都是前天没有的、脑子里完全没这个概念。现在是 **make it happen**……这是一片雾，你把火把点亮，**照亮的区域就是边界**……没有上帝、没人能事先说清。"要的是快速把"60 分是什么"定义出来，边做边调。

## 一、认知突破：培训对象 completely 重新定义（从"教什么"到"用户感知什么"）

**Leon 的 reframe（战略判断）**
- 起点是承认改变有限："我们在 30 天能对老师进行的改变一定是有限的……咱没法把它变成凤凰。那么我们**选择**改变什么，并且真的要在两[周]的单位上进行改变。"
- 关键一跳——**换视角**："我们不要从我们的角度讲，我们还是从客户的角度讲。我们这些老师在大规模送到客户面前之前，从客户的需求诉求想，我们应该对老师实现怎样的[改变]。"
- 落到定义基础："它需要 **completely 重新定义**……这个定义的逻辑基础：大部分的**教学能力会包给课程产品、包给 Cocos**；当新用户和新老师刚开始相遇的时候，最先被感知到的是——是不是 looks good（appearance / background），以及最容易产生开始的恶劣体验的地方。"
- 这与 07-13 直接咬合：07-13 Sophia 挑出"整套设计 80% 是运营 / 内部成功视角、缺老师与用户视角"，Leon 当场认；**本会是 Leon 把那把"用户视角"的尺子真正拿来定义培训对象**——不是补一句提醒，而是重写培训的第一性问题。

**为什么这算突破（而非 07-13 的重复）**
- 07-13 定的是**毕业标准四维**（学生投票 / car / reliability / quality）——衡量"谁毕业"。
- 本会定的是**训练营塑造什么**——"培什么"。Leon 明确把"教学能力"从训练营主任务里摘出去（外包给 Cocos），把"用户初次感知（好看 / 好吃）"提为训练营真正的塑造对象。这是**培训内容的第一性重定义**，07-13 未触及。

## 二、三层框架「好看 / 好吃 / 有营养」与 Customer ready 目标态

**会议共识（现场即兴、待固化）**
- Leon："这个东西要**好看、好吃、有营养**。"三层按用户可感知度递减、按训练营优先级排序（见核心结论 2）。
- **好吃的本质**被具体点破："好吃的本质就是——你会**驾驶 Cocos**，把这些乱七八糟模板从头点到尾。" + 教学三板斧（"极其热情的 hello、my name is / what's your name，三四板斧搞上去"）。
- **有营养**最难、且被有意"降权"："有营养这个东西它的感知的[慢]……学生如果不被你[吸引]还能跟你学，他自然有营养……我觉得跟 NTT 影响不大。"→ 教学深度交给课程产品，不是训练营 30 天的主战场。
- **目标态**收敛为一句：**Customer ready**——"我所有的老师在客户面前都是 60 分上的 / 给家长一个 70 分的体验。"

> ⚠️ Leon 自己给了诚实的置信标注："我现在的直觉是——我不知道是不是上头了自己——它需要 completely 重新定义。"三层框架是**会上"连比划再说、稍微凑了几个"的即兴产物**，尚未定义、未抽检、未固化。

## 三、设备 / 网络自救：被专家忽略、却是用户第一痛点

**Leon 用数据压场（数据化正样板）**
- "我拿个真数字给你们说，不要瞎编。我昨天快速分析了一下 **953 节课**：**网络卡顿占 40%、设备问题占 21%**；频繁进出、看不见听不见、课件打不开，其实都是这两个的果，加起来[约 10%]。所以基本上 **70% 的问题都跟网络和设备有关系**。"（数据源：老蔡团队的课堂分析）
- 反直觉点名："当我们说培训老师，我们第一[番]一定不在那——'老师要自己会重启一下电脑'，这也太 low 了。"但紧接着掉转："**从学生的角度看**，这是第一位。""我猜大概率有一个东西不太可能排在你们（专家）前面……这一定不在你的 top list 上。"
- 现状缺口：耳机突然没声等，"老师是不知道怎么处理的，这种问题应该是有文档的……新老师会不会[处理]？"→ **basic troubleshooting skill 应进训练营培训内容**。

## 四、训练营 = 筛选 + 培训 + 包装；30 天改变有限，必须"选择"

**Leon 的类比与定义**
- **选秀天团**类比：进来 100 个少男少女，一个季度做三件事——①**筛选**（五音不全、不敢上台跳的淘汰）②**培训**（基本舞步、唱歌、麦别掉地上）③**包装**。
- 映射到训练营："我们只是在你**筛选出来有基本教学水平**的基础上，给你做个包装而已。你新老师的训营，你能训什么？**你训的就是他的包装、呈现。**"
- 强度定调（30 天不是"聊一下兴奋一下"）："我们这 30 天都在怼死、**往死里怼**，各种任务、各种激励往死里上。"

**招聘逻辑转变（战略判断）**
- "一个老师如果硬件过关、网络不抖、看起来好看、会驾驶 Cocos……我们从**马车夫变到司机**了，我们标准变了。"——这会改变的不是产品 ID，而是**招聘的逻辑 / 中心**。（承接 07-13「从我们当裁判到客户投票」的换尺，落到招聘端。）

## 五、Sophia 的边界追问与所需输入（用户体验反派角色）

**Sophia 的核心追问**
- "我和安娜所承担的这一部分培训的内容——是我们**只承接教学相关的培训**，还是**一切在提升新师试用期过程当中相关的、凡是有物料都归到培训**？我想知道**边界**是什么，那我才知道我做什么。"

**Sophia 需要的两个输入（否则无法定义）**
1. **TS 团队 FAQ**："我需要 TS 的人——teacher support，像 **Sarina 和 Renao**，他们有 mentor 团队、最常接触新老师——给我一个'新老师常见疑惑的 FAQ'；没有的话他们现场采访也能给我来一个。"
2. **新用户访谈 / 反馈**："我们所有的新用户，有没有人做过**用户访谈**？新用户对课堂满意 / 不满意的点是什么？"

**Sophia 抛出的两个约束**
- **老师未分层**："我们的老师是没有分层的。同一个老师同一天要教不同级别——教了幼儿园再教三年级，前一秒带着这个东西、下一秒就要下掉。带上容易、摘掉不容易。"
- **MVP 先锁最大流量池**："MVP 要先针对新老师、推向我们最大的一个流量池。**Poly 就是个大幼儿园，最多的是 K 和 Level 1，这跟我们类似**——那我们前提要不要先锁定这个？"（呼应 07-13"先限定 level 0–3 青少"。）

**Sophia 的一个实证（印证三层框架）**
- 她看过一位**被误投诉**的老师："他的整个呈现、他自己的情感很好、一直在兜孩子的情绪，**但背景太差、光线也很差**。我后来推给王涛，让 TS 团队把他的背景和灯光弄起来。"→ 天赋（好吃 / 有营养的底子）在，缺的正是"好看"的**包装**。这条实例直接坐实了 Leon 的三层优先级。

## 六、方法论分歧：边界靠"点火把"照出，不靠事先定义

- **Sophia（外企范式）**：先定义清楚边界 / 范围再干活——"不然没法干活，I do care about that。"
- **Leon（当前环境范式）**："先不要着急给他定义、确定边界，这种方式比较适合外企……但**咱们这个环境不是，是一片混沌**。今天和昨天聊的东西，都是前天、前代没有的，脑子里完全没这个概念。所以现在是 **make it happen**……这是一片雾，你把这个**火把点亮，照亮的区域就是边界**了。因为没有上帝，没有一个人可以事先整个说清楚——也不应该。就是快速地把'这个 60 分是什么'给他定义[出来]。"
- **收口**：边界不是前置输入，是**产物**；先点火（做 MVP / 定义 60 分），边界随光照展开。方法论层面这条**不止适用本项目**——见「可沉淀判断」。

## 可沉淀判断

- **【认知突破·候选正典】训练营培训对象 = 用户初次感知，非教学能力。** 30 天训练营真正塑造的是"好看 / 好吃 / 有营养"里用户高频可感知的一两层；教学能力大部分外包给课程产品（Cocos）。定义逻辑从"运营视角"翻转为"从客户诉求往回导"。这是 07-13"从造老师到客户投票"换尺在**培训内容**上的落地，值得晋升为战役正典（详见判例卡候选）。
- **好看 / 好吃 / 有营养三层框架**：一把可传达的培训优先级尺子——好看=形象背景灯光第一印象；好吃=设备自救 + 驾驶 Cocos + 教学三板斧 + 兜情绪；有营养=教学深度（外包、降权）。目标态 = Customer ready（60/70 分体验）。**待固化为可抽检标准**。
- **"马车夫→司机"**：当"硬件 + 网络 + 好看 + 会开 Cocos"成为好老师定义，招聘 / 评价中心随之转移，CE demo 降为入门尺。
- **【方法论·跨项目】混沌期边界靠"点火把"照出，不靠前置定义。** 无人能事先说清的领域，先 make it happen、先定义"60 分"，边界是探索的产物而非输入。这条是组织级工作方式判断，不止本项目——但需配"照到哪写到哪"的即时沉淀，否则边界永远在雾里（见四化·系统化）。
- **教学能力外包给课程产品、训练营专攻"包装 / 呈现"**：产品化方向正确（把最佳教学实践封装进 Cocos，而非靠老师个人手感）；训练营做的是包装。
