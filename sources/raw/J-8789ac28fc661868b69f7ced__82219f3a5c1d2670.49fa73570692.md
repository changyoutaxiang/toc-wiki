# 跨师教学连续性｜业务补充与架构师反馈

## Leon 转贴自己的业务补充

我补充一个业务事实，看看对我们的设计是否有影响。
作为互联网教学，老师和学员之间的关系，不是 1:1 完全固定。受多种因素影响，例如老师的slots，学员的时间，可约性，寻找和选择不同的老师等等，一名学员往往由多个老师共同教学。
当然我们在努力的推动“固定”，学员时间固定，老师固定，争取更大比例的形成“同一个老师教同一个学生”，具体到现实，固定率，它形成一个分布。

在上述条件下，我觉得，Tutor OS 的作用，其实更重要了，因为它能做到原来只靠真人但是不完全固定情况下，几乎没法做到的教学连续性。这可能是 Tutor OS 最大的 game changer，而且直接瞄准了客户价值。

## 架构师智能体回复

我会把这个事实放回架构中，重点检查：教学连续性应由谁负责、跨老师交接需要什么，以及首期路线是否应该调整。

**这个事实会实质性改变架构重点，也会改变首期施工顺序。** 我认为，“让多位老师共同提供连续教学”值得成为 Tutor OS 最优先验证的价值假设。

上一版设计已经包含跨课任务和连续性要求，但首期仍偏重“老师形成能力、完成交付”。现在需要把**同一个学生跨多节课、跨多位老师的学习过程**放到中心，检验整个系统。

**一、系统需要承担一份持续存在的教学责任**

在你描述的业务中，老师、时间和可约性会变化，但学生的学习进程必须持续存在：

- 已经学到了哪里，哪些只是提示下完成；
- 目前的主要困难是什么；
- 上一位老师尝试了什么，效果如何；
- 下一次应该承接什么；
- 哪些事情仍需要后续验证。

因此，我们的核心承诺可以进一步具体化：

> **让每一位接手的老师，都能接住这个学生已经发生的学习，并把他继续向前推进。**

这也是“老师能力得到增强”的一个非常具体的含义：老师开始上课时，能够获得自己原本不可能独立掌握的、经过整理和验证的教学上下文。

**二、固定率与教学连续性，要成为两个分别经营的变量**

可以将连续性拆成三层：

| 连续性 | 需要保持什么 | 系统的主要作用 |
|---|---|---|
| **学习连续性** | 目标、进度、掌握情况和未解决问题 | 维护有证据、可更新的学习状态 |
| **教学连续性** | 方法、支持方式、练习安排和后续验证 | 帮助下一位老师理解并实际承接 |
| **关系连续性** | 熟悉、信任、互动习惯和共同经历 | 支持复约与熟悉老师优先，减少不必要的关系重建 |

前两层可以成为系统重点建设的能力。第三层仍需要人与人之间的持续互动，教学记录只能提供帮助。

所以，推动固定仍然有价值；与此同时，**固定率分布中的每一类学生，都应该得到连续教学的保障。** 也不能默认同一老师授课就一定连续——没有记住上次困难、没有完成后续验证，同样可能发生断点。

**三、这要求建立一个跨老师、跨课次的正式承接机制**

架构上，应当持续维护“这名学生的这段学习任务”，每位老师承担其中具体的一次或数次教学。

一次完整承接至少包含：

**课前接住 → 课中验证与推进 → 课后留下证据 → 下一课实际使用。**

例如，以下是一个假设案例：

老师 A 发现学生在给出句型提示后可以表达观点，但还不能独立表达。下一节由老师 B 授课。

B 的课前提示应当说明：

> 上次在句型支持下完成；本次先检查无提示表达，再决定是否减少支持。尚不能据此判定已经掌握。

B 完成检查后，把真实表现和采取的方法写回。如果再由 A 或老师 C 授课，就能接到更新后的状态。

这里真正要验收的是：**交接信息是否改变了下一次教学，以及这种改变是否有效。** 生成摘要、老师点开阅读，都只是中间步骤。

相应地，老师能力模型也要增加一项：**理解已有证据、接续他人教学，并留下可供下一位使用的证据。** TIDE 应当训练和验证这项能力。

**四、这是 Tutor OS 与 Learning OS 必须共同完成的一条主链**

Shared《Learning OS》已经明确：它负责学习状态、下一任务和掌握证据，并向 Tutor 提供课前建议。《Global Tutor OS》则明确教师学情理解、备课教学和匹配支持。这为分工提供了依据，但尚不能据此认定跨师连续教学已经实现。

我建议明确：

- **Learning OS：** 维护权威学习状态，定义下一步目标及验证要求。
- **Tutor OS：** 选择能够承接的老师，把必要上下文和支持送到教学现场，核实承接情况，回流课堂证据。
- **共同的业务责任：** 指定一个端到端结果负责人，持续追踪这段学习任务；每节课另有具体教学责任。

Tutor OS 不另建一份相互竞争的学生学习档案。它引用同一学习状态，并围绕教学行动组织必要信息。历史判断要有时间、来源和版本；老师能够纠正，证据冲突时进入核实，避免错误随交接传播。

匹配也随之增加一个维度：

> 除了“谁有能力、谁有时间”，还要判断“谁能够以合理的准备成本，接住这个学生当前的学习”。

其中包括熟悉程度、学生选择、现有关系和所需支持，不能只按一次课堂的候选评分决定。

**五、我会调整刚刚制定的首期路线**

**首期试点的主观察单位，应从“一批新师”扩展为“一批学生的连续教学旅程”。**

具体选择一类课程或学习任务，观察一批学生的连续若干节课，纳入现实中自然发生的同师授课和换师授课。无需为了试验刻意让学生更换老师。

在这条学生旅程中嵌入：

- TIDE 新师如何在支持下接住已有学习；
- 熟练老师如何承接、纠正和继续推进；
- 正常换师时如何交接；
- 缺席或代课时如何同时恢复课次与教学承接；
- 有效交接方法如何用于下一批老师。

原来的两个场景继续发挥作用，但现在有了更直接的共同验收对象：**学生的学习过程有没有被接住。**

首个产品也应尽早交付“下一节课的教学承接简报＋课后证据回流”，并进入真实备课和教学流程。它会同时检验数据、教师入口、教学支持、匹配与反馈机制。

**六、验证这个 game changer，要看换师后发生了什么**

我会把以下问题放进首期验收：

- 下一位老师是否识别并处理了此前未解决的问题；
- 是否减少了因信息丢失造成的重复摸底、不必要重教和内容跳跃；
- 需要的复习、保持与迁移验证是否持续完成；
- 学生和家长是否感到老师了解学习进程；
- 老师的准备时间与认知负担是否可承受；
- 学习结果是否改善，而不仅仅是交接记录更完整。

比较时按固定程度、任务难度、学生起点等分层，优先在条件相近的群体中验证承接机制的增量。不能直接用固定率高低解释全部学习效果，也不能把有教学目的的复习当作浪费。

**我会把“跨老师的教学连续性”提升为首期业务结果之一，并用它重新组织试点和验收。** 至于它是否成为最大的 game changer，要靠这项证据证明：即使教师组合发生变化，学生仍能被理解、被接续，并持续获得可验证的学习进步。
