## 常规纪要

### 核心结论

#### 首要战略收获：Every lesson counts

**Leon 会后明确确认：lesson 成为基础单位，是今天最重要的战略收获。** 对这次会议的理解，应从这一认知升级展开，再去看各模块的选择与施工。

**L1 原话摘录（会后输入）**：

> “lesson”，成为我们的“基础单位”
>
> 我们原来的注意力都在“老师”身上，今天的认知突破是“lesson”，这个有点像认知世界的颗粒度，从分子到了原子
>
> 很多原来比较纠结的问题，都围绕这个“统一单位”，有了简洁优雅的解法
>

#### 这一哲学改变了什么｜COO 战略解读

**认知的起点从一个抽象的“老师好不好”，下沉到一次具体的教学发生：谁在什么条件下，面对什么学生和任务，做了什么，产生了什么结果。** 老师、学生、任务、工具和环境在同一节课中相遇，实际表现因此可以被观察，下一步支持也可以落到具体行动。

“原子级”指本次经营哲学选定的基础粒度。课内仍有更细的行为和任务，但这些细节共同解释这节课；长期能力与学习成长，则通过多节课的积累和连接来认识。

由此，许多问题获得了共同的推导起点：

| 原来反复纠结的问题 | 以 lesson 为基础的解法方向 | 会议承接 |
| --- | --- | --- |
| 如何定义好老师 | 从持续交付的课堂证据形成有时间、任务和条件范围的判断，再用于画像与资格 | 第 13–15 议题 |
| 如何把评价变成成长 | 看见一节课的具体短板，提供下一步支持，再用后续课堂检验老师与支持方法的变化 | 第 7、16、17 议题 |
| 即时鼓励与长期待遇如何兼顾 | 同一组课堂证据服务不同时间尺度：当次反馈、阶段判断与相应激励 | 第 14 议题 |
| 如何做更好的匹配 | 面向下一节具体的课，把学生需要、老师已证明的能力与必要条件组织起来 | 第 15、18 议题 |
| 多位老师参与时，怎样理解学生获得的价值 | 沿同一学生的课次序列看实际教学经历、承接与后续变化；老师变化时，这条观察线仍然存在 | 第 13、15 议题；跨师承接的完整机制仍属此前背景与后续设计 |
| 供给规模究竟服务什么 | 从人数、站点和上线量继续追到可兑现的课位、实际课堂与持续质量，判断什么供给值得形成和保留 | 第 1–12、18 议题；统一算法仍待建设 |
| Tutor OS 如何超越并列功能 | 让感知、沟通、训练、奖励、画像与匹配围绕同一课堂事实协作，再把结果送进下一次教学 | 第 16、17 议题 |

**统一单位带来的简洁，在于各模块开始回答同一件事的不同部分。** 它们可以共享课堂证据，同时保留各自的职责、规则和时间尺度；好课标准、聚合算法和具体政策仍需要研究，不能由单位统一直接推定已经解决。

#### 两条积累线，共同连接客户价值｜COO 战略解读

| 沿什么对象连接 lesson | 可以持续认识和改善什么 |
| --- | --- |
| 同一位老师的多节课 | 什么能力在什么条件下成立，支持是否有效，下一步怎样成长；形成持续更新的老师判断 |
| 同一位学生的连续多节课 | 实际经历了什么，哪些困难仍未解决，下一课应承接什么，以及长期学习、体验与关系怎样变化 |

这使“老师在具体条件下的教学能力”有了具体的观察现场，也使非完全固定师生关系下的教学连续性有了贯穿课次的观察线。**当老师改变，学生的课堂序列仍然连续；当同一老师继续授课，也要看前一课的证据是否进入下一课。** 这部分是基于会前业务事实和本次哲学的解读，不宣称跨师承接机制已在会上完整定案或已上线。

因此，“Every lesson count”在这份纪要中的经营含义是：**每一节课都有需要兑现的客户价值，都应留下理解老师与学生的证据，都有机会成为下一节课更好的起点。** 课次计数只是其中最基础的一层，不能替代对课堂内容、适用条件和长期结果的理解。

基础单位统一，也容得下复杂性：底线与正向教学价值可以分别判断；不同用途可以使用不同维度；学习进步可以跨课验证，贡献归因不必被强行压进单节课。老师的意愿、收入、关系、培养投入和经营可持续性仍是重要约束，须与课堂结果一起理解。

#### 再往深处理解：从识别好老师，走向持续创造好课｜v5 会后解读

**L2 给出了更准确的完整表述**：

> 以每一节课作为教学质量的基本观察和改进单元，以持续的课堂表现形成教师评价，以学生长期成长检验整体效果。

这一表述把三个问题放回各自的位置：**课是基本观察和改进单元，老师是能力形成与持续经营的主体，学生成长是最终检验。** 本节在 L1、L2 与原会议的基础上展开，是 COO 的会后解释和建设建议；不倒写成会上已经讨论完的方案。

**突破的深度，在于公司开始改变“用什么来认识和经营教学”。** 过去通常先凭入口表现、资历或等级判断老师，再期待好老师带来好课。现在可以逐步直接观察学生实际获得的教学，沿这些证据重新认识老师、课程、匹配与支持条件，并干预下一次教学。老师等级仍有预测价值，但预测需要接受真实课堂的持续检验。

这与此前“真正被经营的，是老师在具体条件下的教学能力”相接：**lesson 是这种能力被组织、被使用和被验证的具体现场。** 一位老师使用什么支持、面向什么学生、承担什么任务，在这里共同产生结果。因此，“把老师管理得更好”可以进一步发展为“把好教学持续生产出来”。这仍是有待业务验证的经营命题，不能靠概念本身证明效果。

**变化也从评价发生之后，前移到教学发生之前。** 如果一节课暴露出学生只能在提示下表达，系统的价值不止是事后打分，而是让下一位老师拿到明确任务：先检查无提示表达，再决定如何提供和撤去帮助。判断因此连接准备、支持、实际执行与复检；没有改善时，同时检查老师是否执行、任务是否正确、支持是否到位。

**更细的粒度首先提高了问题的可定位性，是否提高准确性仍需证明。** 把学生、老师、课程和环境放进同一现场，可以提出更有针对性的诊断假设：

| 逐课证据出现的模式 | 可以提出的假设 | 下一步要验证什么 |
| --- | --- | --- |
| 一位老师在不同学生中反复出现同类问题 | 可能与教师能力、习惯或共有支持条件有关 | 改变支持或训练后，后续同类课堂是否改善 |
| 多位老师在同一段内容都遇到困难 | 可能与课程设计、难度或工具有关 | 调整内容／工具后是否改善，排除学生起点等差异 |
| 特定师生组合不顺，换组合后表现改变 | 可能存在适配差异 | 在相近任务与条件下复核，不能只凭一次换师下结论 |
| 教学准备充分，网络却使课堂未完成 | 交付条件可能失效 | 核清平台、Center、教师端或学生端事实，修复后实际授课是否恢复 |

这些是 L2 提供的诊断方向，经本稿明确为待验证假设。它们的重要性在于：资源可以投向真正有问题的条件，而不把每一种失败都转成“再培训老师”。

#### 同一批课堂证据，形成三种积累｜v5 会后解读

v3 已明确老师和学生两条积累线；L2 进一步提醒，**还要让支持方法和系统本身积累有效经验**。第三种积累依靠前两条线的真实结果，不另造一套只看系统活动量的成绩。

| 积累方向 | 每一节课贡献什么 | 下一轮改变什么 |
| --- | --- | --- |
| 老师的条件化能力 | 在某类任务、学生和支持条件下的实际表现，包含未知、失败与纠正 | 资格范围、培养、教学支持、匹配建议，以及经规则签收的机会和待遇 |
| 学生的连续学习 | 当前做到哪一步、提示条件、未解决困难、后续要验证什么 | 同师或换师后的课前准备、教学承接、复习与下一任务 |
| 公司可复用的教学与支持方法 | 某种任务、训练、工具、匹配或环境调整是否有效、对谁有效、代价多少 | 经验证后更新支持方案、标准和系统；失效做法能够修正或退出 |

一位老师可能暂时在成熟教案和现场辅导下教得好。系统应保留这些条件，而不能把全部效果记成个人能力；撤去条件后也需要重新观察。方法只有能让另一批老师受益，才开始成为可复用的系统资产。

在非完全固定师生关系下，学生这条线尤其重要：老师可以更换，前一课留下的证据、困难和后续任务仍应被接住。**固定率和教学连续性分别经营。** 课前简报被阅读只是中间证据，要看它是否改变了下一次教学；后续课堂的表现再检验这个改变是否合适。平台已有能力和跨 OS 接口能否支持这件事，尚未完成运行验收。

#### 十五个业务模块如何围绕 lesson 协作｜v5 会后映射

这张表解释模块之间的业务联系，保留战略全景；它不是新组织划分，也没有改变会上近期工作的先后顺序。

| 业务模块 | 围绕 lesson 要回答的问题 |
| --- | --- |
| 居家老师转介绍 | 推荐和带新最终形成了多少适配需求、可以稳定授课的能力，而不只是多少上线老师？ |
| Center 模式规模化 | 哪些场地、时段、设备、管理和辅导条件，让好课更稳定发生；这些条件能否复制？ |
| TIDE | 老师在真实任务和必要支持下，证明了什么可授范围；哪些仍需补样、支持或验证？ |
| 成长衔接 | 合格以后，如何得到第一批适配课堂，形成收入、履约习惯与稳定交付？ |
| 鹰眼（全知） | 这节课实际发生了什么；哪些观察可信、哪些缺失，哪些只能提出假设？ |
| 沟通阵地（全达） | 课前重点、求助、反馈与纠错能否到达并被承接，老师能否主动推动问题解决？ |
| 薪资与升降级 | 哪些真实贡献得到及时认可，持续贡献怎样影响长期待遇；评价和政策分别如何签收？ |
| 培训与持续成长 | 这类课堂短板需要什么帮助，老师是否实际使用，后续同类课是否改善？ |
| 老师全员画像 | 逐课证据怎样形成有时间、任务、条件和可信程度的能力判断，而非永久总标签？ |
| 师生匹配 | 下一节课需要什么，谁有相应能力、意愿和课位，并能以合理准备成本接住此前学习？ |
| 老师包装外化 | 向客户展示的优势是否有真实课堂依据，适用范围和可约条件是否清楚？ |
| 直通车 | 体验课前看见的好供给，能否在付费后继续约到，并持续兑现教学与关系？ |
| 数据治理和本体建设 | 各模块是否引用同一课堂、同一事实来源，以及关联的老师、学生、任务和条件？ |
| 标准建设 | 本课底线、课程任务、个性化需要分别怎样判断；不同用途如何使用证据并持续修订？ |
| 全局供需计算 | 在具体区域、时段、课程及条件下，需要多少教学，已有多少可兑现课位，怎样补缺口？ |

**由此，Tutor OS 有了共同的业务对象和反馈入口。** 鹰眼不只向一个质量看板报数，沟通不只向老师发通知，培养不只完成课包，匹配不只读取静态标签：它们可以围绕同一节课的实际需要、证据与后续行动协作。AI 的作用是让原来无法逐课承担的信息理解、支持和复检成为可能；最终仍以真实教学是否改变来验收。

“共同对象”不意味着把所有信息塞进一份长档案，更不意味着只保留一个分数。建设时应能关联这次课堂的承诺、任务、老师与学生、课程与工具、时间和环境、实际交付、证据、后续动作及复检；具体数据结构和接口另行设计，引用既有权威对象。**未开成或受损的承诺课也要被看见，不能只统计完成课而消失失败；可用 slot、已约课、实际完成课和经验证的好课，仍是不同状态与口径。** 这是由新哲学推导的建模建议，未作为会上已经签收的字段表。

#### 同时保留三个时间尺度、三类判断｜v5 会后解读

| 时间尺度 | 要检验的价值 | 不能用什么替代 |
| --- | --- | --- |
| 每一节课 | 约定交付是否完成，教学和支持是否适合当次任务与学生 | 热闹、点击量、当堂正确率或即时满意度 |
| 一段连续学习 | 是否承接前课、处理困难、逐步推进，并完成必要的保持和迁移验证 | 逐课分数简单相加，或只看是否同一老师 |
| 学生长期成长 | 最终能力、学习体验和信任是否改善，经营是否可持续 | 单一续费相关性、内部效率或教师排名 |

有价值的复习、暴露错误、建立基础和延迟验证，未必让当堂分数最高。**Every lesson counts 的含义，是每一节课对长期成长有贡献。** 它不要求每节课都创造一个可以即时归因的能力跃迁。

同时，应分开三类判断：**课堂结果怎样 → 原因和责任是什么 → 按什么政策采取行动。** 一节课没交付好，并不能跳过归因就认定教师过错，更不能自动连到扣钱。代课老师、新老师或承担困难任务的老师，要保留条件差异、有效机会和合理观察窗。高频反馈也不等于高频排名；老师应得到支持、理解依据并能够纠错，而不是为躲避风险回避困难学生。

L2 的另一项关键提醒是：指标可能被“做漂亮”。多提示可以提高正确率，无意义重复可以增加说话时长，回避挑战可以提高即时满意度。Cocos 等过程数据提供的是观察，**学习价值仍要由合适的标准和后续证据检验**；不能让更高的课堂评分反过来成为评分正确的自证。

#### 从哲学到施工：先证明看得准、帮得上，再扩大｜v5 建设建议

这三道关口承接 L2，作为已有行动项的验收透镜，不新增一组会上指派，也不把首期范围扩成全量系统建设。

| 关口 | 要拿到的证据 | 对应既有会议工作 |
| --- | --- | --- |
| 看得准 | 核对真实交付、表面表现与学习证据；识别归因缺口、适用条件和误判；能够解释并更正 | A25 数据盘点、A29 评价矩阵，A19／A20 评价研究 |
| 帮得上 | 课前任务和支持被实际使用；后续课堂出现合适的改变；未改善时查执行、任务及支持条件 | A16 培养、A24 成长衔接、A27／A28 触达、A30 任务试验、A31 匹配 |
| 值得扩大 | 改善持续并可复用；学生受益、老师愿意参与，准备和运营负担、全成本可以承受 | Center 治理与培养、A30 小范围试验、A32／A33 直通车与区域验证 |

最窄的完整验证，可以在已有候选试点中选一类真实学生需要：**课前明确任务与支持 → 老师上课 → 取得证据 → 后续课堂复检 → 调整老师支持与任务方法。** 正常课和自然发生的换师都可以提供观察机会，无须人为打断师生关系。图上这一链是会后建设建议；人数、课程、责任和数值门槛仍需试点前签收。

首先要验证的关键未知是：**课前反馈或任务，能否让后续教学更好，而不只是让记录更完整。** 还必须有可用老师与课位、有效训练和实际执行承接；“发现了问题”不能替代“有能力解决”。随着前两道关口取得证据，再研究扩大薪酬和流量的作用；及时认可与逐课现金结算并非同一件事。

跨 OS 分工沿用此前讨论的设计边界：Learning 侧维护学习状态与学习效果标准，Tutor 侧组织老师、支持、教学承接与课堂证据回流；原业务系统维护正式排课等状态，Agent Hive 支撑有规则的协作，人类责任方签收标准、权益政策和结果。此处仅为建设背景，未将相关接口或运行能力视为已完成。

**L2 的收束，也适合作为下一阶段的建设主张**：

> 让公司从识别好老师，进一步走向持续创造好课；让每一节课的真实表现，帮助学生进步、帮助老师成长，也帮助系统改进。

认知突破已经由 Leon 明确认领；测量能力、可靠运行与教学经营效果，分别需要证据。这让哲学获得可以检验的落点，也保留了继续修正实现方式的空间。

#### 会议内容概览｜按原讨论记录

全天讨论的主线进一步清晰：**以每节课作为最小管理和评价单元，用数据看见实际教学，把学生需要转成老师可执行的任务，再用后续课堂验证奖励、支持和训练是否有效。** 这条运行链承接老师从进入、获得机会到持续成长的全过程，并通过匹配与直通车兑现客户价值；Center 和居家转介绍提供两种重要的供给组织方式。

傍晚场次的重要推进，是让“鹰眼、沟通、薪资、培训、画像”从五个并列功能，连接为 **观察课堂 → 评价 → 发出任务／反馈 → 老师实际执行 → 下一课检验 → 更新画像与方法**。这是一项明确的建设方向；观察能力、任务规则、执行承接与学习效果仍需分阶段验证。

### 关键议题与分歧

#### 1. 经营底盘：规模增长之外，需要分清“在册、活跃、有效产能”

**来源：P1 00:08:31–00:13:36、00:22:27–00:27:02；S4「Infrastructure and Data Governance Status」；R4 00:07:54–00:12:23。**

汇报从老师数量、上线、流失、开课和履约展开。讨论首先揭示：当前不少指标在各自口径下可以解释，但放到全局供给经营中，仍缺少同一套层次和分母。

| 指标 | 会中汇报 | 讨论中的解释或待核口径 |

供给增长也在适应需求变化：第二季度起，月度上线大致向两千人推进；第三季度更偏向国内业务需求。因此不能只用全年统一总量评价所有月份的招聘表现。

对于流失，海外需求未如预期发生、主动清理有问题的老师等，都可能影响总量。会上出现“好／坏流失”的讨论，但两类名称和比例的准确含义未充分交代，不能把流失率下降直接当作唯一目标。

傍晚直接把这些问题提升为三项基础建设，而不只是在经营报告中改几个数字。

| 底座 | 会上识别的主要矛盾 | 进展与要求 |
| --- | --- | --- |
| 数据治理与本体 | 今年进展未达预期，形成洞察仍常靠人找数和人工分析 | 蔡林团队在建设底座，外教是试点之一；会中报告本周开始装载较多数据、未来几周试用，不等于底座已完整可用 |
| Law & Standards | 缺少好课、好老师等共同定义，也缺少 Center 毕业、履约等更广泛业务标准 | 标准对象从老师扩展到课堂与业务过程；逐课评价矩阵是本次重点，不能把标准建设缩成一个总分 |
| 全局供需计算 | 国内和海外各有计算，却未与菲律宾供给充分连接；主要盯月上线和利用率报警 | 要能解释“每月真的需要两千名老师吗”，建立可指导资源投入的供需模型；TOC 业务承接，蔡林团队提供数据基础支持 |

**本议题留下的问题**：把需求、人数、可用课位、真实授课、新师形成周期和留存连成同一口径，才能比较激活、培养与招聘。建设必要性和责任方向已明确，完整算法、具体个人负责人及上线日期仍未给出。

#### 2. 履约治理：老师不缺席、学生有课上、替代课值得上，是三个结果

**来源：P1 00:25:30–00:39:56。**

汇报中的 TAR 与 Miss 不能混为一谈。TAR 包含老师对已安排课位的请假等情形；老师发生缺席或请假后，平台可能成功安排替代，因此不一定转成学生最终没有上课。反过来，即使安排了替代，也未必满足客户原来的偏好和期待。

| 层次 | 会议关注的问题 | 对应动作方向 |
| --- | --- | --- |
| 老师履约 | 能否减少原老师未按约上课 | 到课提醒、提前确认、稳定课位、设备和网络准备 |
| 学生最终获得课堂 | 原老师不能上时，平台能否接住 | 找到可用替代老师、缩短恢复时间、确认安排 |
| 替代的客户价值 | 客户是否愿意接受，并得到好的教学 | 优先熟悉或喜欢的老师，提高代课质量，尊重拒绝替代的选择 |

会中汇报 TAR 国内约 2.65%、海外约 2.84%；Miss 国内约 0.66%、海外约 0.29%。另提到最近一个月及 8 月指标继续改善，具体数值使用了不同时间窗口，不能与全年／阶段均值直接拼在一起。

具体进展包括：海外 TAR 从约 3.2%／3.3% 降到最近一个月约 2.19%，汇报将提前通知老师确认能否上课视为原因之一；国内 Miss 从一季度约 0.79%，到阶段值 0.66%、再到约 0.54%；海外从约 0.41% 到约 0.24%。这是会中报告的改善及解释，尚不能视为本次独立验证的产品因果效果。

一项关键数据是：在 Miss 原因中，“拒绝替代”占国内约 83.5%、海外约 51.1%。这两个比例的分母是相应 Miss 原因构成，**不是所有学生中拒绝替代的比例**。同时，拒绝选项可能由学生设置，也可能由服务同事操作，尚未拆清来源。

由此产生两种容易混淆的目标：平台具备更强恢复能力，和客户必须接受任何替代。会上明确注意到，客户原本选择某位老师，“随便换一位”不自动等价。后续“zero Miss”的强目标也加上了客户不愿接受替代的例外，不能记录成不顾选择的零缺课硬指标。

当前替代机制也存在供给限制：固定／喜爱老师优先、备用老师池较小、新师前十节课等条件限制，以及高缺席或设备不稳定老师被排除。系统主要是分配，而不是所有老师自由抢单；经 AC 触达或抢单式参与属于后续讨论方向。

**讨论的收束**：先降低原始异常，再提高恢复能力，并把代课质量经营成正向体验。最终验收不能只看“派出去了”，还要看客户接受和实际教学。

#### 3. 新师获得第一批真实机会：可把优质代课与成长衔接连起来

**来源：P1 00:40:16–00:46:29；P2 00:34:46–00:40:16、00:52:42–01:04:15；S4「Teacher Supply and Retention Strategy」；R4 00:14:35–00:16:04。**

会上反复出现的现实矛盾是：部分 Center 或新老师已经有开课意愿和时间，却没有足够订课；与此同时，平台又在为缺课恢复寻找可用老师。两端是否可以连接，成为一个具体机会。

候选方案是挑选**已经证明基本质量、设备和到课可靠性的新师**，为其设置一定时段的参与或收入保障，让他们承接适配的代课，同时仍可获得普通订课。这样既减少平台缺课，又让新师有机会被学生认识、获得认可和后续复约。

讨论没有把“新老师”整体等同于“优质替代老师”。相反，它要求比较候选新师与当前代课池的真实表现，并确认设备、网络和前几节课的准备。这与现行“前十节课新师限制”等规则存在需要解开的矛盾，不能仅因会上提出新方案就当作原限制已解除。

会上也区分了平台能主动调度的机会与客户自由选课。代课约占少数课量，会中用约 2% 作量级说明，却可能成为平台帮助新师起步的一个抓手。能否扩大，要看质量、成本、时段和后续自然订课效果。

新师等待第一单的数据也引发关注：不同月份和渠道出现五天以内、约十三天、约七天等不同等待长度。它们提示需求与新供给衔接不稳，但不足以形成统一的“几天必须订上课”结论。

傍晚把这里明确命名为需要新增的成长阶段：老师现在上线后就进入大池子，平台不清楚每一百位新师在十天、两周后还留下多少，哪些获得订课、哪些没有。未来从上线／TIDE 出营到成为稳定日常老师之间，应有专门的观察、支持与承接。会上把它比作新师的“teenager stage”。

这个阶段也被认为最容易建立培训、操作与履约习惯。它承接的是**合格到稳定**，不是另一个资格入口；十天、两周是拟观察的时间点，不是替代三十天试用期的新周期。

**仍需选择**：保障面向哪些老师、提供什么时段和金额、允许承接什么课、何时退出保障；平台投入后，怎样证明其带来了更好的课堂恢复和更稳定的新师成长。

#### 4. 老师收入与竞争力：从“每节多少钱”转向“好老师能实际赚多少”

**来源：P1 00:51:05–01:06:39、01:23:06–01:41:39；P2 01:05:52–01:12:14。**

会上认为，收入是老师体验的核心。对外竞争不应只看挂牌课酬，还要看老师可获得的课量、订课率、投入时间、Center 分成之后的实际到手，以及增收路径是否可理解。

汇报提到平均收入约国内 11,465、海外 12,245，但同时讨论了 Center 约 30% 分成加回后的“总收入”与老师实际到手的区别。其纳入人群和税费／分成口径需核，不能用加回分成的数字直接宣传老师实际所得。

今年部分月份收入改善，也可能与开课、订课及季节有关。会上要求按月、同比去看，不能仅凭六月到八月上涨就断定薪资政策已产生相同幅度效果。

讨论对过去偏向压低课酬、设置复杂升级条件的思路提出挑战：如果老师质量和贡献已经被真实课堂证明，应有更及时、更清楚的回报。否则好老师未必理解怎样提高收入，竞争对手更简单的报价也更容易形成吸引力。

作为现状，汇报称从今年四月起，已按经验设置不同入口：无经验者从 Level 1 开始，至少一年经验者可以从 Level 4 开始（P1 00:13:07–00:13:19）。这项会中报告的既有变化，应与本次讨论的下一轮薪资调整分开。

会上提出一个更强的长期目标：**在可比较的同一教师市场，让老师实际 earning 具有领先竞争力。** 不同国家、课程或教师市场可以有不同定价；“实际赚得更多”也可以来自更充分的优质课量，不要求所有挂牌单价都相同。

**入口价格的讨论经历了两步。**

1. P1 提出用更有竞争力的起点吸引人，减少对 demo 判断的过度依赖，再通过真实课堂中的试用表现识别。有“统一某一档”“先低后高”“有经验老师更高起点”等举例。
2. P2 又强调不同人群不能一刀切：有经验老师要面对相应市场竞争；应届毕业生或缺乏条件的人群可以结合 Center 支持，以不同起点进入。50、58、65 等只是方案演算和讨论中的报价，并未收束为全量统一政策。

另一个被提出的检验是：目前高起始等级／A、B+ 老师，真实表现到底好在哪里。纪律或操作更好，不等于学生反馈与教学效果必然更好；较高 demo 等级不能反向证明教学价值。

成本方面，会中用当前 CPL 与过去水平作比较，并举出有限成本增加换取更大老师收入增幅的可能性。这表达了**愿意为有价值的供给投资**的方向，不构成具体预算增幅授权。

竞争研究还应区分“守住现有好老师”与“吸引外部好老师”。P1 00:14:51–00:24:47 曾讨论识别同时在其他平台授课的老师，以理解真实流动和对方优势；它属于调研线索，既未形成完整名单，也未证明某地区老师天然更优。

**本轮回查补足了这一调研的频率和判断边界。** P1 00:21:32–00:22:06 提出跨平台任教及竞争相关数据应每月更新一次，同时指出：识别到部分跨平台老师，并不能据此认定其他老师都没有跨平台任教。此前 P1 00:13:36–00:17:04 结合 Mindanao、Visayas、NCR 的分布，追问地区间的教学、口音与设备稳定性差异，进而提出能否按区域定价的可能性；当场明确仍是在提问题，没有决定按地域直接划定质量或价格。按月更新是会上要求，具体个人承接未明确；地区比较与定价仍需数据和方案。

**仍需测算**：按来源、经验和质量分层的新旧政策成本；对现有老师公平性的影响；课量与课酬对实际收入分别贡献多少；什么证据足以快速调整待遇。第三段进一步讨论了逐课奖励和动态基础课酬，见第 14 议题。

#### 5. 招聘渠道复盘：从买线索、追上线，转向形成和留住供给

**来源：P2 00:02:56–00:27:41。**

招聘汇报回顾了月度目标、上线转化、获客成本、来源结构及 A／B+ 占比。一个突出的变化是 Center 来源增加，尤其六、七月新增站点对八月上线形成贡献；与此同时，居家老师的介绍视频等环节影响上线速度。

| 招聘报告指标 | 会中汇报值 | 解释范围 |
| --- | --- | --- |
| 月度上线目标 | 一至八月平均目标约 2,000；四至七月达到目标 | 八月达成数据另有冲突，见下文 |
| 招聘 CPL（每位上线老师获取成本）目标 | 一至四月 2,000；五至八月 1,500 | 与薪资讨论中的每课成本 CPL 分开 |
| 八月招聘 CPL | 1,118 | 汇报解释为当月 Center 相关来源占比较高；不含全部后续培养、管理成本 |
| 八月整体上线转化 | 约 2.57% | 需要核对线索与上线的同期归属 |
| A／B+ 来源占比 | 汇报称此前未达到 10%，九月已调整目标 | 目标与 demo 分类不等于真实课堂质量证明 |

Center 可以承接一部分缺少电脑、网络或教学条件的新毕业生，扩大原本难以进入平台的人群。这意味着它与招聘成熟居家老师服务的对象不同，成本与转化不能脱离人群条件比较。

但部分报告数字在口头表达中相互冲突：例如八月达成 97.65%，同时又出现 1,053／2,000；渠道占比的多组数字也不能直接相加为 100%。这些需要回原报表，不影响会议提出的核心追问：**线索量多，是否真正形成了有质量、能留下来的老师？**

会上认为，过去“更多线索中总能找出更好老师”的假设并未充分兑现。大量低转化线索还消耗招聘团队精力，使工作陷入处理漏斗和救火，挤压了对转介绍、Center 及上线后成长的经营。

转介绍成本约 1,649 的例子被用于说明资源去向：其中约 1,500 直接给推荐老师，其余才是获取／处理成本。与付给广告渠道相比，它可能同时增强现有老师的收益和参与感。但这只是资源结构的比较，还需看最终产出，不能仅凭钱给了老师就认定更有效。

会上倾向把转介绍和 Center 作为更需要深入开发的方向，并讨论先收缩部分中国侧营销，再视承接能力调整其他渠道。这里的含义是集中有限注意力和资源，不是确认所有营销立刻归零。

竞争对手 KOC 政策成为一个明显的信息缺口。有人认为其获客和老师组织方式值得借鉴，但现有认知包含零散观察和猜测，连伙伴的职责、收入结构都没有完全查清。会上要求弄清实际规则，不能只复制“让老师发视频”的表面形式。

**尚未定下**：各渠道继续投入的条件、停投节奏、转移金额、招聘团队工作方式如何改变，以及用上线、有效课量还是稳定存活来评价渠道。

#### 6. 居家与 Center 的共同逻辑：让优秀老师成为带出更多老师的伙伴

**来源：P2 00:27:41–00:52:09。**

转介绍讨论从一次性拉新，逐步走向“老师伙伴经营一组老师”的设想。可能从已有活跃推荐者中挑选愿意、也有能力的人，负责招募、帮助准备、辅导起步，直到新师达到明确条件，再由平台系统接续。

会上用 Mentor、Captain、KOC、Head Teacher 等词探索这一角色，但名称和制度没有定稿。关键变化是职责从“介绍进来”延伸到“帮助真正站住”，收入也可能与后续贡献相联系。

例如，挑选四百位伙伴、前两三个月按某比例分成等都属于说明可能模式的例子，不能当作正式人数、比例或期限。需要同时明确新师自主选择、伙伴责任、资格、退出以及持续收益依据。

这使 Online 与 Offline 出现一条共同逻辑：**一位有能力的老师，组织和支持更多老师。** 居家可以形成分散的伙伴网络，Center 则提供集中场地、设备、管理与培养。物理形态不同，但都可能让优秀老师从只靠自己授课，走向通过带人扩大贡献和收益。

讨论也没有忽略风险：如果网络只依赖某位中间人，伙伴离开是否会带走老师；平台与伙伴、新师的关系怎样保持；当平台尚未建立有效承接系统时，伙伴退出后谁继续支持。这些问题尚未形成解决方案。

**渠道效果证据的限制**：会上引用 TPCAP、推荐来源在活跃率、利用率、流失和收入上的差异，但其中存在优先订课、所服务市场及批次差异。当前表现有助于选研究方向，不能直接证明某一种组织方式在所有条件下更优。

其中一组较明确的报告对象是 **2026 年新上线批次**：TPCAP 来源流失率约 5.42%，推荐来源约 5.64%、活跃率约 84.08%。会上也讨论推荐者辅导是否使新师更愿意开课、赚到钱并留下；这一机制仍需要进一步检验。

#### 7. TIDE 的推进节奏与课前演练：验证资格，也减少可预防的失败

**来源：P2 00:56:11–01:04:15；S4「Teacher Supply and Retention Strategy」；R4 00:13:42–00:16:04。**

**TIDE 的当场推进口径已经补齐**：用 30 天验证老师能否合格交付、保护客户体验；九月进入灰度，**希望十月开始覆盖全部范围**。S4 将其压缩成“十月实现全覆盖”，R4 原句带有“hopefully”，因此本稿记为计划目标，不写成已实现或保证完成。具体覆盖人群、毕业标准版本与验收安排仍需规则正本承接。

新师早期真实课中的缺席、设备、网络和操作问题，促使会议提出先在模拟环境中演练。老师即使知道规则，也不意味着能在真实开课时完整操作；让学生承担这些可以提前暴露的问题，代价过高。

讨论也检视了内部员工试听这条替代路径：现有量较小，若接触未准备好的老师，还可能使员工对教师质量产生不良印象（P2 00:59:48–01:00:43）。这是转向研究 AI 模拟学生的具体理由之一，属于容量观察与顾虑，不代表已经测量出员工信任损失，也未因此取消全部人工试听。

候选流程是使用 AI／模拟学生完成一到两次课堂演练，检查进入课堂、准时出现、设备网络、AC 与课堂操作、异常处理等。通过后再进入真实课，未通过则继续准备或复演。演练次数、是否最多两次和通过标准均未定。

会上以每月约两千新师、每人十节早期课、每人两次演练作量级讨论，说明人工逐一保障的负担及 AI 支持的潜在价值；这些数量是设计估算，不是已排定的试点规模。

**能力边界很关键**：模拟演练可以减少技术和流程失败，但不能仅凭模拟通过，就判断老师能够教好真实儿童、已经满足出营条件。它可以作为 TIDE 和成长衔接的前置支持，不能把它记录为取代整个 TIDE 的新制度。

上午出现的十天、前十节讨论，涉及早期观察、代课准入或操作准备；与傍晚再次明确的三十天试用期并存，不能混成同一个制度周期。

#### 8. Center 的经营贡献：人数占比不高，但课量与稳定供给贡献更大

**来源：P1 01:07:49–01:22:36；P2 01:13:01–01:22:18。**

Center 被讨论为一种新的供给组织方式，其价值不只在集中办公，也在于帮助部分尚无电脑、网络或成熟教学习惯的人进入教学，并通过设备、纪律、同伴和现场支持提高有效产出。

| Center 数据 | 会中较清楚的口径 | 应保留的限制 |
| --- | --- | --- |
| 物理站点与经营者 | 162 个 Center、79 位经营者 | 站点数与经营者人数在讨论中有过澄清，应分别记录 |
| 场地潜在容量 | 约 6,000 个席位 | 不等于已经配齐设备、可以立即开课 |
| 已配备席位 | 约 4,800 个 | 与潜在容量分开 |
| 填充率 | 汇报称前一日约 96%，约二百个空位 | 不等于订课率或课堂利用率 |
| 教师占比 | 约 19%–20% | 不能据此估算全部课量 |
| 课量占比 | P2 报整体约 37.57%，海外约 41%；P1 另有 34.62% 等说法 | 时间、业务范围不同，需回报表统一 |
| 经营者类型 | 企业经营者相关站点约 84、前老师经营者相关站点约 77 | 合计 161，与总量 162 存在一处待核 |
| 最大单体举例 | 213 位老师、容量约 300 | 单点案例，不代表平均规模 |

其课量贡献超过人数占比，与开课天数、稳定时段、更多可用课位等有关。Center 具备供给效率的现实优势，但是否已经普遍提高教学质量，会上并未给出充分证据。

讨论区分了两件事：Center 可能抬高交付底线；Center 是否也能提高教学上限。过往抽样并未展示压倒性的教学质量差异，仍存在“把居家管理方式搬进场地”的情况。集中带来的培养和纠错条件，没有自动转化为标准化能力。

区域、口音与形象的讨论也遵循同样问题：不能直接因来自 NCR、某地或某个 Center 就判断更好。竞争对手在灯光、背景、呈现和课堂规范上的一致性值得关注，但外观更统一与实际教学更好需要分别取证。

**会议的关键认识**：Center 的价值需要由标准和持续经营兑现，不能只依靠场地与老师聚集本身。

#### 9. 固定、纪律与环境：标准是否生效，比挂什么模式名称更关键

**来源：P2 01:22:55–01:36:08；P1 01:07:49–01:17:22。**

Center 的固定开课安排引发了较长讨论：进入某种课酬或模式，是否就应承担明确的固定时段要求；现在的规则是必需条件，还是额外激励；为什么现场仍像居家老师一样自由开关课位。

会上对当前固定规则的理解不完全一致，对竞争对手是否“完全固定”也出现当场纠正。因此，需要回到具体标准及实际执行数据，不能用竞争传闻来制定政策。

特别需要区分三个概念：

| 概念 | 本次讨论涉及的含义 | 不能直接推出什么 |
| --- | --- | --- |
| 固定开课时段／课位 | 老师稳定提供哪些时间 | 不等于每节都由同一学生预订 |
| 固定师生关系 | 同一老师持续教同一学生 | 本场没有给出覆盖全体学生的固定率分布 |
| 教学连续性 | 后续教学是否承接此前学习 | 不能只用前两者替代验证 |

“固定是否提高续费”被多次当作待验证问题，而非已证实因果。比较时还要分清，是按老师只要开过固定时段就打一个标签，还是按每一节真正固定的课来比较。

环境方面，Center 的集中也带来噪声问题。移除 Krisp 后部分场地噪声突出，有的站点自行购买降噪服务；蔡林正在看商业降噪产品。讨论支持做实际测试，而不是把是否集中办公直接视为设备环境已经合格。

技术达标汇报提到，推动设备达到 **3,500 的 tech score 门槛**时，初期约有 3,000 未达标；经过四至六周升级，仍低于门槛的设备约 169。**3,500 是技术评分门槛，不是设备总数或教师人数。** 月底全部达标仍是计划，评分的具体测试定义及实际完成情况需回原表。

**未决项**：固定时段与价格的明确关系、站点最低环境标准、平台和经营者各自承担什么成本，以及数据应如何证明标准真的被执行。

#### 10. Center 下一步：先补治理、Head Teacher 与可复制培养

**来源：P2 01:36:41–01:56:21。**

会上对 Center 的近期顺序形成了比较清楚的倾向：其课量已接近重要份额，治理能力却未同步跟上；接下来先集中约三个月，把标准、教学管理和培养链条建立起来，再在年末复盘扩张策略。

这不是全面停止增长。已有扩张计划、经营者和现场资源仍然存在，但增长应与达标能力联动，不能只围绕新开多少站点安排工作。

**Head Teacher 是其中的具体抓手。** Center 经营者可以擅长经营而不是教学，但现场必须有人具备教学管理能力。会上以酒店店长类比，讨论平台培养、认证或安排教学负责人，经营者承担相应成本的可能性。怎样任命、谁付费、如何与经营者形成关系，仍有不同选项。

1:100、1:50 等师资管理配比在会上只是举例。真正需要先定义的是：Head Teacher 要能做什么、怎样判断合格、怎样获得课堂信息、怎样辅导和复检，以及平台如何确认其作用。

现场提出，部分经营者希望看到课堂，以便辅导老师，但当前可访问内容和共享边界未完全清楚；需要把标准、课堂信息、培训与现场执行关系接起来。会上也直接提出这件事需要一个**原子小队**推进，但成员、唯一结果负责人和具体资源尚未明确（P2 01:53:18–01:54:10）。

培养上，讨论主张从能观察、能训练的具体短板开始，例如发音、课堂表达和 TPR，而不是一上来只谈复杂教学能力。现有发音练习或 AI 工具有尝试和自述进展，但并未给出面向全部 Center 的成熟系统验收。

**近期方向**：把较好站点的做法转成共用标准，用真实课堂检验几个月的辅导是否带来改善，再判断哪些方法可以复制。经营者关系经营与教学负责人认证相互配合，不能以新增角色替代经营者的责任。

傍晚总结又把这一优先级说得更重：老师实际分为 Center 与居家两类供给群组（原文称 TBT／HBT，另有缩写转写变体），Center 的业务份额已经很大，治理、系统和标准若跟不上，会构成经营风险，因此将 Center 治理列在近期重点之首（R4 01:37:55–01:39:11）。这是对已有两种经营方式及其管理需求的进一步确认，未形成新的全量教师分类制度或份额目标。

#### 11. Center 扩张的约束：不只是钱，还包括老师能否尽快开始赚钱

**来源：P2 01:36:41–01:48:03。**

汇报提到 2025 年新增 52 个、2026 年截至当时新增 63 个 Center，以及未来数月拟新增约 30 个站点、四五百席位等计划。这些是报告中的计划量，不是本次新批准额度。

已有 79 位经营者运营 162 个站点，说明部分经营者发生了重复扩张。讨论认为，对已验证模式的老经营者，资本未必是唯一或首要约束；新老师何时获得足够订课、更稳定地赚钱，直接影响其下一轮再投入。

会上举例，有经营者希望某批二十个席位先达到一定收入水平再扩大。它说明经营者会等待上一批投资得到验证，不能把案例中的收入阈值推广成全体系统一扩张标准。

新经营者可能仍受资本限制。平台是否提供资金、上线激励和其他支持，需考虑缓解起步风险与维持经营者自身投入责任之间的关系。会议没有形成一个统一融资方案。

本议题与新师衔接连在一起：招聘新师、装好工位、完成上线，只是前端投入；如果真实课位与订课没有跟上，老师和 Center 两方都会承担等待成本。

#### 12. Center 毕业、转居家与竞对争夺：三方利益必须同时算清

**来源：P1 01:17:39–01:22:36；P2 01:57:11–02:26:09。**

老师在 Center 成长约一年后，希望转居家拿到更多收入，是会议集中讨论的结构性矛盾。Center 投入设备、招募、训练和管理；老师成长后不愿持续让出较高比例；平台既希望维持稳定全职供给，又要避免好老师流向竞争对手。

会中提到约 30% 的分成，以及部分大站点第二年降到 28% 的做法。它们不是所有 Center 统一适用的已确认制度。老师从总收入约一万六到到手约一万一的案例，也不能直接复制为平均收入结论。

**各方关切**：

| 责任／利益方 | 会议中表达的主要关切 |
| --- | --- |
| 老师 | 成熟后有更高到手收入和选择权；转居家也要承担设备、网络、环境及自我管理成本 |
| Center 经营者 | 前期投资和训练是否得到回报；同批老师集中离开会造成空位、重招和重新训练压力 |
| 平台 | 留住好老师，保持可用时段、质量和履约；不因限制内部转移，把老师推给外部平台 |

原有“毕业后”观察显示，前几个月在经营者继续管理下表现可能保持，后续则可能下降。但这里的下降可能涉及开放课位、活跃和稳定性，不能未经拆分就写成教学能力一定退化。

会上探讨了多种利益重组方式：降低后续分成；**经营者抽取达到一定额度后封顶**（P2 02:07:52，额度及周期未给定）；新增奖励不进入原分成；由平台支付一定持续管理费用；支持老师转居家后继续接受辅导；让成熟老师承担带新职责；调整毕业补贴等。20%、10%、带十位新师等数字均属方案示例，没有达成统一组合。封顶是候选解法，不是已生效合同条款。

汇报还提到约 4,000 的毕业激励、经过一定存续观察后发放，以及上月约六十位毕业。两个月／三个月的相关表达需要核对具体制度及变更时间，不据转写推出新生效规则。

讨论后段强调公司更希望老师持续留在 Center，以保持全职、固定时段等优势；但这不抹去前面提出的老师选择权。真正难点是使留下来有吸引力，同时保留可行的内部转居家路径。若只有公司和经营者满意，老师不满意，模式无法稳定。

**竞争事实及其证据强度**：

- 有经营者报告，Polly 曾接触 Quezon 的 Center，希望吸收已有一年左右经验的老师。会上展示或转述了较高报价，例如 85 对比 60、最高 125 等；具体对应资质、课型、附加条件和实际支付方式没有完整说明。
- “CEO Leon”在此指 Quezon Center 经营者。该经营者表示没有接受，不代表其他经营者都不会接受。
- 某些站点数、城市布局和筹建计划存在报告、材料和传闻混合；不能用它们推出已完成的大规模迁移。

竞争压力真正暴露的是：Center 可能承担了新师培养成本，却在老师成熟、希望增加收益时出现外流窗口。下一步应把毕业、持续支持、收入和内部流动一起设计，而不是只做挽留话术。

#### 13. 好老师评价的起点：Every lesson count，但不能简单宣布取消老师评价

**来源：S4「Restructuring of Teacher Management and Incentive Mechanisms」；R4 00:39:34–00:55:24、01:06:43–01:08:39、01:33:10；P3 00:01:42–00:12:50、00:20:53–00:22:30。**

傍晚先发生了一个明确转变：**以课为最小管理和评价单元**。相较一个复杂的“老师好不好”，具体一节课包含明确时间、学生、教学目标、交付条件和实际表现，更容易被观察，也更能对当次行动作出反馈。课堂把学生一起放进评价现场，能暴露“老师总体不错，但这一课不适合这个孩子”等情况。

这不是从评价“人”退回只查操作。会上进一步提出，核心产品可以从老师下沉到课堂、再到教学任务：什么需要被完成、谁能够完成、实际是否发生。更远的不同执行者形态属于未来讨论，不是本次替换真人业务的决定。

到了晚间 P3，问题接续为：既然选择逐课评价，老师评价是否可以由每节课累积形成？这使“课是最小单元”与“怎样理解和经营一个老师”接在一起。这里的“逐课评价”是本场建设方向，不能据讨论语态推断已全部投入运行。

会上回看了三类价值：可靠完成课堂、对学生学习产生有效支持，以及被学生认可、愿意继续选择。其中，可靠性与认可比较容易理解；学习进步能否归因给某位老师，则受到现实中一名学生由多位老师教学的挑战。

讨论没有因此放弃学习效果，而是把**看见学生进步**和**把进步分配给某一位老师**分开。即使后者困难，前者仍然值得衡量。以主要授课份额加课堂质量，再分配部分进步奖励的设想，属于候选方法；40%／50% 等比例只是举例，并非归因标准。

对于课堂本身，不能只记录错误和故障。老师是否帮助学生进入状态、给予合适的情绪支持、促进表达、形成有效互动，都可能是正向价值的组成部分。当前能识别底线，不代表已经充分理解好课。

“是否还需要老师评价”随后被薪资问题拉回：即使逐课发奖励，基础课酬、等级和机会仍然需要某种老师层面的判断。因此本场没有决定取消老师评价，而是在讨论让它建立在逐课证据上，并随近期表现更新。

**较趋同的认识**：

- 不能由一次 demo 或过去等级永久定义老师。
- 持续上出好课，才构成当期“好老师”判断的依据。
- 本月表现好，不自动保证下月；评价需要反映当前状态。
- 总课量、好课数量、好课占比、均分等怎样组合，仍未选定。

会上以“电脑坏、课没交付”说明客户得到的实际结果比抽象能力标签重要。这不等于已经裁定所有环境问题都是老师过错，也不能直接推断老师个人能力下降。

#### 14. 两种反馈速度：逐课奖励与周期性基础课酬／等级调整

**来源：S4「Innovation in Compensation and Evaluation Models」；R4 00:37:22–00:41:26、00:52:23–00:56:50、01:39:24–01:40:03、01:44:49–01:46:46；P3 00:09:54–00:22:30。**

傍晚以服务“小费”类比提出：奖励针对一次具体服务发生，而服务者的长期评价另有用途。好的课堂可以获得及时回报，明显问题也要反馈原因；不能只发钱或扣分，却不告诉老师哪一步值得继续、哪一步需要改变。新师还没有足够真实课时，其训练完成和准备状态也要被单独看见，不能只靠成熟老师已有课量设计激励。

在逐课证据的基础上，会上讨论了两种激励机制同时存在的可能性：

| 机制 | 希望解决什么 | 尚待选择 |
| --- | --- | --- |
| 每节课后的即时奖励 | 让老师看到“下一节课教好就有回报”，低等级老师也有当下动力 | 何种表现触发、金额、反馈形式、成本及误判处理 |
| 按一段时间表现调整基础课酬／等级 | 让持续贡献影响长期待遇，避免仅靠资历或一次入口判断 | 评价周期、样本门槛、上调／下调幅度、稳定性与公平性 |

会上出现每节奖励 1、3、10，以及基础课酬 50、65、75 等例子，也讨论按月变化、排行榜或累计分等方式。这些用于探索机制，不构成一份可直接执行的薪资政策。

**支持该思路的理由**：反馈更及时；好表现不会长期被低入口等级压住；老师可以看到行动与回报的联系；成熟老师也不能仅凭历史等级维持待遇。

**仍未化解的矛盾**：新师课量少时会不会天然吃亏；学生、课程和时段不同怎样比较；短期运气是否放大收入波动；经营者的收入预期如何保持；高等级下调后怎样解释和纠错。

讨论把两件事进一步分开：以真实课堂为老师评价基础是一层；多快、多大幅度地把评价作用到收入是另一层。对底层方向的认同，不等于对高频、大幅度动态薪资已经一致。

傍晚对施工顺序作了更清楚的区分：**新师价格对标可以较快算账；完整的逐课评价与奖励先测试。** 如果新师方案符合财务预算，可以考虑今年推进；评价、反馈、培训、QA 和个性化奖励这一整套机制，需要今年先建立数据、标准和小范围实验，规模化作用更多面向明年。会上提过找一两个 Center 测试，属于候选起点，并未完成试点签收。

因此，补齐前文后可以确认“按课激励”是本场明确的建设方向；仍不能宣称统一 65、每月大幅动态调薪或任何示例金额已全量批准。S4 中“VD system”的名称在 R4 对应转写也不清楚，本稿不将它扩写成已确认的分配制度。

#### 15. 从“知道什么是坏课”走向“更懂好课”：数据、目标与客户结果

**来源：S4「Definition of Good Classes and Evaluation Matrix」；R4 00:41:43–00:51:56、01:11:15–01:12:49、01:25:25–01:32:44；P3 00:22:45–00:33:51。**

傍晚把三个问题拆开：一节课能不能被评价；手头数据目前能评价到什么；评价出的“好”与客户满意、学习进步究竟有什么关系。第一点形成较强共识，后两点需要验证，不能因“有很多数据”就合并为“已经知道什么是好课”。

| 证据层次 | 会上讨论的可能信号 | 本场保留的困难 |
| --- | --- | --- |
| 单课交付与基础状态 | 到课、完整结束、设备网络、可观察教学行为 | 是底线，不能单独代表教学价值 |
| 单课教学目标 | 课件任务、首次答对情况、对话 ASR、目标达成 | 在提示／修改后答对可能掩盖困难；既有数据不能百分之百映射好课 |
| 当次体验与参与 | Engagement、挫败感、互动、情绪支持 | 学生性格、任务难度和适配会影响表现，热闹不自动等于学会 |
| 跨课学习结果 | 一段时间的 learning progress、考试或后续表现 | 需要多课观察；一名学生多个老师，不能简单归功于单一老师 |

眼前可先盘点已有课堂数据，做第一版矩阵和历史试算，边做边积累，列出还缺什么。原稿中“一个月补上更多第二层数据”的表达是推进预期，课堂质量评估仍需定量和定性共同工作。

会上提出，薪资机制能够用多大力度，取决于评价有多可信。如果对课堂价值的理解还比较粗，激励先保持相应谨慎；随着证据改善，再调整政策强度。

研究思路是把一名学生长期接受的课堂组合，与后续学生结果联系起来。例如，回看一百节课中有多少好课、平均质量如何，再研究与续费、升级、退款等指标的关系。它把研究单位从单个老师扩展到学生真实经历的课程组合，也回应了多人教学下的归因难题。

AI／Agent 可以帮助批量提出不同权重或候选模型、做历史回算、比较解释力。会上用十种、二十种、一百种方案说明探索效率，但没有证明现有数据已满足条件、模型已完成验证或即将直接接管薪酬。

**重要的当场修正**：有人提出可能需要一个统一评价标准，随后又讨论不同用途、不同结果未必只有同一组权重。因此本场不能收束为“所有场景唯一分数”。可听、可见、基本交付等底线与更复杂的教学贡献，也不能未经论证混在同一个总分里。

这里的业务指标可以帮助检验评价，但其相关性本身不能证明教学因果，更不能只因最能预测续费，就宣称某个模型已经完整衡量教育价值。这个边界属于对研究结论的必要限定，会议尚未给出因果验证设计。

匹配会消费这些课堂过程证据，而不只是消费老师总分；傍晚对现状、改进路径和直通车已有专门讨论，合并见第 18 议题。

会议最后还提出保留原始转写、让各自的 AI 继续处理，避免只有高度压缩的摘要。这份合并稿因此保留关键推理、不同选项与澄清，并附原稿回查入口。

#### 16. Tutor OS 日常运营：全知、全达与老师端 AI Support

**来源：S4「Tutor OS: Agent-Based Automated Operation System」「Shift in Management Grip」；R4 00:16:24–00:37:08、01:14:09–01:15:41、01:43:14–01:44:31。**

**经营目标**：不是再建一支两百人的人工团队来逐一管理两万名老师，而是建设 Agent 驱动的运营系统，使高频、个性化沟通、支持与管理可以发生。S4 用“不增加人手”概括这一目标；本稿记录为运营能力目标，不扩展成人员冻结或所有岗位编制决定。会上“两万老师”是量级表达，与上午报告的 24,530 人不使用同一个精确统计口径。

会上区分了广义和狭义 Tutor OS：广义覆盖供给形成、运营及价值输出；狭义讨论的是怎样把现有庞大教师群体的日常运营真正做起来。两者没有互相替代。

**全知：数据逐步出现，下一道题是知道之后做什么。** 新课改已增加师生两端埋点，部分教学表现、课堂设备与网络信息开始可得；但发音等细节仍有识别困难，新课件覆盖也有限。会上反复追问：“如果知道每个老师、每节课、每个要素，能做什么？”这是场景设计和行动机制的问题，不能只以采集量验收。

**全达：从单向通知走向双向、有内容、有结果的沟通。**

| 能力／使用面 | 会中报告的状态 | 后续意图与边界 |
| --- | --- | --- |
| AC 弹窗 | 本周已报告上线；依赖老师升级到新 AC 版本 | 版本升级覆盖仍是瓶颈；可发消息不等于所有老师已经收到、回应 |
| 开课与求课触达 | 缺席提醒已在做；求课、开放课位等方向继续推进 | 需要有效工作时窗，避免向不在班的 Center 老师发送无效求课 |
| 老师 App | 汇报日活一万以上；已有开关课、请假、课表及薪资查询相关入口 | 保持简洁，作为主要 Support 和沟通入口；具体功能实现形态需看现状 |
| IM | 客户端已有应用，讨论向老师侧连接；消息中可承载链接 | 老师端覆盖、业务联调和每类 AI 场景仍待完成，不能把客户侧上线等同于老师侧已完成 |
| App／AC 与 AI 联动 | 原子小队已有 AC 弹窗工作，并正与 App 外包侧联调、测试 | 在入口能力上接 AI Support／AI CC 类场景；不是完整双向闭环已验收 |
| 外呼与双向语音 | App 被讨论为未来承载面；当前测试仍偏单向通知 | 双向 AI 互动有技术问题，未形成已具备能力的结论 |

**产品分工较明确**：AC 聚焦上课相关事项，减少与课堂无关的弹窗干扰；App 承接老师日常求助、费用解释、信息反馈等。希望老师与平台无需在多处渠道寻找回应，而是通过统一入口完成双向沟通。AI 是支撑这种高频、个性化服务的主要方式。

费用问答被举为具体起点：把正式规则与老师实际数据接起来，直接解释为什么拿到这些钱、某项钱为什么没有发，而不是只给一页账单。另一个场景是老师收到学生好评后得到及时认可；全达不应只有催办和异常通知。

**强触达的讨论与实际权限必须分开。** 会上有将 App 做得像紧急提醒一样及时、要求老师开启通知／必要权限、按要求回应等强主张；也举过不打开就下线、签到积分、对重复缺席者要求连续签到等例子。其中“不打开就下线”后有“我就瞎说哈”的限定。可记录建设强触达标准、按问题加强支持与约束的方向，不能把示例惩罚直接写成已生效规则；“最高权限”也没有列出权限项，不能解释为 Agent 获得绕过业务规则的超级权限。

同段还提出，不缺席的老师可能不需要打卡（R4 00:36:47）。这一讨论包含按具体问题加强管理、正常授课者减少额外要求的思路；既不能改写为全员统一新增打卡义务，也不是已经发布的正式豁免规则。

S4 中“89% 响应率”经 R4 00:35:09–00:35:37 回查，语境是 **AC 相关应答数据**，并有当场澄清，不是 App 或全体教师各种消息的统一响应率。它为“明确规则后老师会响应”提供一项会中经验，分母与时间仍待核。

**资源与时间的真实张力**：R4 有“今年不投 RD 资源”的一句表达，同时紧接着讨论本月／下月是否投入、App 外包联调、约一个月建入口及四季度明显推进。不能据 S4 压缩成“今年禁止所有 App 建设”。较稳妥的会议记录是：历史上资源不足，接下来重点利用已有 App、IM、外包与原子小队打通入口；具体研发安排未完全收束。约一个月连接入口、一至两个月推进基础能力，是工作预期，尚未形成全部接口和工期承诺。

#### 17. 个性化任务、持续成长与全员画像：把每节课接到下一次改善

**来源：S4「AI-Driven Personalized Task Closed Loop」；R4 00:56:50–01:10:46、01:11:15–01:12:49、01:15:41–01:22:24。**

按课评价首先遇到公平性问题：同一老师遇到不同学生和情境，结果波动，老师会不会觉得奖励全靠运气？会上由此提出更主动的一步：**先根据学生当前需要，明确下一节课应完成什么，再观察老师怎样执行和产生什么结果。**

例如，学生某个发音需要修正、不愿开口的孩子需要被引导说出一句话、代课老师需要了解孩子姓名和兴趣，或一段学习需要被接住。它们均为会上说明思路的例子，不代表系统现在已能准确生成所有任务。

这个方案使老师获得具体支持，也使评价更可理解：不只是下课后收到一个分数，而是课前知道重点、课后知道依据。对替代老师而言，必要学情和任务还可能帮助其提供超出“陌生人临时补位”的体验；是否形成真实教学承接，要在课堂中验证。

**评价矩阵讨论出三个层次**：

| 层次 | 要看什么 | 与管理的关系 |
| --- | --- | --- |
| 基础交付与行为 | 到课、设备网络、课堂状态、基本行为 | 保障底线；需要修复时发出相应检查、提醒或改进任务 |
| 课程规定的教学任务 | 课件目标、应完成的教学活动及学生表现 | 检查课程要求如何落实；不能只看机械点击或页面完成 |
| 面向这个学生的个性化任务 | 当前困难、表达、兴趣、情绪支持、需要验证的事项 | 给老师具体支持，并研究怎样回报其对学生的实际贡献 |

会上曾用“现有能力大概已有五六成”等说法表达不是从零起步，但未给出分母或逐项能力清单，不能转成工程完成率。

**运行关系在讨论中被逐步补完整**：

1. **从课堂取得证据**：结合教学过程、设备、学生及家长反馈，形成可追溯观察。
2. **判断并发出下一步任务**：做得好的及时认可；教学短板对应训练；设备问题对应复测；缺席对应到课支持与必要约束。
3. **老师实际执行**：会上明确指出，任务发出后老师不理，循环仍然没有完成，因此必须看到做或没做。
4. **看后续课堂是否改变**：不是只看已读、看视频或做题完成；还要回到下一课、后续同类课堂，看问题是否改善。
5. **同时更新老师与方法**：没有改善，可能是未执行，也可能是任务不合适；要修正支持方式，不能只归因给老师。

“未来五节均分是否提高”“连续签到十节”等是演示如何检验或干预的例子，尚非统一观察窗口、淘汰门槛或奖惩规则。退出或限制授课仍需正式规则，不能由本段示例自动生效。

**画像的角色也随之明确**：从招聘开始留下老师信息，持续把课堂、任务执行和复检结果写回，形成每位老师的历史与状态；学生侧也有持续更新的画像与记忆。两条线通过真实课堂相交，为下次支持和匹配提供依据。这里的画像是长期经营老师的承载方式，并未被“以课为最小单元”取消。

会上还把家长正向反馈作为缺口：好老师有时要靠家长专门写信才被看到。希望让每节课之后更容易形成有效反馈，减少只靠固定周期人工回访挖掘信息。新的反馈方式值得建设，但没有形成关闭既有回访或要求家长付小费的决定。

**系统持续进步的目标**：更多课堂带来更好的理解，更好的理解带来更准确的支持与任务，随后课堂验证改进是否成立，使普通老师能够成长为更好的老师，并获得更好的收入。它首先是一条待跑通的业务与系统机制，不能以档案更多、任务更多、平均分上升单独宣布智能飞轮成功。

#### 18. 客户价值输出：课堂过程进入匹配，直通车连接“看得见”与“约得到”

**来源：S4「Teacher-Student Matching and Business Observations」及末四个章节；R4 01:22:24–01:37:00、01:40:17–01:46:46、01:48:31–02:18:46。**

**18.1 师生匹配：补进课堂中两个人实际怎样相处。**

会上认为，现有匹配主要使用老师属性、行政／行为结果和最终学生评价，缺少课堂过程。新数据如果能显示学生是否听懂、是否挫败、双方互动怎样，就能帮助判断“这位老师与这个学生是否适配”，而不只是排除总体较差的老师。

因此匹配应使用分维度证据。某位老师擅长某级别、互动好但设备需改善，不能全压成同一个总分；引擎可按当前任务取用有关变量。新课件覆盖较小、过程数据尚未充分进入匹配，是现实依赖。

技术方向讨论了算法、规则与本体 Agent 的组合。当前“2.0”被描述为仍大量依赖规则，并逐步补充基础变量；未来可让 Agent 根据老师、学生和课堂证据推理。会上有对效果的较强预期，但仍要求测试，未决定原算法立即退役。

**另一个需要接住的问题，是匹配机制本身越来越难理解。** R4 01:40:17–01:43:40 追问了持续叠加属性变量、规则和算法后的复杂性，并指出其对老师像一个“黑盒”，要求团队明确匹配接下来怎样发展。现有规则、数据和算法如何组织，是否以及怎样引入本体 Agent，仍未选定完整路线。第三方稿将其概括为“反黑箱”，有对应的原稿问题依据；但不能进一步写成已经确定唯一透明评分公式，或认为换成 Agent 就自然解决解释问题。

会中口头提到复约约 58%、使用率约 55%、海外若干 50%／90% 等数字，但市场、分母和指标互有混用；明确要求再看中东。不能把它们整理成已核验的统一效果表。

**18.2 老师包装外化：让真实好供给更容易被看见。**

傍晚再次提到竞对善于呈现老师，平台需要把已有好内容更好地对外展示。R4 将相关项目牵头称为 Tom，但本次未核实其完整身份，也没有提出新的预算或发布决定。它仍是价值输出的一部分，不能仅因逐课评价成为焦点而遗漏。

**18.3 直通车的两个部分，需要分别兑现。**

| 部分 | 客户得到什么 | 对供给端的要求 |
| --- | --- | --- |
| 体验课之前老师可见 | 知道将跟谁上课，能形成预期；进一步可探索提供几个老师供选择 | 可展示、能授体验课、所展示人选实际可约 |
| 体验课之后老师可继续约／固定 | 喜欢这位老师后，可以继续上付费课并形成更稳定关系 | 老师同时能教体验与付费课，后续课位未被其他需求占满 |

傍晚较早把直通车称为“静待花开”，是暂不急于宣布全球主要模式。后面的数据讨论更进一步：**优先支持国内及订阅制所需的供给方式，把中东等区域作为需要分组测试的方向。** 这两个阶段需要合起来读，不能只保留“暂不推进”，也不能改写成全球立即推广。

**试点报告与比较限制**：

- 合肥报告八月、九月新模式有较好转化和较高使用，占比有约三分之一的口头数据。会上同时明确，合肥不是严格意义的 AB 测试，与上海的客户来源、旧模式和团队使用习惯不同。
- 上海存在按能否使用新模式分组的比较，被认为相对更严格；但样本较小、实际使用也有差异，仍有继续验证空间，不能据会上“没有选择偏差”的判断就认定实验已消除所有偏差。
- 可见老师的预约方式，被认为有助于出席和转化；更强的既有 CC 自选老师表现也可能来自其熟悉的优质老师名单。到底是客户选择、老师质量、CC 手艺还是新流程起作用，需要拆开。
- 同师付费课与后续固定尚未充分兑现：一些好老师的时段被体验课或其他学生占用，即使能上体验课，也未必能持续约到。会上约 35.78%／37% 的同师付费课占比等口径，仍需回报表核验。

**被暴露的核心约束是供给**：想扩大，就需要更多同时能上体验课和付费课、又留有后续课位的老师。不能仅为扩大名单而给所有老师打体验课标签，也不能把体验课成功转化当成后续连续供给已经兑现。

讨论了限定老师池、由熟悉这些老师的 CC 支持匹配、Center 新师参与等可能方式，但尚未选定统一的占位和分配规则。长期设想是让“可教体验课”更像经过验证的能力标签，而不是割裂的固定身份；它以整体质量和底线提高为前提，并非下季度立即对所有老师开放。

**区域与产品选择**：国内有竞争压力，订阅制或弱销售模式也需要把产品说清楚、约得到，减少依赖销售解释；中东则提出找两个组做相对完整的模式测试。外部／Web 上课、老师可见、用户主动选择、同师付费后固定是不同的改变，不应把其效果混为一个“新模式”数字。

这里的订阅制讨论明确举到**未来欧洲拓展**：销售较弱或没有销售时，老师可见、供给可用需要由产品本身兑现；港澳台、中东等则被列为需要进一步测试的区域。会上同时指出中东的测试组织能力较弱，提出以完整团队分组试验，并先在国内摸索清楚供给链（R4 02:04:11–02:05:42、02:09:24）。这些是不同场景的理由与验证安排，不能整理成已批准的“国内→欧洲→中东”固定扩张顺序，也没有新增各区域开业或上线时间。

下一轮还可测试由 AI CC 提供三位老师让客户选择，将选老师从部分老 CC 的经验变成可复用流程。即使与高手旧方法效果相近，能让新人稳定使用也有组织价值。是否提高出席、转化及后续固定，需要分别验证。

R4 末段出现“下周定标准、测到月底看稳定性后再推进”的时间方向，但具体标准、推广对象和个人承接在转写中不够清楚，保留为待细化安排，不写成无条件月底全量。

## 基本法审视

以下为 **COO 对本场材料的审视，属于会后分析，不属于会议发言、决议或新增指派**。v3 依据 L1 更新解释重心；“本场证据”仍只引用原会议材料。

**本场启用包**：客户价值北极星（代课选择、好课与学习价值）；战略聚焦与长期主义（渠道资源与 Center 治理顺序）；系统化交付与持续进化（演练、Head Teacher、逐课证据及方法复用）。依据为 [《51Talk 基本法（15周年发布版）》](../../../../strategy/01_上位约束/51Talk%20基本法（15周年发布版）.md) 当前本地正本。

### 客户价值北极星

- **基本法原文依据**：第一条《使命》要求所有战略与系统回到客户能否更有能力对话世界；第三条《价值观》：“成就客户不是讨好客户，而是持续理解客户、持续创造客户价值、持续帮助客户成长。”
- **本场证据**：第 2、3 议题保留客户拒绝替代的选择；第 13、15、17 议题讨论教学目标、参与、个性化任务与学习进步；第 18 议题进一步检查体验课选择与付费后同师可约能否一起兑现。
- **判断**：以 lesson 为基础，使客户价值落实到学生实际经历的教学，方向与基本法一致；沿学生的连续课次观察，才能继续判断这种价值是否累积为学习、体验与信任。实际效果尚无法判断。风险是把课次增加、单课高分或续费相关性当作价值本身，或为新师培养而牺牲客户选择。
- **要补的闭环**：同一节课分清承诺、实际发生与结果证据，再沿学生的后续课次查看任务是否被承接、困难是否改善，以及付费后能否继续约到合适老师。单课与跨课结果分别验证，评价研究说明用途和归因限制；本次不新增个人指派。

### 战略聚焦与长期主义

- **基本法原文依据**：第四条《长期主义与战略聚焦》：“资源要投向客户价值最大、长期回报最高、最能形成系统资产的主航道。”并要求清楚选择不做什么。
- **本场证据**：第 5、6 议题反思低效线索；第 10 议题先补 Center 治理；第 14、16、17 议题将较快的价格测算、入口建设，与逐课机制试验和明年规模化作用分开；第 18 议题保留区域推进顺序。
- **判断**：出现了真实聚焦方向，尚未完成资源选择。以 lesson 为共同参照，可进一步检验渠道、Center、薪资和支持投入怎样改变可兑现课堂及其持续质量，而不是分别用线索、站点和功能数证明成功。风险仍是新旧工作全部并存、课堂结果没有改善，团队负担却继续增加。
- **要补的闭环**：在原定推进顺序内，比较各项投入形成的可用课位、实际课堂表现、老师持续参与和全成本；明确资源转移及承接证据。可用课位、完成课堂与好课分别计量，供需算法不能把它们混成同一个数；这是一项解读与验收建议，不新增或改变会上资源决定。

### 系统化交付与持续进化

- **基本法原文依据**：第五条《持续进化的系统、组织和个人》要求问题进入解决、标准化、系统化闭环；第六条《51Talk 操作系统》要求优秀经验进入“标准、产品、系统和 AI”。
- **本场证据**：第 7 议题提出真实课前演练；第 10 议题提出 Head Teacher；第 16、17 议题明确“任务发出不够，还要执行、再看下一课”，并把不合适的任务纳入修正；第 18 议题探讨将老 CC 的经验转成新人可用的选师流程。
- **判断**：lesson 为系统提供了共同的事实和反馈单位：各模块处理同一节课的不同问题，老师与学生沿各自的课次连接继续积累。真正的系统进步，应表现为后续课堂发生变化，以及有效支持能被更多老师复用；运行效果尚无法判断。演练、认证、已读和模型回算仍各自只是中间证据。
- **要补的闭环**：围绕可回查的课堂证据，连接判断、任务、支持、实际执行及后续课堂复检，同时更新对老师的认识和对支持方法的认识。让演练减少真实首课失败，让辅导改善后续课堂，让经验证的方法跨老师与站点复用；评价和激励变更仍需独立结果证据及纠错机制。以上为后续验收建议，不冒充本场已签收契约。
