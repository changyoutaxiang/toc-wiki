## 核心结论（拍定项）

1. **招聘准入标准从 3200 → 3500，拍定。** 3500 锚定 I3-8 代最低设备分（3529）。代价：存量约 10 个点风险、招聘端约 5–6 个点压力，**咬牙扛**。5200 不提（损失约 16 个点，"砍腰子"，太狠）。
2. **上线时间点拍定：下周三（双周会移到周三）现场拍、周四上线。** 物理动作 = "在尺子上改刻度"（只改字典 + 数据），不依赖 AC 改造，两个工作日内完成。需同步招聘端漏斗（调回来会有 5–6 点变化，让招聘端处理例子）。
3. **"3388 vs 5588" 翻译成战场语言：3388 = 素颜上课，5588 = 能化妆（开美颜 + many cam）上课。** 二者差异精确落在 **many cam**（及美颜）这一档；many cam 出场率"高"但**无数据，坚持说"不知道"**。
4. **存量分阶段"小手术"淘汰，不一刀切**：先切总人口约 3%、稳住、再切 2–3 点；2500 以下极低档（国内 254 人）拉名单 → 匹配投诉 + 人工抽查，别误伤固定学生的老师。李阳出报表。
5. **12% 上不了 Cocos 的老师 → 摘 H5 标签、打成人标签**（成人对设备要求低、能上 PDF）；但摘标签是**产研动作**，运营出标准（if-then 策略）。
6. **本卡第 6 格（数据链路）/ 第 7 格（上线锁定）由本会推进**——尺子已钉死（锚定黄金 + 三套打分源优先级 + 锁版本），上线时间与物理动作已定。详见末尾「对 [[设备准入标准卡]] 的推进」。

## 一、测试矩阵：一台机器、两套标准（据 CSV 实测）

李阳投屏，拿真实机器在两套基准上跑 Cocos（教材 20 帧）+ 常用功能，测 **CPU 维持使用率**：

**标准一：CPU 评分 ≥ 3500**（3500 = I3-8 代系列最低分；实测机 i3-8130U = 3529 分）

| 功能组合 | CPU 维持使用率 |
|---|---|
| AC + Chrome（≤3 个页签，下同） | 43~50% |
| AC + Chrome + 贴图 | 46~50% |
| AC + Chrome + 贴图 + AI 降噪 | 48~52% |

> 低端设备：AC 新版本**不开放** 美颜、Krisp、ManyCam、虚拟背景。

**标准二：CPU 评分 ≥ 5200**（5200 = I5-8 代系列最低分；实测机 i5-8265U = 5789 分）

| 功能组合 | CPU 维持使用率 |
|---|---|
| AC + Chrome | 29~42% |
| AC + Chrome + 贴图 | 33~44% |
| AC + Chrome + 贴图 + AI 降噪 | 40~46% |
| ＋美颜 | 44~64% |
| ＋Krisp | 50~70% |
| ＋ManyCam | 47~70%（⚠️ ManyCam 使用率仍缺数据） |
| ＋美颜 + Krisp | 60~75% |
| ＋美颜 + ManyCam | 60~70% |
| ＋美颜 + 虚拟背景 | 80~90% |

> **CSV 备注（关键规则）**：① 美颜、Krisp、ManyCam **任意两个不建议同时使用**；② **虚拟背景在 I5-8 代设备上不建议使用**。

**读图要点**：
- **现行判定 3200 → 本次测 3500**（基于 I3-8 代最低设备分；手上正好有这台机器）。3500 档 Cocos 可用但严格：只能 AC + Chrome（≤3 tab）+ 贴图 + AI 降噪，CPU 已到约 48~52%。
- 浏览器口径：会上 Leon 让加定语"最多 3 个、一般理解水平也能看懂"；并提出**未来把常用功能放进 AC 内置浏览器**（下季度规划，姜老师方向），减少另开 Chrome 的内存占用——**当前测试仍用 Chrome**，AC 内置浏览器是规划态，勿混淆。
- I3 设备**帧率锁死 20 帧**（I5 可提到 25/30）；I3 不能开虚拟背景（一开约 +20%）、不能美颜。

**功能关系澄清**：
- **Krisp（口音转换）与 AI 降噪是替代关系**——开了 Krisp，AI 降噪自动失效，不用同开。
- **虚拟背景**：抠图效果差（对比度弱抠不出轮廓）、且吃资源（+美颜后直冲 80~90%）；必须优化到 10% 以内才放开。**推广口径：不要用虚拟背景。**
- **辅助功能管控（新 AC）**：S3 禁美颜等；S5/8 代可美颜 / Krisp / ManyCam（但任意两个不同开）；虚拟背景需 **>1 万分**（后端可配）才放开，等虚拟背景优化到 I5-8 可用再放。AC 浏览器内核（V8）5.0 升级，H5 打开性能会提升。

## 二、把"3388 vs 5588"逼成精确语言（Leon 主导）

Leon 反复逼问产研："Cocos 跑在 3388 和 5588 上，对老师/学生最大区别到底是一二三哪几点？" 收口结论：

- **3388 = 素颜上课**：只能开"低保/小资两件套"（AC + Chrome），加上贴图 + 降噪也到头；I3 开一个贴图占用就到 10%。
- **5588 = 化妆上课**：除裸奔外还能开 **many cam**（"中产五件套"），整体更流畅、同等功能下对资源占用更少。
- **核心差异 = many cam**（贴图更丰富 + 美颜把老师"整亮一点"；也能挂机/遮挡摄像头等负向操作）。**many cam 是第三方软件**，收益"有了会好一截、但不是必备"，**出场率无数据**。
- tab 数差异可被 control（让老师不开），不算关键差异。

## 三、数据现状（李阳 / 王韬）

- **口径**：取每个老师"最后一节课用的设备"，样本从 5/1 起有上课的老师；在职约 **1.9 万**（总量约 2.1 万，全量近似）。
- **锚定黄金已锁版本**：3200 / 3500 / 5200 各锁定一个评分版本（I3 最低值 / I5 最低值），是**客观、不随第三方评分漂移**的黄金标准。评分源优先级：**A 站 > B 站 > 自研**（virtual CPU 库里查不到时用自研，有换算关系）。
- **关键比例**：
  - **不能上 Cocos = 12%（2296 人）** = 低于 3200（约 1500 多：国内 700 多 + 海外 700 多，等效跑不动 Cocos）+ 低于现招聘标准两档之和。
  - **3500–5200 ≈ 7%**（勉强，不能开其他）；**约 80% 躺赢**（达标）。
  - **招聘设备检测通过率 ≈ 75%**。
  - 招聘口径（5 月全月检测通过 5400 人）：<3200 有 300 多、<3500 有 500 多、<5200 有 900 多。
- **CPU / 内存 / 网络标准**：CPU 占用阈值（提到 50 / 60 / 75 多个口径，当前定 ~75% 不过）；内存 75%；ping（网络延迟）相关。**注意检测的是"当前裸机占用率"而非上课场景**，裸机已 75% 的设备需调低标准。

## 四、配套机制与产研侧

- **设备好不加分**：招聘里现为"减分"机制，过线即可；设备更好（一万 vs 两万的苹果）对产出无差异，不额外加分。
- **设备识别集成 AC**（客户培训系统）：判断老师设备型号是否与招聘时一致，不一致则首次登录 AC 重新注册设备；设备检测直接放进 AC，不单独发包。**需 7 月中之前做完**（8 月稳定，9 月最缺人）。
- **AC 加速球**（类似 360）：10 秒调一次系统 API 取 CPU 占用，可清内存碎片 / DNS、列 top 进程让老师勾选关闭。现仅在课中，已给季业提需求扩到课前（招聘时也可用）。
- **命名安全（重要）**：**口音转换（crisp）不要用中文名**——老师可能截图当把柄。改叫"语音优化" / 英文 / 直接 crisp，"音频优化"四字千万不能出现在任何可见处。**这是黑科技，不可暴露**。
- **隐私合规**：加速球读取本机进程/CPU，在境外敏感，需在 **AC 用户协议 / 合同**里加一句（找不起眼处加），登录时声明。

## 五、Mac 老师问题（悬而未决）

- Mac/MacBook 与自研 AC 适配性差（摄像头打开等问题，AC 自身没开发好）；**现在 Mac 不检测、直接放进来**（没法检测）。
- 装 Windows 系统的 Mac 当 Windows 电脑用、过检测。
- **要不要投入开 Mac 版 AC：今天没资源、讨论无意义**。先要数据：Mac 老师占比——若约 10% 马上开会，若约 1% 先不开（且低分 Mac 老师第一节课就会被淘汰，存活不下来）。

## 可沉淀判断

- **把技术语言翻译成战场语言**：Leon 全程把李阳的技术口径（CPU 占用、tab 数、功能开关）逼成老师教学视角的精确语言——"素颜 vs 化妆""低保/小资两件套 vs 中产五件套"。这是一号位做标准时的关键工艺：标准必须"一般理解水平也能看懂"。
- **"但凡不知道就说不知道，别说'挺多'"**：many cam 出场率被说"挺多"，Leon 坚持改成"不知道"——拒绝用模糊经验词替代数据，先用经验决策但要标明是经验不是数据。
- **"以后这种 debate，用事实解决，不要 debate"**：把主观争论收敛到数据/事实。呼应已沉淀的「系统判断优于人判断」原则——动态分（系统实时判定）优于静态人判定。
- **分级处理 / 小手术迭代 vs 一刀切**：存量淘汰先切 3%、稳住、再切 2–3 点；先处理"最恶心"的尾部。
- **命名规避敏感功能**：黑科技类功能（口音转换）名称不可出现在老师可见处，防截图把柄。
- **标准化的元价值**："吵了好几年的事终于拍定 …… 我们干了一件标准化的事情，最重要的标准化之一。" 印证四化里标准化是地基。
- **四化逼问（Leon 自述）**："我作为四化的人"——在座没人能说全什么是贴图/降噪/美颜/Krisp/ManyCam；若 AI 有 AC 产品文档访问权，这些定义本应在某文档里可查（ManyCam 除外，第三方、官网可查）。这是知识沉淀/数据化的逼问点：定义散落在脑子里 = 治理债。**佐证**：本会附带的 [[journal/2026/06/2026-06-05/media/AC教室改版说明.md]] 正是这类产品文档——贴图（动态贴纸）、虚拟背景、H5/PDF 教室区别等都有定义，恰好印证"定义存在但未被治理成单一可查事实源"；ManyCam 不在其中（第三方），与 Leon 判断一致。建议把功能术语表沉淀进 wiki 作单一事实源。
- **ManyCam 数据缺口已被实测确认**：CSV 在 ManyCam 行明确标注"使用情况？数据"——产品侧也拿不到 ManyCam 出场率，呼应"但凡不知道就说不知道"。这是设备准入卡数据链路待补的一个具体缺口。
