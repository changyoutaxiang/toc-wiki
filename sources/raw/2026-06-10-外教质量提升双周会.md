## 核心结论

1. **战役半仗判断：好老师"失血止住"已基本完成，创可贴贴上了。** 经薪酬改革 + 师生匹配产品化 + 推荐系统迭代，A&B+ 老师离职从月 700~800 降到 300 多、留存数据转好。**结论：好老师"留得住"这半仗接近交卷；下半场重心切到"招 + 培"**——从市场抢好老师 + 自己批量造好老师（"新东方逻辑"）。但 CEO都明确：用户侧尚无明显感知、A&B+ 招聘占比仍只有 10%，"成规模增加好老师占比其实我们还没见效"。

2. **竞品 Polly 7/1 新薪酬制 → 不照抄、用"季度跳级电梯机制"差异化应对（升级了 06-09 的 fast track）。** Polly 把最高档从 300 降到 125（与我方 120 拉近）、改"快升快降 + 木桶最短板考核"，对新人极具诱惑、但伤存量好老师（一次地震/掉课即跌到底）。决策方向：**不学其"快降伤人"，只学其"快升的即时反馈"**——在我方升级体系上加一个**跳级/电梯机制**（三级制、每季度一次正式评估、升级可跨档跳、降级一级一级缓降），"对好老师友好"。激励要**产品化**：别堆复杂激励，让系统全算明白、老师简明看懂。

3. **师生匹配 / 体验课直约：CC 选老师 vs 算法直派的 debate，收敛为"派的本质、选的体验"。** 国内体验课直约功能 6/15 上线、本周五培训销售。Leon 质疑"让 CC 从 50 个老师里挑"=效率低、是销售自我感觉良好，主张算法直派；邵涵主张让 CC 在体验课前能"看到老师长什么样"有价值。**共识收敛**：给 3 个选项（"给三个就是派、三选一"——本质是派、体验是选），**杜绝依赖 CC 个人品味**、要把"CC 的品味蒸馏进系统"；并设"出来后大家都骂才放心"的倒逼机制（产品好坏看 CC 是否总翻到第 2/3 页）。

4. **新老师推荐利用率大涨 → CEO 要求引入"观察期"防体验反噬。** 优先推荐优秀新老师后，新老师利用率从~70% 提到海外 94%/国内 77%。CEO点出这是"战役至今最好的、用数据证明系统在进步"的产品级解法，但**必须加用户视角**：利用率涨不等于用户满意度涨。要求产品/系统引入**"观察期"（≈2 周）**——过了观察期才放量推荐，先筛掉缺席率高等问题老师，"不能只靠几个老司机脑子里过滤"。

5. **四化正式从"数据治理"开刀，Leon 被明确为外教战役数据治理/四化指挥官。** 公司认知近一周突破很快（"日心说" + L3 业务负责人主责 + "卡"为四化最小单位）。CEO 拍板：**外教战役做全公司数据治理试点，1-2 个月把 L3（数据资产层）治理完**，由 **王东带国内+海外两边核心团队亲自写数据集**（不依赖数据组"0.3 个人"）；报表层交给 Leon 用 Codex 做，把数据组的人解放出来专心做数据集。Leon 明天起闭关2个半天，和数据同事坐一起亲自写数据集。

6. **方向性大判断：以 agent 为中心重构外教系统，外教是"全自动化运营"最佳战场。** 数据治理是第一步（给 agent 读、不是给人读），治完后"BI 都不需要了"。下一步把招聘/培训/质检/匹配/运营做成**以智能体为中心的自净化系统（FSD 化）**：几十个 agent 各管一个老师任务（感知质检→推送培训→检查执行→正/负反馈），把老师质量"系统性变好"。外教场景"现在没人干、不取代任何人、响应快、可快速迭代"= 最适合先跑通的战场。

7. **执行哲学（CEO 反复强调，单列）**："**5 个高管 + Codex 干 1 个月出第一版 = AI native；50 个人干半年 = 用旧方式干、一定不对**。" 这套数据治理/系统底座要 CEO/核心高管**亲自下场**（"就像创业启动期，前 10 个员工 CEO 亲自招"），先打地基（"关于系统的系统"），地基打牢后各战役"区域自治"长各自的楼。

8. **品牌资产唤醒（CEO）：被遗忘的品牌弹药要捞出来。** 借 John Lucas 老师（中非相知奖得主，与马科斯总统之母同届获奖、菲外交部网站至今挂着）案例，CEO 强调"外教的包装和外教的真实质量一样重要"，要求建一个"品牌 agent"扫描所有沉睡品牌资产、给老师角色（首席培训师/品牌大使）、用故事承载"为什么我们的菲教是最好的外教"。

## 三、竞品 Polly 新薪酬制 & 应对（升级 06-09 三策）

> 慧茹（Catherine）主讲，底稿 = [[projects/外教战役/_reference/2026-06-05_51Talk-vs-Polly_师资薪酬完整分析报告.md]]。接 06-09 周会"Polly 反击三策"。

**机制判断**：
- Polly 新制**不是升降级培养体系，是"快升快降"**：嵌入质量指标但仍用老逻辑，每月结算/评价；最高档从 **300 降到 125**（我方最高 120，**差距缩小=对我方利好**）；用**木桶最短板**考老师、容错极低，"有点问题咵嚓掉到底"。
- **对谁有吸引力**：对"开课多、行为好"的新老师＝强激励（"毕业升入职半年升总监"）；对存量稳定型老师＝确定性低（一场地震/掉课即降级）。CEO指出："菲律宾老师要的是 **instant feedback**（借钱开 party、没有下个月），我们的反馈链太长——他们这点洞察是对的。"
- **战场判断**：Polly 从"高地打我们（高薪）"变成**进入同一战场同台竞争**（风格之争：他们激进、我们人性化）——**是机会不是威胁**。Polly 新政更像"被供应压力逼出的反应"（标准从 2 年降到 1 年、新 leader 把 51Talk 政策搬过去、稀释自身优势）。

**应对决策（关键升级）**：
- **不照抄"快降伤人"，只学"快升即时反馈"**。Leon："好老师为什么不让他尽快上去？Polly 不考虑人、只信系统逻辑；我们发挥人性光辉——下来时缓一点。"
- **在我方升级体系上加跳级/电梯机制**（取代单纯 fast track）：**三级制、每季度一次正式评估**（不按月、月太短视）、升级可跨档跳（这月一级、下月可到六级=爽）、**降级一级一级缓降（自动化）**。先做一次测试、不承诺每季都有。CEO/Leon：风险只是一点沉没成本、对 CPL 影响"低于 0.5"、"大概率问题不大"。
- **激励产品化**：别像过去把激励散在课时费外/搞复杂传导链，"让系统全部算明白、老师简明看懂"；前端入职看不到达成才触发的激励。落点对应 06-09 策一"整体收入包 + 收入计算器"。
- **TPT level program 进度**（慧茹）：4 个试点选定、物料/职责清单已下发，6/8 内测宣发、6/9 QA manager 培训各 center quality head，6 月底汇报培训效果（51 小时培训物料，由 CE 检测）。国内数据取不到、待王韬找邵老师解决后全量推。

**未讨论的问题**："其实我不需要那么多老师，要的是 300 个里 200 个 A&B+"——是否要**重新算账：不要那么多老师、只要足够多的 A&B+**？

## 四、师生匹配 / 体验课直约（CC 选老师 vs 算法直派）

**功能现状**（产研 demo）：国内给销售增加"体验课直约"入口，接入新约课系统，**6/15 上线、本周五培训销售**；与推荐外教系统打通（CC 进学员详情页→直约入口→约课系统选时段，老师=推荐引擎推的、打了 FT/FTEX/FTHT 等标签、后面可固定）。做 A/B 测试：小红书+转介绍两渠道按手机号 50/50 分有/无入口。

**核心 debate（Jack/Leon vs 邵涵）**：
- **Jack/Leon 质疑**：让 CC 从 **50 个**老师里挑＝效率太低、是"销售自我感觉良好"、不符合"要人效"的逻辑；"我会给 5 个不给 50 个"；"Polly 接这么多 leads 不可能真让销售挑 10 个，大概率也是给 3 个、让你感觉自己挑"。本质主张＝**算法直派**（"产品完全来推"），不相信 CC 个人品味。
- **邵涵**：CC 在体验课前"能看到老师长什么样"（看自我介绍/教学视频、可一键分享给学员）有价值；CC 挖透高潜 leads 后有"手感"知道要什么老师；Poly/伴鱼/Kid 这类比我们产品化更好的公司，**临门一脚体验课仍由销售选**。
- **收敛**："如果对产品足够有信心，**选老师是情绪价值、干不过算法**"；"给 3 个就是派，三选一——本质是派、体验是选"。
- **共识落点**：
  1. **给 3 个选项**收口（本质派、体验选）；面向**高潜用户/好渠道**做（Poly 也只在优质渠道才让销售选）。
  2. **杜绝依赖 CC 个人品味**，要**把 CC 的品味"蒸馏"进系统**（产品要做的事）。
  3. **倒逼机制**：产品出来"大家都骂才放心"；若 CC 总翻到第 2/3 页选＝推荐引擎有问题、得改。Leon："下次开会**先看数据再看产品**，千万别信销售个人品味。"
  4. 价值闭环：给学员"确定性"（"教 Lucas 老师在等你"提升体验）+ 后面可固定→**有可能提转化率**，待 A/B 数据验证。
- **未决/技术债**：体验课时段与付费课时段是**两个池子、底层没打通**（打通周期长）。现做法是体验课约的是老师"付费时段"，可能被别的学员抢走、或产生空转率。**这是个很强的合理需求，留作未来。** 核心问题还是"招新老师质量上不去"，这个功能只在小量优质渠道放、A/B 看 CC 选 vs 系统派差别多大。

## 五、新老师推荐利用率 & "观察期"提议

- **数据**：6/1 上线"优先推荐优秀新老师"排序后，新老师利用率从~70% 提到**海外 94% / 国内 77%**，每天还在涨。
- **Jack 判断**：
  1. **这是战役至今最好的、用数据证明系统在进步的产品级解法**——"不磨人、不需要执行，是产品解决方案"。可反馈前端："只要你是好老师、过了某时间，开 10 节我保证约 9 节。"
  2. **必须加用户视角**：利用率涨 ≠ 用户满意度涨。"我们战役的终极指标是提升用户满意度，各项数据都变好、用户侧没反应＝白打"。要继续盯 **rebook 率 / 收藏 / 赴约 / 好评 / 解绑**（看板后天出）。
- **Jack建议：引入"观察期"（≈2 周）**——现状是"想推谁就能推"、靠几个老司机脑子里人肉过滤（缺席高/差评高），"经不起打开"。要做成**系统化的观察期**：过了观察期才放量推荐，可能筛掉一小半~一大半。这是"用户体验 vs 系统化的平衡"的好案例

**其余产品细节**：
- **替学员收藏功能**：业务要求公开"替学员收藏"入口（原被隐藏以保护学员自主收藏意愿）。共识：服务动作需保留，但**数据上要区分"用户自主收藏" vs "业务替收藏"**（排序/分类上前者靠前）；可在赴约时弹窗引导用户自己收藏缩短路径。中东收藏率低=业务不做、家长也不做。
- **固定时段开放规则境内外不一致**（境内绑定后 30 天、境外开课后 90 天可解绑）→ 产品化已支持分开配置，**运营思路差异让两边自己判断**，不在本会议决策。
- 新约课系统反馈：操作变简单、月固定课更方便、新采教学视频好用；**6/24 关老系统**；老详情页缺新约课入口的 bug 本周 CRM 修复。

## 七、四化建设 / 数据治理

### 7.1 Leon分享三个新认知（近一周突破）
1. **"卡"= 四化最小计量单位**：一个卡＝一份 MD 文档（含名字/ID/owner/所属战役/状态/来源/被哪些卡使用/定义/关键字段/数据源/可信度/谁消费）；**是 agent 的官方输入格式，给 agent 读、不是给人读**。例如：数据集卡 / 指标卡 / 标准卡 / 决策卡 / 流程卡。
2. **数据治理分五层，L3 是瓶颈**：上周六达成共识——**L3（数据资产层：口径/字段/owner/可复用）是业务负责人主责，不是数据组的事**（推翻"谁负责数据谁负责"的旧认知）。
3. **"日心说"（前天出炉，颠覆）**：我们建设的一切（卡/数据）**围绕 agent 为中心**，不是给人消费的、是给 agent 消费的，**人读 agent 消费后的产物**。

### 7.2 五层框架现场对齐（多方拉锯，最终由 Tammy 演示收敛）
> 过程中 L3/L4 定义反复拉锯，暴露"一屋子人说六种语言"的口径混乱。Tammy 现场开表演示后收敛：

| 层 | 名称 | 内容 | 归属 |
|---|------|------|------|
| **L1** | 数据同步层 | 任何操作留下的原始日志/数据表（CIM 等系统落表，散、谁都不知道是啥） | 技术侧 |
| **L2** | 数据源/数仓层 | 从海量数据中提取、清洗、变成数仓（暂无业务定义，灰色） | 技术侧（超人/数仓） |
| **L3** | **数据资产层（瓶颈）** | 定义字段/口径/owner/可复用逻辑；**业务+产品共同定义**（聚合成"宽表/明细表"） | **业务一号位主责** |
| **L4** | 数据服务层 | 跨表聚合、BI 看板/仪表盘（教师×学生×课程聚合） | 产品+运营 |
| **L5** | 业务使用层 | 运营最终用的现成产品/可视化 | 运营 |

- **生产次序**：流程 → 指标 → 数据集。先梳理业务流程→标准化→明确要看哪些指标→基于指标反推标准化数据集。"指标在数据集之上、流程在指标之上"（Jack纠正 Leon 初版的颠倒）。
- **现状自报家丑**：上周会 1/3 数据还在 Excel 上吵；"老司机们直接从 L5 穿到 L2"（跳过 L3 资产沉淀）＝**没有数据资产沉淀的根因**；过去 L5 直接调 L2，数据不可靠不准确。

### 7.3 "保安三问"
对任何口径/理论发起三问，**扛不住＝没标准化**：① 你说的是啥？② 这东西文档上能找到吗？③ 这文档 AI 能读懂吗？
> Leon 现场用三问"逮"了多人（曲老师的 L1-L5 解读"在哪个文档能找到？→ 没有，是老司机的理解"）——证明仍在人脑、未落文档。

### 7.4 CEO 核心治理决策
- **试点**：拿外教战役做**全公司数据治理标杆**，**1-2 个月把 L3 治理完**（agent 能直接读梳理好的数据集、出结论、不需要 BI）。
- **外教战役的四化建设和数据治理指挥官 = 王东（Leon）**：带国内+ 海外两边核心团队**亲自写数据集**，不外包给数据组"0.3 个人"——"全公司巨大瓶颈是数据集瓶颈，不能千军万马过独木桥等一个人排期，绝不是 AI 时代做法"。
- **分工解耦**：能写数据集的人专心写数据集，**报表层交给业务 用Codex 做**
- **方法**：老司机 + AI 写 90~95% 半成品 → 数据 owner（亮亮等）审核入库；亮亮（年轻人、懂业务=能写数据集的关键，不是技术强）证明业务人 + AI 就能写。CEO："**王东不可能比亮亮差，跟亮亮 PK 一下**。"
- **Leon 承诺**：明天起推掉所有会、和战役数据同事坐 2 天亲自入门写数据集
- **次序铁律**：四化**从数据治理开刀**；数据没治理好，AI 化是空中楼阁——"数据是给 AI 看的，AI 能看懂了 BI 都不需要了"。

## 八、以 agent 为中心重构外教系统（FSD 化构想）

- **系统收敛判断**：招聘（增量）+ 培训 + 质检 + 运营（存量）中，**培训/质检/运营是一条路子、拆不开**（都跟教师行为和成长路径相关），应"从教师维度写一条完整路径、做成一套系统"；招聘是增量、相对独立。
- **以智能体为中心（必须，不是可选）**：数据治理产出大量数据后，**以 agent 为中心构建整个逻辑**。举例：培训场景几十个 agent，每个 agent 管一个任务（质检 agent 感知发音问题→推送纠正物料→检查是否执行→正/负反馈），形成**让老师质量"自净化"的系统**（FSD 逻辑）。
- **为什么外教是最佳战场**：现在**没人在干**（不取代任何人）、老师响应度高、能快速迭代拿反馈——"最快能看到成效的战场"。
- **基础架构设想**：FSD 系统对**外教端和学生端共用一套基础架构**（与老蔡讨论的方向）；公司级做底座，各战役在底座上配置/训练自己的系统（"区域自治"）。Leon 收口比喻："我们花一个月把**地基的地基**搞出来——它是'一个关于系统的系统'，地基打牢后各战役长各自的楼。"
- **三系统收敛草图（Leon）**：把外教大件浓缩成 **① 增量系统（灌水/招聘，看算法牛不牛）② 学生体验连接系统（算法×学生体验）③ 存量经营系统（质检+运营+培训，看捞金能力）**，培训是基建、服务于质检与运营。

### 执行哲学（CEO本场最强的方法论）
> **"5 个高管 + Codex 干 1 个月出第一版 = AI native；用 50 个人干半年 = 用过去的方式干、一定不对。"**
> 这套底座要核心高管**亲自下场**（"前 10 个员工 CEO 亲自招，你包给 HRBP？开玩笑"）；先打地基、不做完整设计（"大楼长啥样想象不出来，只能先把地基打好"）；小步快跑。CEO 自承"超出认知、很颠覆，这事很不靠谱、完全基于我对 AI 的理解，但不是完全不可能"。

## 可沉淀判断

- **"失血止住"≠"开始增长"**：战役半年的成绩是把好老师"留住"（止血），但 A&B+ 招聘占比仍 10%、用户无感知——把"止血"和"造血"显式分开，避免把止血成绩当胜利。下半场命题清晰切到"招 + 培"。
- **竞品快升快降的正确学法 = 学"即时反馈"、不学"快降伤人"**：菲律宾 home base 老师要 instant feedback（"借钱开 party、没有下个月"）是真洞察；用"季度跳级电梯 + 缓降"把即时正反馈给到好老师，用"人性化"对冲 Polly 的"系统冷酷"，把竞争从高低之争转成风格之争。
- **"派的本质、选的体验"**：把"算法直派 vs 销售选"的伪二选一，收敛为"给 3 个=本质是派、体验是选"；并立"把 CC 品味蒸馏进系统、不信个人品味"的产品原则 + "出来被骂才放心"的倒逼机制。
- **数据治理次序：流程→指标→数据集**（demand-driven，与 sihua-gov 第 11 宪法反射同源）；L3 是业务一号位主责、不可外包给数据组——这是本场把"业务一号位=首席数据治理官"落到外教战役的具体执行。
- **AI-native 的判据是"人数×周期"**：CEO 把"5 人 1 个月 vs 50 人半年"当作判断是否 AI-native 的倒逼尺子——不是看做了什么，是看用几个人、多快做出来。
- **以 agent 为中心 + 外教是最佳试验场**：外教运营"现在没人干、不取代人、响应快、可迭代"，是走向"完全以智能体为中心运营"最快见效的战场；底座（"关于系统的系统"）公司级做、战役区域自治。
