# 原子小队：两周的实践与一点点思考

2026 年 8 月 14 日，外教侧同时成立两支原子小队。两周里它们跑得比我们预期快，也撞到了比预期更硬的东西。这份材料不汇报业务进展，只回答一个问题：**这种工作方式，在真实战场上到底发生了什么。**

今天**不讲**业务进展数字 · 只讲**工作方式**：我们撞到了什么、怎么修的、哪些还没答案

### 几个词，先说清楚

原子小队围绕**一个真实客户任务**临时组队，不是按部门组队

DRI唯一直接责任人（Directly Responsible Individual）。可以一起讨论，但**只有他拍板**

两张收据结项要交两份：**客户结果收据** + **可复用资产收据**

小范围试跑先小范围试，用证据决定是否扩大（内部常叫「灰度」）

红线层独立于授权级别、**永远要人把关**的事项（客户承诺 / 老师收入或处罚 / 隐私合规 / 不可逆生产变更）

四象限上线前按「影响大小 × 后果轻重」决定授权方式，见 [§5](#s5)

评审节点过了才进入下一阶段，不靠感觉续期（内部常叫 Gate）

八要素公司原子小队立项模板：客户任务 / DRI / 成员投入 / 判定标准 / 授权 / 周期 / 接口红线 / 退出


## 230 秒认识这两支小队

一支小队 = 一个真实客户任务 + 一个唯一 DRI + 一组要调用或补建的能力 + 两张收据。**不按部门组队，也不按功能清单组队。**

| 维度 | 坏课治理原子小队 | 外教触达原子小队 |
| --- | --- | --- |
| **唯一 DRI** | 曹海璇 | 吴洪熙（技术侧）；业务侧袁慧茹 / 翟雨佳 |
| **客户任务** | 课中老师无通知缺席时，让学生在承诺窗口内拿到完整交付或真实保护 | 建一条可靠的推送通道，把关键信息准时送到老师上课用的电脑软件（AC）里 |
| **首期边界** | 只做「课中无通知缺席」*一种*事件。网络 / 设备 / 迟到早退 / 口音 / 长期评价，一律二期再说 | 只做*两个*验证场景（课前 2 小时新预约提醒、代课强提醒）验证同一条通道 |
| **起跑日** | 2026-08-14 | 2026-08-14 |
| **当前状态** | 一期流程基本跑通 进入收尾 + 数据观测；二期（设备网络）已启动 | 通道可用 统一消息通道已上线；9/1 随新版 AC 发布；菲律宾侧验收中 |
| **两张收据** | ① 客户保护覆盖与恢复时效改善且护栏不恶化；② 事件—核验—救援—恢复—申诉的可重放证据包 | ① 两个场景分别按冻结口径闭环；② 通道、模板、唯一任务编号、小范围试跑与退回的标准做法 可由非作者复用 |

### 为什么必须是「唯一」负责人

团队可以一起讨论，但四件事只能由 DRI 形成明确结论并记录：首期范围与事件定义；哪一项保护动作进入下一阶段；资源不到位时的升级；评审节点与最终关闭建议。**DRI 不是催进度的人，是让「客户结果、事实证据、动作边界、复盘」成为同一条闭环的人。**

**唯一负责人有一个边界条件：**当动作的后果落在另一方身上——比如另一个国家的老师——那一方必须在规则定义阶段进场。这一条我们第一周没有做到，现在是一个开放问题（见 [§8 问题一](#s8)）。

这两支小队的立项备案，是我用 AI 读群上下文先填出初稿、再交给 DRI 修订敲定的。8/14 发出去的时候我原话是「AI 写的，队长你修订吧」。**把「繁文缛节」的成本从一线身上拿掉，是管理者该干的第一件活。**

## 4撞到的三个真问题

这两周真正沉淀下来的是这三个问题。

### 问题一　生产力已被证明，生产关系没有跟上

#### 我的感受：轻微失控

坏课治理小队一周内就把一期做完上线了。**中间没有汇报，没有审批。**我是极其激进主张这套工作方式的人，授权也是我给的——但那一周我的诚实感受是「轻微失控」。*态度和理念激进，身体感受诚实。*这说明问题不在态度。

#### 区域负责人的感受：被排除在外

有被缺席治理规则命中的老师，直接去 Facebook 质问菲律宾运营主帅 Jen。**她不是没搞懂，是被排除在规则定义之外。**她的原话：「我们没有把『成立了原子小队』沟通清楚；方案在周五下午上线，事先没有咨询。」教学中心负责人也开始反弹：连续缺席就直接取消排课，有老师只是迟到几分钟也被停了。**这条反馈已收进 [§8 问题一](#s8)。**

**诊断要拆成两半。**一半是**真实的流程缺陷**：规则定义时受影响方不在场、上线时点不当——这个必须修（见 [§8 问题一](#s8)）；另一半才是转型摩擦：原子小队冲击层层上报的管理方式，改革过渡期躲不开。管理者在转型中**同时扮演推动者和阻碍者**——后者大多是无意识的：「哎，某某某，来我办公室，跟我说说你们目前进展」，这是习惯动作，意识不到就做了；还有忍不住「指点江山」，自己掌握的情况不够，说话的分量又太重，团队听也不是、不听也不是。

#### 换的不是态度，是控制方式

旧：靠路径控制获得确定性

领导知道每一个动作  
领导逐项给意见  
团队逐层汇报  
→ 确定性来自「我看见了你做的每一步」

新：靠系统控制获得确定性

**任务边界清楚**  
**关键事实透明**  
**风险自动升级**  
**结果可读回**  
**异常可以退回**  
→ 确定性来自「系统健康、越界报警、我能读回」

**答案不是让管理者继续闭嘴，也不是「因为不安就把审批权收回来」，而是替换控制方式本身。**领导者不再控制路径，但仍要能看见系统是否健康、哪里越界、何时必须介入。

### 问题二　「你大胆去做」这五个字，撑不起授权

坏课治理小队立项时其实早就写清楚了红线：**「停排课这类动作必须老板点头」「涉及老师饭碗的事必须人来把关」**。原则没问题。但真到上线那天，「连续缺席就取消排课」这个重动作，还是被当成普通功能一次全上。

这说明我们缺的不是原则，是**把原则变成上线纪律的工具**。授权停留在口号上，一线就只能靠猜——猜错了要么越界，要么不敢动。

### 问题三　零容忍 ≠ 一刀切

对「无通知缺席造成的客户伤害」零容忍，是对的——这是学生端最差的体验。但*零容忍不等于没有标准，恰恰相反：零容忍更需要一把清楚的尺子和一套补救办法*。没有尺子的零容忍，执行起来就变成一刀切，误伤好人，最后积累成一堆「委屈」。

这周我改了一个判断：真正该零容忍的，不是「老师犯了一次错」，而是这三件事——**风险长期无人识别、规则不可解释、申诉无人承接。**对事实不确定、首次异常、系统误判，应该是宽容的。


## 5我们修的三样东西

都不大，但都在出事的当天就开始用了。它们不是新原则，是把已有原则变成能当场用的工具。

### 资产一　广播制度：不汇报，但要边做边公开

**用广播代替汇报，用文档代替 PPT。**原子小队不汇报，不等于不沟通。五类事件必须广播：

| 广播类型 | 什么时候发 |
| --- | --- |
| 启动 | 小队成立 / 新任务开题 |
| 规则变 | 策略、口径、阈值发生变更 |
| 小范围试跑 | 开始试跑 / 调整范围 |
| 异常升级 | 踩线、误伤、外部反弹 |
| 阶段结案 | 评审通过 / 关闭 / 转制 |

**关键转变：**信息不是一层层从下往上汇报，而是**事情一发生，需要知道的人自动收到**。Jen 被突袭，一半是因为信息没到达，另一半是因为**规则定义时她不在场**。广播只解决前者——让「我不知道」不再发生；后者要靠下一节的四象限来接。**两样是一套，缺一不可。**

### 资产二　四象限上线纪律 + 红线层

把每个上线动作放进两个维度的交叉里判断：**影响多大**（一小批 → 所有人）× **后果多重**（能撤销 → 撤销不了 / 牵累他人）。四个象限，四种授权方式。**广播解决知情，这一节解决参与**——受影响方在哪个象限、有什么权利。两节合起来才是一套。

后果重 ↑后果轻 ↓

通知 + 可喊停

影响小 · 后果重

事先通知，受影响方可喊停。**喊停 ≠ 一票否决**：必须给出「现场真实情况 / 规则可能误伤谁」，且限时给结论，不能一直拖。

双审批

影响大 · 后果重

业务负责人与受影响方负责人事先都批。看三样：影响多大、怎么退回、观察多久。

完全授权

影响小 · 后果轻

DRI 自己定，记一笔就通知。**不增加任何审批**——这一格是保住速度的关键。

先小范围试 · 用证据推进

影响大 · 后果轻

充分授权，分步走；**证据就是授权**。切可承受的量、监控指标说清楚、证据出现立即调整。

影响小→影响大

⚠️ 上面四格之上，还有一层独立的红线层

- **客户承诺**　**老师收入或处罚**　**隐私合规**　**不可逆生产变更**
- 红线**不随象限降低**——「影响范围小」不能自动穿透红线。这是四象限最容易出错的地方。
- 「取消排课」落在**双审批**象限：从 8/25 起，连续缺席就取消排课，不能再当成普通功能一次全上。

#### 配套：每次上线填一张卡片（七问）

它**不增加审批**（完全授权象限不用批），但让每个动作都有记录可查、有人可找。**另有一条时点纪律：面向老师或客户的生产变更，不安排在周五或假日下午上线**——给受影响方留出准备窗口（这条来自一次真实反弹）。

| # | 要回答 | 说明 |
| --- | --- | --- |
| 1 | **改了什么** | 上线 / 停排 / 试跑了什么，一句话说清 |
| 2 | **落在哪个象限** | DRI 先标，AI 再核对；**拿不准就从高从严** |
| 3 | **影响谁、多少人** | 含「一线运营侧要不要跟着干」这一项 |
| 4 | **为什么这么干** | 基于什么数据、规则、标准 |
| 5 | **怎么退回来** | 怎么撤销 + 什么情况就该撤 |
| 6 | **谁负责 + 观察多久** | 看什么指标 + 什么情况立即停 |
| 7 | **跨边界语义确认** | 动作跨部门或跨区域时，受影响方负责人**书面确认四件事**：规则本身、运营后果、权限边界、退回条件——**不是回复「收到」** |

### 资产三　给「零容忍」配一把尺子和一套补救办法

| 要划清的 | 怎么划 |
| --- | --- |
| **缺席 vs 迟到** | 「没打招呼就缺席」和「迟到几分钟」是两码事。**迟到不能直接当成缺席来停排课。** |
| **连续几次才停** | 连续缺席几次才触发；一次缺席和连续缺席分开处理 |
| **停谁、停多久** | 对哪些市场、哪些课、哪一批老师生效；先试跑多大范围、观察多久 |
| **停到什么程度** | 停多久、什么条件能恢复——**不能一停到底、没有期限** |

**尺子必须配上补救办法：**申诉通道（人工复核后可改判）、恢复机制（误伤怎么补救、怎么恢复排课资格）、例外处理（设备故障、不可抗力、系统误判）、事后人工复核（必须能撤销、能退回、能申诉）。

**治理哲学的修正：确认制优于惩罚制。**8/26 有一个强证据——**所有点击确认出席的老师，100% 到场**。老师不说谎。让老师主动确认、说清后果，比事后处罚更有效。处罚只是治理链的一环，**预防、召回、代课、复测、申诉、恢复必须一起成立**，否则一刀切只会把客户伤害转化成老师伤害和管理救火。


## 6现场切片：四象限第一次被用来收口一场真分歧

8/26 Bad Class 会议，17:01–19:18。工具在这里第一次用在一场真分歧上。

#### 背景：数据定位出两大根因

- 开课前 **0–2 小时**的紧急约课，缺席风险显著偏高（占约 **10–14%** 课时）；
- **新老师 / 回归老师前 10 节课**高缺席（8 月新老师约**四分之一**已不活跃）。

#### 真分歧

「是否接受 2 小时内紧急约课」这个开关——**给老师自己选，还是系统硬控？**现场两派各有理由，不是谁对谁错，是风险偏好不同。

#### 怎么用四象限收口

| 判断 | 结论 |
| --- | --- |
| **影响** | 大——面向全量老师 |
| **后果** | 轻——可以退回、可以先小范围试 |
| **落格** | 先小范围试 · 用证据推进 → 「go but set control」：可以走，但要把控制项设好 |
| **拍板** | **当场授权 DRI 曹海璇**吸收全部反馈后自己拍板。我只做后盾，**没有上升给任何领导**。 |

离场只带**两句话约定**：  
**① 你的决策是什么**（切多大范围）；  
**② 什么证据出现，你会改变决策。**

这两句话是我们现在代替「汇报 + 审批」的东西。它把「领导同意了」替换成「决策说清楚了 + 翻盘条件说清楚了」——**后者比前者更难糊弄，也更可复核。**

同一场会还定了：两个方案**错开小范围测试**（开关先小范围试 / 新师前 10 课规则 9-1 上线），只为一个目的——**分得清效果来自哪个动作**。如果一起上，赢了也不知道赢在哪。

抽屉 B｜10 个会被问到的问题问到的次数最多

Q1　老师迟到 3 分钟，算"课中缺席"吗？

不算。判定点是开课后 **1 分钟**（触发召回）与 **4 分钟**（记缺席 + 代课）。迟到与缺席是两件事——这正是 §5「零容忍 ≠ 一刀切」里第一条要划清的。8/24 之前出现过"迟到几分钟也被停排课"的反弹，就是这条没划清的代价。

Q2　-27.7% 和 -23.7%，到底哪个是真的？

都是真的，是同一件事的两种算法。**率**降 27.7%（0.5034%→0.3640%）；**量**降 23.7%（2,560→1,954 节）。率的降幅更大，因为分母（课量）同期还在涨 5.5%。8/28 广播里写的是 -27.7%，指的是率。

Q3　分母涨了 5.5%，会不会是课量结构变了（比如多了容易守时的课）？

**我没拆，这是真缺口。**我只确认了两地合并总量 +5.5%，没有按市场 / 课型 / 时段做结构分解。如果要认真回答"是不是运气"，这层必须补。出数的人（技术侧牛琪）可以补。

Q4　"同日连续缺席"这个"连续"，到底怎么数？

同一老师、同一天内连续 ≥2 节课中缺席。图里有两个口径：**课量**（缺席涉及的课节数，8/1–20 基线日均约 155）与**老师量**（涉及的人数，基线日均约 63）。954→79 用的是课量口径。  
⚠️ 我把它标为「部分推断」：**群内没有成文定义**，是我从 DRI 与技术的对话和图字段反推的。这是我认为最该先补进字典的一条。

Q5　响应率 60%，剩下 40% 是什么人？

没表态的老师。两个细节：① 分母是「被触发的课」不是「老师人数」，同一老师可能被触发多次；② 分子同时包含"确认能到"和"确认不能到"。  
8/27 实例：触发 473，确认能到 268 + 不能到 20 = 288，288/473 = **60.9%**。  
另外一个反直觉的点：**8/26 起响应率从 21% 跳到 40%、再跳到 61%，触发点是菲律宾侧 Sharina 发了一条公告**——技术能力不变，一条运营公告让效果翻了三倍。

Q6　"课前请假"是不是就是把缺席换个名字、糊弄人？

数据上确实是这个流向：8/21–23 每天有 145 / 306 / 264 节课从「课中无通知」变成了「课前请假」。  
但两者对学员的伤害不同：**课中缺席 = 学员已经坐在教室里干等；课前请假 = 提前告假，学员可以改约。**同时 8/27 有 185 节无人课、143 节被代课覆盖（77%）。  
⚠️ **但我没有"课前请假后学员是否成功改约 / 补课"的数。**如果这一步没接住，那就是把伤害从"现场空等"换成了"课后流失"。**这是我要补的下一张收据，我不假装它已经有了。**

Q7　老师会不会怕被罚，先点"能到"然后不来？

973 节确认中，确认后仍缺席 **4 节（0.41%）**。这个数很小——**老师基本不说谎**。这也是我改变治理判断的依据。

Q8　两周的数据够吗？会不会只是因为被关注才变好（霍桑效应）？

**不够。**两周能证明"能跑起来"，不能证明"能持续"，也不能排除霍桑效应（被关注导致的短期改善）。**我没有排除它的设计。**这正是 9 月上旬要做**完整重放复盘**的原因（见 §9 检查点）——重放要还原的是"谁掌握什么事实、做了什么决定、哪个护栏本应生效"，而不是再看一遍数字。

Q9　这些数字谁算的？有没有第三方核过？

技术侧（牛琪）出数，DRI（曹海璇）核口径，我复核。**没有独立第三方复核。**  
8/24 那次口径不一致（老师量 vs 课量）是 DRI 自己发现、当天主动更正并重发的——**这说明自查机制在起作用，但不等于已复核**。

　　　· **数理论据**：8/27 当天 143 节被提前标记 ≈ 未上线前 8/1–20 日均 159 节连续缺席课量（落在基线内部）→ 被抓的**就是过去会缺席的那群**，**不是误抓**。完整论证见 [§7b-⑦](#s7b)。

抽屉 D｜另外三个常被问到的不在正文里

「原子小队」和「项目组」到底有什么区别？

三个硬区别：① **唯一 DRI**——可以一起讨论，只有一个人拍板；② **两张收据**——客户结果收据 + 可复用资产收据，缺一不结项；③ **退出条件**——写清什么情况下停止 / 缩小 / 转制，**不允许因为任务重要而无限续期**。多数"项目组"缺的恰恰是第三条。

这么放权，会不会把组织搞乱？汇报线怎么办？

**不改变原职能汇报线。**小队是任务组织不是编制；成员来自各自专业母体，结果验证后退回。真正会被打乱的不是汇报线，是**信息流**——所以我们的应对是加广播制度和四象限，**而不是加新的审批层**。这两者的区别，是这份材料想讲的核心。

出了事谁负责？

**DRI**（坏课治理：曹海璇；触达：吴洪熙）。但有一层例外：**涉及客户承诺、老师收入或处罚、隐私合规、不可逆生产变更的事项，永远保留人类 Gate**——小队和 Agent 都不能自动触发。这条写在立项里，也写进 §5 的红线层。


## 8四个我还没答案的问题

这四件事都还只是假设或开放问题，没有收据。问题一来自一份真实反馈，写给所有想复制这个模式的人。

问题一　我们还没有治理，就跑起来了——「参与权」是一个开放问题

**发生了什么：**第一周（8/14–21），小队在没有任何参与权规则的情况下，把面向老师的动作直接上线——包括 8/21（周五）下午的一批。承担后果的一方（菲律宾运营），不在决策现场。  
  
**它带来的真实问题：**区域负责人的正当抗议。她的原话：  
*「我们没有把『成立了原子小队』沟通清楚；方案在周五/假日下午上线，事先没有咨询。」*  
*「当后果落在 PH 团队身上时，PH 不能只是动作的接收方。」*  
  
**两种立场，都写在这里：**  
· **速度（我的）：**这个窗口里，先跑起来的收益为正；治理要追，但一定追不上。  
· **参与（她的）：**广播解决「我不知道」，不解决「定义规则时我不在场」；承担后果的一方必须在规则定义时进场，并在上线时确认语义——不是回复「收到」。  
两种都有道理。**我们不共识，也没有答案。**  
  
**没答上来的问题：**参与权怎么落地？三个候选都摆在桌上——① 受影响方在规则定义阶段进场 + 上线门槛权（不改唯一负责人）；② 跨边界任务设共同负责人；③ 按动作分类，影响老师权益的给区域实质否决权。  
  
**已决定的下一步：**把这场辩论开放给区域侧——规则草案交对方修订后再定稿。  
  
**给复制这个模式的人三个坑（我们摔过的）：**① **上线时点**——周五/假日下午，不要上面向老师或客户的变更；② **语义确认**——双语送达不等于语义一致，要对方确认规则、后果、权限、退回四件事；③ **定义期缺位**——「先通知」替代不了「先参与」，被通知的人会在最贵的时候（事故现场）才进场。

问题二　广播制度现在靠纪律维持，能撑多久？

目前广播靠 DRI 自觉。我不想让它长期只靠纪律。我们在设计一个「可订阅广播」的业务智能员工（内部叫 TOC 小王）：按订阅者的**真实责任**组合信息（战场 × 能力 × 价值 × 信号类型 × 新鲜度 × 权限），无变化则静默，并把「不成为新科层、不成为中央审核者、不成为影子经理」写进治理红线。  
**状态：设计草稿 v0.1，未上岗，未授权任何对外发送。**它是否成立，同样要拿收据验：关键信息到达是否更快、同步会与层层汇报成本是否下降。

问题三　「只存在原子小队的部门」，是把临时组队浪漫化了吗？

我提出过一个更激进的假设：客户体验部可以成为一个**只存在原子小队的部门**——它是客户体验结果的责任主体，但不必拥有固定团队实体；出现客户问题时从相关部门拉起小队，结果验证后成员退回专业母体。  
我要诚实标注：**这仍是组织假设，不是结论。**少了「唯一负责人、明确授权与数据边界、停止条件、结果收据」，它就只是把临时组队浪漫化。8/26 已组建第一支小队，本周交付第一版「学员像素级全景画像」——这是第一张收据的验证点。

问题四　「把数据整理成 AI 能读懂的样子」，是部门的事还是公司的事？

8/27 我把 AI 知识库、概念关系图、数据仓库三者连起来试了一遍，结论是：**数据基础建完可能只是一半——教会 AI 正确地用它，不是丢几份说明文档进去就行，要一遍遍校准。**测试过程几乎一步一问。  
但另一面收益巨大：我第一次不通过团队汇报，直接看到了老师缺席的详细时间分布、坏课按入职司龄的分布，**发现前 7 天新老师是重灾区**。这些数字以前要提需求、排期。  
我的判断：**这应该是公司级工程，不是部门级。**但这是我的判断，不是已验证的结论。


## 9想请高管考虑的三件事

不要求现在批。只请把它放进候选池——这只是 2 支小队、14 天的样本。

1

把「四象限 + 红线层」作为公司级原子小队上线纪律的候选模板

我们的样本很小，**不建议直接推广**。但如果第二批小队起步时能直接拿到这套东西，可以少吃几个烧饼。它已经用一场真分歧做过压力测试，不是纸面设计。

2

挑选公司级首批金牌原子小队时，把两种「极端形态」纳入候选

一种是**总部能力单元 own 一个真实业务场景**（外教触达：技术团队不当下游支持方，而是负责方）；另一种是**只存在原子小队的部门**（客户体验）。一个测「总部能力怎么进现场」，一个测「组织能最小化到什么程度」。

3

把「让 AI 读懂公司数据」作为候选的公司级项目

关键不是再多几张报表，而是把「教会 Agent 正确读数」当成**产品**来做——包括口径、权限、失败处理和重放支撑。我判断这可能是个被低估的「虫洞」：业务负责人自己直接查数据，让「最低充分层级决策」第一次在数据侧成立。
