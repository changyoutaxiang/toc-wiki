# 使用说明

> 本说明仅解释发布包的使用方式，不新增治理政策；以五篇核心全文为准。

## 人类阅读

先建立“基本法 → 主要矛盾与铁三角 → 战略方向 → 51Talk OS → 蜂巢系统”的整体理解。做具体产品或技术判断时，回读对应章节，并另行补足领域规则、事实和授权。

## 接入知识库与 Agent

1. 将 `fulltext/` 中五篇文件按独立文档入库，保留 `manifest.json` 中的文档 ID、名称、版本、来源、状态及适用范围。也可导入合订本，但不要两种方式同时重复索引。
2. 摘要用于导航，检索片段应带回文档 ID、章节和版本；重要判断允许回读全文，不把孤立片段当作新的政策。
3. 按任务加载相关全文或章节，再补充领域与任务上下文。架构任务重点关联 OS、蜂巢及其业务战略依据；Coding 任务还需批准的 Spec、代码和接口；检查任务还需测试、Eval、授权和变更范围。
4. 本包不能替代实时客户事实、地区规则、权限服务、工程仓库或运行日志。读取治理文档不等于获得工具执行权限。
5. 无法从文档确定的事项应标明未定，并向相关 Owner 取得澄清；不得用 Agent 推断填充权威规则。

## 建议的任务上下文入口

可在任务说明中使用以下文字，并按实际任务调整：

> 本任务使用《51Talk 公司治理 Context Pack Version 1.0》（2026-09-15）。五篇核心全文是公司治理与方向依据。请依据任务相关章节开展工作，保留版本及来源；区分已确认原则、建议和未来构想。不把未定事项推断为政策，不提高建议性原则的约束强度，不将读取权限视为行动授权。领域事实、具体业务规则和工程 Spec 需另行提供。

这段文字是使用示例，不是新增的系统权限配置。

## 必须保留的理解边界

- Learning OS、Tutor OS 的领域方向已确认；Service OS、Growth & Commercial OS 仍是构想，整体 OS 架构可迭代。
- 小船验证、复用晋级和旧路径退役的建议性原则，不得被发布包装强化为全公司统一阻断门槛。蜂巢全文已经删除的原章节不在本次发布中恢复。
- 战略方向暂不对具名学习责任人或真人责任接口作具体选择，不设统一产品承诺；本包不附未批准的收入、增长率和利润率目标。
- 100% AI Coding 是允许追求的目标，不等于无人审核、无人批准或无人承担责任。
- 知识库供给知识与上下文；工蜂负责研发生产；蜂巢运行客户任务。三者不能互相混称。

## 版本管理

分发时保留整个发布包的版本与清单。后续变更应形成新的受控版本和变更说明，不静默修改已经分发的快照。全文出现真实矛盾时，结合职责和明确修订记录判断；仍不能解决则交给相关 Owner，不由加载顺序自行决定。

包的版本是 1.0，不意味着《基本法》的原始版本号也被改写；其原文仍为 15 周年发布版。基本法文件开头的 Wiki 元数据也原样保留，包级权威属性与发布时间以清单及本包说明为准。
